## 摘要
流程挖掘（PM）为从事件数据中发现和优化运营流程提供了强大的框架。然而，PM技术的有效性严格依赖于结构化事件日志的可用性。迄今为止，事件日志通常由领域专家和流程挖掘专家耗费大量精力手工创建。这种高昂的成本导致大量组织知识（包括事件工单、手册和文本报告）未得到充分利用。我们通过研究大型语言模型（LLMs）作为自动化数据转换器的有效性来应对这一瓶颈。我们提出了一个可扩展的框架，利用LLMs作为数据转换器，弥合非结构化文本资源与结构化事件数据之间的差距。我们在一个新创建的文本到日志数据集上对LLMs进行微调，证明所得模型能够从非结构化资源中提取高保真事件日志。我们的结果表明，这种微调方法在性能上大幅优于少样本或零样本提示，凸显了微调是生成可靠事件数据的必要前提。我们得出结论，我们的方法为将以前未使用的数据提供给流程挖掘生态系统提供了一条有前景的流水线，有效扩展了使用PM进一步调查组织工作流程的可能性。

## Abstract
Process mining (PM) provides a powerful framework for discovering and optimizing operational processes from event data. However, the efficacy of PM techniques is strictly predicated on the availability of structured event logs. Thus far, event logs have often been laboriously created by domain and process mining experts. This costly effort causes large portions of organizational knowledge, including incident tickets, manuals, and textual reports, to remain underutilized. We address this bottleneck by investigating the efficacy of Large Language Models (LLMs) as automated data translators. We propose a scalable framework that leverages LLMs as data translators to bridge the gap between unstructured textual resources and structured event data. We finetune LLMs on a newly created text-to-log dataset, demonstrating that the resulting models can extract high-fidelity event logs from unstructured resources. Our results show that this finetuning approach outperforms few-shot or zero-shot prompting by a large amount, highlighting finetuning as a necessary pre-condition for generating reliable event data. We conclude that our method provides a promising pipeline for making previously unused data available to process mining ecosystems, effectively expanding the possibilities of using PM to further investigate organizational workflows.

## 6. 主要结论与发现

1. **监督微调显著优于提示学习**
   - 零样本几乎无法生成有效的 XES 事件日志；few-shot 虽有改善但仍混杂较多错误。
   - 在 LoRA 微调后，Llama3.1-8B 在 434 条轨迹中有 430 条格式正确，生成质量大幅提升。

2. **轨迹保真度高**
   - 微调后的 Llama3.1-8B 和 Ministral-8B 的 Kendall’s Tau 均值高达 0.99，Levenshtein 距离归一化后均值达 0.99–1.0，与原文轨迹几乎一致。

3. **变体覆盖较可靠**
   - 微调后变体数量接近原日志：Llama 得到 46 个变体、Ministral 43 个，等；而 one-shot 通常生成超额变体（≥129 种）。

4. **幻觉率显著降低**
   - 微调后活动和属性幻觉率很低（无或 0.5% 以下）；显式提供允许活动与属性集合对抑制幻觉有效。

5. **跨域迁移和分布外泛化可行**
   - 在警察报告上微调的模型迁移到 Sepsis 医疗域时仍有效果提升（F1 提升 4–40 pp），尽管与训练域结果仍有差距。

6. **对 LLM 的选择性较强**
   - Qwen2.5-7B 是微调效果相对最弱的模型，提示模型架构和预训练数据对下游事件日志生成效果有显著影响。

## 7. 优点与亮点

- **数据集构建方法论上的创新**：用多个“前沿”LLM 做合成文本生成，加入人设、场景和随机采样，增加了文本多样性，同时解决了“text-to-log 配对数据集缺失”的关键瓶颈。
- **双层级评估框架全面且可复用**：既评估了轨迹级的准确率、顺序、属性还原度，又从过程模型层评估了挖掘出的流程与实际流程的一致性，为后续 LLM-to-PM 研究提供了模板。
- **考虑了循环依赖问题**：特意用不同的模型做文本生成 vs. 事件日志提取，避免相同 LLM 内部偏差被循环放大。
- **选择了偏向产业落地部署的本地小参数模型**（7B/8B 级），并公开代码与数据集，具备较好的可复现性和实用性导向。
- **手工验证合成文本质量**：将文本生成环节本身作为一种可检验的“可信数据”来对待。

## 8. 不足与局限

- **完全基于合成数据**：数据分布、行文格式与真实事故记录仍有差距，作者自己也承认真实的警察文档往往带有“表格/叙述混合”等特性。泛化到真实世界非结构化文档仍缺少验证证据。
- **输出格式局限于 XES 主轨迹范式**：未支持 object-centric event logs（OCEL）等模型，对现实业务中多对多、多实例结构化关系覆盖不足。
- **仅选择 8B/7B 级的开源模型**，没有检验更大规模开源模型（如 70B 等）或 API 闭源模型的极限表现，由于微调仅限于本地部署场景，结论可能有一定程度偏向。
- **在少样本演示里每次仅提供一条演示**：few-shot 本身只有 1-shot，模型能力发挥不完全充分。
- **对带各种不同文本语体的真实文本（如多语义、歧义、不完整表述）没有全面探讨**；测试文本有较准确的简化描述，缺少噪声和纷杂真实文本的压力测试。
- **评测过程的科学严谨性有待补强**：缺少多次随机种子重复实验的完整方差报告，以及统计显著性检验；跨域输出部分更偏向描述性结果。
- **无完整环境报告**：未提供精确的 GPU 资源、能耗、训练时间等信息，削弱了复现时的资源配置参考。
