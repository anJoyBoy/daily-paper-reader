## 摘要
表格数据作为机器学习中的核心数据格式，由于特征信息不足，往往缺乏高性能建模所需的判别能力。自动化特征工程（AutoFE）通过自动化特征生成和选择来解决这一问题，同时确保模型性能和运行效率。然而，传统的AutoFE由于依赖盲目的数学变换，生成的特征可解释性差；而基于大型语言模型（LLM）的AutoFE则需要昂贵得多轮迭代才能生成高效用特征以有效提升模型性能，且存在偏差与幻觉的内在风险。本文将符号回归与LLM相结合用于特征工程（SymboLLM-FE），以解决这些挑战。我们通过符号回归提取与目标强相关且能提升模型性能的数学表达公式，再由具有丰富先验知识的LLM对其优化，确保可解释性。在六个真实数据集和四个Kaggle竞赛上的实证结果表明，SymboLLM-FE优于现有的AutoFE。同时，SymboLLM-FE通过采用基于统计先验的LLM优化机制和仅个位数次LLM调用，解决了可解释性差与迭代次数多的双重挑战。

## Abstract
Tabular data, as a core data format in machine learning, often lacks the discriminative power needed for high-performance modeling due to insufficient feature informativeness. Automated Feature Engineering (AutoFE) overcomes this by automating feature generation and selection, ensuring both model performance and operational efficiency. However, traditional AutoFE often yield features with poor interpretability because they rely on blind mathematical transformations, while large language models (LLM)-based AutoFE faces challenges in requiring costly multi-round iterations to generate high-utility features to effectively enhance model performance, compounded by inherent risks of bias and hallucination. In this paper, we combine symbolic regression with LLMs for feature engineering (SymboLLM-FE) to solve these challenges. We extract mathematically expressive formulas strongly correlated with the target via symbolic regression, which can enhance model performance, then refine them by LLMs with rich prior knowledge to ensure interpretability. Empirical results on six real-world datasets and four Kaggle competitions demonstrate that SymboLLM-FE outperforms existing AutoFE. SymboLLM-FE also addresses the dual challenges of poor interpretability and numerous iterations by employing a statistical prior-grounded LLM refinement mechanism and single-digit LLM calls.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：在真实世界的表格数据应用中，特征信息不足和隐式的高阶交互缺失是制约机器学习模型性能的关键瓶颈。特征工程（Feature Engineering) 是缓解该问题的常用手段，用以增强特征与目标变量的关联。但传统人工特征工程成本很高，因此自动化特征工程（AutoFE）成为研究重点。
- **现有方法的固有矛盾**：
    - **传统 AutoFE（如 AutoFeat、OpenFE）**：依靠启发式搜索或预定义算子栈盲目进行数学变换，虽能提高性能，但生成的特征通常是复杂且无语义含义的数学组合，导致可解释性差，无法在信贷风险、金融因子挖掘等需要业务逻辑验证的场景中取得信任。
    - **LLM-based AutoFE（如 CAAFE、OcTree）**：利用 LLM 进行了语义理解能力，但存在**三大致命缺陷**：
        1. 需要**多轮迭代**与下游模型交互验证才能产生有效特征，存在极重的计算开销和代价（如表1中所见，部分方法需 50 轮迭代）。
        2. 存在固有的**幻觉**风险。
        3. 存在**隐性偏差**，易导致生成语义无效或不公平的特征。
- **核心解决目标**：需一种既能保证特征效用（高模型性能），又能保证人类可理解性与逻辑可验证性，还能大幅降低迭代成本的 AutoFE 范式。

## 2. 论文提出的方法论

- **核心思想**：提出了 **SymboLLM-FE**，一种**两阶段协同构建的混合框架**，协同**符号回归（Symbolic Regression, SR）** 与 **LLM** 的合作机制：
    - **机制定位**：并非单纯堆叠两种技术，而是让符号回归充当"统计/数学结构挖掘者"，让LLM充当"领域语义整合/翻译者"，以此重新定义了LLM在AutoFE中的角色：**从不可控的开放式生成器转变为受统计现实约束的程序优化器**。
- **阶段一：基于符号回归的公式构建（Formula Construction）**
    - **特征组合采样（子集选择）**：为避免全量特征组合 2^N 的指数搜索空间，引入了 **“基于 Spearman 相关性的动态扩滑窗（Expanding-Sliding Window）”**：
        - 先计算每个原始特征与目标变量的 **Spearman 相关系数**，进行升序排列形成有序特征序列。
        - **扩窗阶段**：从窗口长度 k=⌊n/2⌋ 开始逐级增加到 n（即全量）。
        - **滑窗阶段**：针对每一个固定的 k，窗口向右滑动以产生不同的连续特征子集。
        - **理论贡献（公式2）**：将候选子集的搜索复杂度从 O(2^n) 严格控制在**多项式 O(n²) 量级**。
    - **公式生成（SR 模型搭建）**：对采样出的每个特征子集，分别训练 遗传编程（GP） 类符号回归模型，并使用简洁性与复杂度惩罚（正则化，追求奥卡姆剃刀），最终输出可显式表达的公式（如 `add(mul(c1,c2),c3)`）。
    - **建立公式特征库 R**：每次公式生成过程被记录成一个三元组（特征子集 Si，公式性能 Pi，具体公式 Ƭ）。
- **阶段二：基于 LLM 的特征生成（Feature Generation）**
    - **输入构造**：将公式库中所有公式进行自然语言语义转换后，与数据集背景信息和 **代码生成模板 Prompt** 拼接，注入 LLM。
    - **代码合成与执行**：LLM 通过链式思考（CoT）生成用于加入新列的 Pandas Python 代码。
    - **性能验证与反馈闭环**：执行代码生成特征，与原始特征合并后，在下游预测器（Downstream Predictor）上测试得到性能分数。
    - **迭代优化**：将性能分数与刚才的代码作为反馈喂给 LLM，令其迭代优化代码、去除冗余特征，直到验证集性能达到相对阈值。
    - **异常恢复机制**：设计了自纠错机制，自动捕获执行异常并反馈给LLM，实现无需人工干预的全闭环执行。
    - **去冗余与幻觉抑制**：要求 LLM 仅能在数学有效公式所限定的统计真实子空间内操作，不仅剔除无益特征以防止维度爆炸，还通过语义过滤器识别数学上关于原始特征冗余的列并执行删除。
- **关键实现细节**：
    - **数据集防泄漏**：严格按折（fold-wise）划分数据集：训练集仅供符号回归学习；验证集仅被 LLM 迭代精炼参考（作为模型选择）；测试集完全保留在最后评估阶段，不与训练和 LLM 迭代重叠。下游模型架构/超参固定。
    - **符号回归算子集**：定义了14种受保护算子（add, sub, mul, div, sqrt, log, sin 等），在非法输入时返回安全值保障数值稳定。

## 7. 优点

- **范式定位精准**：LLM并不承担主思想架构的生产任务，而是收敛做“公式的解释器与合成逻辑整合器”，这是一种有效的资源重构。该方法系统意义上打通了“数学有效性”和“语义透明度”的自动特征库。
- **真正可行的可扩展性突破口**：设计了一种严格的公式化统计实现：通过 Spearman 特征重要性引导的 **扩滑窗**机制（O(2^n) → O(n²)），确实有力遏制了特征累积的维度爆炸，并且使用极少LLM调用即收敛，工程落地可能性大。
- **用户评估细致且克制**：大量进行了指标公平性校对、数据颗粒度保护（分割数据框），消融组件的功效细分研究和与 GP 库（演化计算派）的对抗验证，在目前表格 AutoFE 研究里属于少有的严谨。
- **针对商业逻辑友好**：在逻辑透明的数据集中能形成带业务洞察的说明（例："生育-教育权衡指标"），由于最终特征使用LLM加注了现实语义，能直接使 CRISP-DM 数据挖掘方法论在金融等高风险领域快速上手。

## 8. 不足与局限

- **计算相对开销依然隐患（可扩展性挑战）**：
    - 尽管 LLM 侧代码生成带上的只有几次调用，但是前期的符号回归阶段依然属于较为昂贵的遗传程序演化过程。在更高维特征集上进化群体和演化代数带来的计算压力未知。
    - 论文没有将动态滑窗方法的真实运行时间与数据规模（达到上万条样本时）变化的极限实验证据提供给读者，对开源极高维（数千features）数据集依然存在应用限制。
- **特征组合策略的前提假设存在漏洞**：
    - “扩滑窗”基于“排序后仅连续窗口内特征可能有效”这一隐含前提，但结合数据时会出现本质缺陷。若两个强协同作用的变量在不同重要度排序中相隔较远（如非相邻特征的高阶交互作用强烈），该采样机制将根本性错失这类跨位效用的挖掘机会。
- **LLM自带知识幻觉的“暗门”并未彻底封死**：
    - 虽然 LLM 对数学公式的动作进行了约束，但若业务背景提示词中自带表层认知偏差，仍可能发生语义漂移，且论文未在大量未知数据域（如图像/语料表格以外的边缘场景）中对“意义传递链条”做更多健壮性验证。
- **下游模型框架滞后于横空标杆存在的普遍性**：
    - 尽管对比了 TabPFN 和传统树模型，却未展示基于新型深度Tabular Transformer或较新的功能（如具名向量等新式结构）的大规模全切片实验；论文的全部实验样本量并未突破中小表格界限（最大为约12000条），对高样本量环境的规律性推断仍受限制。
