## 摘要
实体匹配（EM）需要细粒度的上下文理解和领域知识。近期研究表明，大语言模型（LLM）可以跨领域充当强大的匹配器，但大多数方法要么做出独立的成对决策，要么依赖手工设计的复合流水线，因而在现实的多候选设置中缺乏灵活性。同时，它们通常忽略大规模推理成本。我们将带候选集的基于LLM的实体匹配形式化为一个成本感知的序列决策问题，并提出CaRL-EM——一个管理LLM操作的强化学习控制器。给定锚记录的状态、其候选集及成本，CaRL-EM在不同操作符（匹配/比较/选择/决定）和模型容量之间自适应选择，以最大化质量-成本目标。该策略与抽象操作符交互，使得同一控制器在推理时无需重新训练即可与不同的底层LLM后端复用。在7个基准上的实验表明，CaRL-EM（i）学会根据任务复杂度动态规划廉价与昂贵操作符的使用；（ii）在不同数据集和领域间实现稳健的零样本迁移；（iii）相较于强大的基于LLM的基线和手工设计的流水线，始终取得更好的质量-成本权衡，在相当或更高的质量下获得更低的推理成本。

## Abstract
Entity matching (EM) requires fine-grained contextual understanding and domain knowledge. Recent work shows that large language models (LLMs) can serve as strong matchers across domains, but most methods either make independent pairwise decisions or rely on manually designed composite pipelines, thus lacking flexibility in realistic multi-candidate settings. At the same time, they typically ignore inference cost at scale. We formulate LLM-based EM with candidates as a cost-aware sequential decision problem and propose CaRL-EM, a reinforcement learning controller that manages LLM operations. Given the state of an anchor record, its candidate set, and the cost, CaRL-EM adaptively chooses among different operators (Match/Compare/Select/Decide) and model capacities to maximize a quality-cost objective. The policy interacts with abstract operators, allowing the same controller to be reused with different underlying LLM backends at inference time without retraining. Experiments on 7 benchmarks show that CaRL-EM (i) learns to dynamically plan the usage of inexpensive and expensive operators based on task complexity, (ii) achieves robust zero-shot transfer across diverse datasets and domains, and (iii) consistently achieves a better quality-cost trade-off than strong LLM-based baselines and manually designed pipelines, yielding a lower inference cost at comparable or higher quality.

- **整体研究意义**：论文为“如何高效且可控地使用 LLM 完成数据管理任务”提供了新的视角——以强化学习控制器替代静态人工流水线来编排 LLM 操作，使实体匹配系统具有实例级的自适应能力和良好的跨域可迁移性。

## 2. 方法论：CaRL-EM

- **总体框架**：CaRL-EM 将“带候选集的实体匹配”建模为一个**成本感知的、可中断的马尔可夫决策过程（MDP）**。对于每个锚记录，强化学习控制器从初始状态出发，按步骤迭代，根据当前特征向量选择下一步的高层operator，直到选出最终答案（或达到最大步数）。
- **四种高层操作符**（LLM-based operators）：
  - **MATCH**：对（锚记录，单个候选）的成对比较，判断是否匹配，适合低成本快速验证；由轻量模型执行，输出 YES/NO 信号（及其概率）以更新该候选的内部置信得分。
  - **COMPARE**：比较两个候选（champion–challenger），判断哪一个更可能与锚匹配，将偏好转化为两个候选之间分数的此消彼长，使分数分布更尖锐。
  - **SELECT**：对当前分数最高的 top-k 短列表执行列表式推理，从多个候选中整体挑选最可能匹配者，或输出 None；这是更昂贵但全局视野更强的操作。
  - **DECIDE**：唯一终止操作；控制器直接输出最终预测 `DECIDE(i)` 或 `DECIDE(None)`。
- **双层抽象成本模型**：并非绑定特定 API 的真实价格表，而是根据“操作类型 + 模型容量”分配两级抽象成本：低成本的 MATCH / COMPARE 调用记为 `κ_l`，高成本的 SELECT 调用记为 `κ_h = ρ·κ_l`（默认 `ρ = 2.5`）。该抽象成本充当策略学习的控制信号，使策略与具体定价脱钩。
- **状态表示**（State）：控制器状态是多种特征的拼接向量：
  - `v_score`：各候选的当前置信分数；
  - `v_mask`：各候选是否仍可被 MATCH 操作处理；
  - `v_freq`：各候选参与 COMPARE 调用的频次；
  - `v_global`：累计抽象成本、归一化时间步 `t/T_max`、当前最高候选得分；
  - `v_hist`：最近 H 个高层动作的 one-hot 编码（用于识别循环/重复模式）；
  - 可选地附加锚记录和最高分候选的稠密语义嵌入 `v_emb`。训练时加入少量高斯噪声增强鲁棒性。
- **奖励设计**：兼顾正确性、置信度、成本与效率——包括终止时刻的选择正确/错误奖励（区分「选择正确匹配」「选错对象」「无匹配时正确 reject」「无匹配时误选」四种情形）、全局正确候补与错误候补之间的**间隔（margin）奖励**、每一步对抽象成本的惩罚 `-λ·cost(α_t)`、提前停止的效率奖励，以及避免过早终止的惩罚项。
- **策略网络与训练**：策略网络为 3 层 MLP（768–384–192），使用 PPO + 价值基线训练。模型只与抽象操作符和抽象成本标签交互，**不依赖任何具体 LLM 的实现细节**，因此训练完成后可以在推理阶段直接换用更强/更便宜的 LLM 后端，无需重新训练控制器。
- **核心设计思想**：CaRL-EM 是“元决策层”而非匹配器本身——它负责**编排**底层匹配工具，做到易样本少花钱、难样本多花预算的自适应推理。

## 3. 实验设计

- **评估数据集（7个标准基准）**：Amazon-Google（AG）、DBLP-ACM（DA）、DBLP-Scholar（DS）、IMDb-TMDb（IM）、IMDb-TVDb（IT）、TMDb-TVDb（TT）、Walmart-Amazon（WA）。覆盖电商、学术文献、影视、餐饮等多种领域。
- **设置细节**：阻塞阶段使用 Sparkly blocker 为每个锚记录检索 top-10 候选（recall@10 在 94.89%–99.96%）；最终评估集为每数据集 400 个锚（其中 300 个有真实匹配、其余无匹配），进行 clean-clean 多候选选择。
- **评估指标**：实例级 F1 而非逐对 F1——F1_id（真匹配选择）+ F1_none（空匹配拒绝），以及两者无权重平均的 F1_macro；方法间成本以标准化 API 定价 + GPU 成本（$5.98/h）综合计算。
- **对比方法**：
  - 域内监督参考：DITTO（每个目标数据集单独训练）；
  - LLM 零样本基线：Matching、Comparing、Selecting 三种单一操作；
  - 最强手工流水线基线：COMEM；
  - CaRL-EM：在 AB 上训练后**零样本迁移**到其余 7 个数据集；
  - 后端鲁棒性测试：同一控制器换用 Llama-3.1-8B、Gemma-3-27B、GPT-4o mini、GPT-oss-20B、ERNIE 4.5、Qwen3-30B 等多个 LLM 后端进行推理，不重新训练。

## 6. 主要结论与发现

1. **质量-成本权衡显著**：CaRL-EM 在所有 7 个目标数据集上零样本取得了平均 F1_macro=76.09，为相同设置（零样本/迁移）中最佳；推理成本平均仅 **0.13 美元**，约为 COMEM（0.59 美元）的 22%、约为域内监督模型 DITTO（2.22 美元）的 6%，形成了比更强基线更好的帕累托前沿。
2. **策略具备实例级自适应性**：简单案例几步骤即终止（如 SELECT 后两次 COMPARE 快速验证），难度大的案例则反复调用 MATCH 进行本地校验，体现了类似“System 2”的动态计算资源分配行为，而非 COMEM 式固定路径。
3. **跨数据集零样本迁移**：DITTO 跨域迁移后 F1_macro 从 85.64 跌至 59.75，而 CaRL-EM 无需特定域训练即可达到 76.09，说明学到的“决策策略”（何时用什么操作符）具有跨域泛化性且优于传统监督模型的迁移能力。
4. **后端可随意更换**：不重新训练控制器，仅把后端从 Llama-3.1 换成 GPT-4o mini/ERNIE/Qwen3 等，分别将 F1_macro 从 69.36 提升至 76.09/77.97/79.37，成本和精度可用不同后端灵活选择——策略学到的是抽象编排逻辑而非对单一模型过拟合。
5. **位置偏差控制更稳健**：CaRL-EM 在 gold 候选位于不同初始位置时（第 1 至 10 位）表现相对平稳，且跨数据集方差最小，优于纯 SELECT（对位置变化最敏感的单一列表式阅读策略）。
6. **有效缓解“无匹配时误选”**：经由 SELECT 的全局判断 + 条件性 MATCH/COMPARE 兜底，CaRL-EM 在 F1_none 指标上（68.20）明显优于 COMEM（60.78）——说明自适应方式更会在证据不足时做出拒绝对判断。

## 7. 优点

- **问题定义新颖且角度精准**：首次将基于 LLM 的多候选实体匹配明确定义为成本感知的序列决策 RL 问题，绕开了传统散点对判断的局限，直接面向真实业务需要（单锚至多一个真匹配，成本是规模化应用的硬约束）。
- **抽象成本两级模型设计巧妙**：不是捆绑具体供应商的真实账单，而是以高/低两级抽象成本控制调度行为，使同一策略易于适配不同后端 LLM、不同定价环境的实际部署；这提高了模型的复用度和迁移能力。
- **系统架构灵活性高**：将“决策编排”与“底层 LLM 匹配能力”解耦成独立层次，策略仅与抽象操作符（MATCH/COMPARE/SELECT/DECIDE）交互，使得未来的 LLM 升级可直接以即插即用形式嵌入现有控制器，省去重新训练成本。
- **奖励设计精细**：全局间隔势能、局部势能、成本惩罚、提前终止与过早终止的奖惩机制共同作用，让策略既学会“快跑”又学会“及时刹车”，这种结构在节约成本的同时避免了早停误判。
- **评估标准严格**：采用实例级指标而非传统成对 F1——只有在多候选列表中通过精确选择正确命中的才计成功，比较级匹配、误选既计 FP 又计 FN，从而更接近真实业务场景的正确性评价；同时对候选位置进行压力测试，提升了结论的可靠性。
- **可解释性好**：通过定性案例分析展示了策略在不同难度记录上的置信度轨迹和工作流走向，直观呈现了 RL 控制器“动态分配认知资源”的真实行为，而非把系统做成黑箱。

## 8. 不足与局限

- **适用场景限制（clean-clean 假设）**：论文明确限定在每锚“至多一个真匹配”的场景，现实中的数据常存在一对多、多对多、表内重复噪声等情形，这些情况需要修改状态表示、动作空间与决策规则，其当前代码无法直接覆盖。
- **候选池规模较小**：实验仅覆盖由 Sparkly 检索的固定 top-10 候选；在真实大规模实体解析中，候选集可达到成千上百条，此时当前对整个候选列表直接推理的设计可能退化，需要额外的层级式粗筛或索引协同机制。
- **抽象成本模型容量有限**：双层成本只是一个粗粒度近似，不能区分精确的 token 级价格差异、位置偏差、不同 API 提供商的批量优惠单价、延迟约束等复杂计费因素；因此，在实际部署的价格体系与默认二级成本设置显著偏离时，学到的策略可能不再保持全局成本最优化，需要针对实际成本函数重新校准或微调。
- **训练域和数据偏差**：策略仅在 Abt-buy 一个领域训练，跨域零样本结果虽然表现良好，但理论上数据规模和训练集（主要是电子商务属性结构）的不均衡可能会对策略泛化带来的潜在惯性造成影响（作者并未进行多源训练域的全面审计）；作者提出了“训练规模变化时成绩仍相对较稳”，但也揭示出 PPO 训练本身的墙钟开销远高于 DITTO，可复现迭代成本较高。
- **风险用途限制**：作者在“伦理考量”中明确指出不鼓励将技术用于跨数据集身份关联，且不正确匹配在敏感领域可能导致错误合并或道德/合规风险；对于高风险的对接场景必须在策略外层加入人工审查环节。
