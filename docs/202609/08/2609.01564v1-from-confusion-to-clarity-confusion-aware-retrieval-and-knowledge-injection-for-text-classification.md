## 摘要
大型语言模型（LLM）在将文本分类为具有许多语义相似标签的分类体系时存在困难，因为这些区分是领域特定的，且未被预训练捕获。为处理大规模标签空间，一种常见方法是通过嵌入相似性检索前K个候选标签，并提示LLM在其中进行选择。然而，前K检索减少了候选数量，但并未帮助模型区分相似标签。当两个相似标签同时作为候选出现时，模型缺乏正确区分它们的信号。我们提出一个框架，该框架能够：（1）识别模型难以区分的标签对，（2）扩展候选集以包含易混淆标签，以及（3）生成针对性的规则以区分相似候选。该框架无需微调，生成的规则可迁移至更小、更便宜的模型。在三个基准（WOS、Flipkart、LEDGAR）上，我们的方法相较于检索基线将宏F1提升了多达10.0个百分点，而较小的模型（2B--20B）通过跨模型迁移获得了高达11.5个百分点的提升。

## Abstract
Large language models (LLMs) struggle to classify text into taxonomies with many semantically similar labels, as the distinctions are domain-specific and not captured by pre-training. To handle large label spaces, a common approach retrieves top-$K$ candidate labels by embedding similarity and prompt the LLM to choose among them. However, top-$K$ retrieval reduces the number of candidates but does not help the model tell similar ones apart. When two similar labels both appear as candidates, the model lacks the signal to choose correctly between them. We propose a framework that (1) identifies which label pairs the model struggles to distinguish, (2) expands the candidate set to include confusable labels, and (3) generates targeted rules to differentiate between similar candidates. The framework requires no fine-tuning, and the generated rules transfer to smaller, cheaper models. On three benchmarks (WOS, Flipkart, LEDGAR), our approach improves Macro F1 by up to 10.0pp over retrieval baselines, with smaller models (2B--20B) gaining up to 11.5pp via cross-model transfer.

## 2. 方法论：核心思想、技术与算法流程

### 总体框架概览

框架包含两个阶段（对应论文图 2）：
- **离线阶段**：分析基线分类器在训练集上的混淆矩阵，找出系统性易混淆的标签对，并经三阶段管线生成成对判别规则，构建知识库 K；
- **推理阶段**：检索候选标签 → 用"困惑伙伴"扩展候选集 → 筛选适用的判别规则注入提示 → LLM 一次调用完成分类。

### 核心机制一：困惑感知检索（Confusion-Aware Retrieval）

- **关键观察**：若模型曾将标签 l 误分为 l'（或反之），说明两个标签对相似查询都具有合理性，应同时出现在候选集中——这类标签对称为 **confusion partners**。
- **实现步骤**：
  1. 在训练集上运行检索基线，记录每次真实标签 l 被预测为 l' 的错误，累加得到有向混淆计数 c(l→l')；
  2. 按计数降序选择最少数量的有向标签对集合 P，使其累计覆盖至少 τ%（默认 75%）的训练错误；
  3. 对每个标签 l，找出与其混淆双向总计数最高的标签作为 PARTNER(l)；
  4. 推理时为检索到的每个候选标签 l 追加 PARTNER(l)，确保易混淆的两方同时在场。

### 核心机制二：三阶段知识生成管线

对 P 中每个有向对 (l→l') 执行：

1. **阶段一：单例推理（Per-example reasoning）**——对每条 l 被误分为 l' 的训练样本，提示 LLM：*"该查询中什么信号表明它属于 l 而非 l'？"*，得到一系列按样本粒度的观察信号；
2. **阶段二：合并（Consolidation）**——将单例观察汇总，提示 LLM 提炼出跨样本一致、可泛化的共识信号，形成一条**有向规则** r(l→l')；
3. **阶段三：双向合并（Bidirectional merge）**——若双向混淆均有规则，提示 LLM 将两条有向规则合并为一条**对称判别规则**（如："当查询指向 X 时归为 A；当指向 Y 时归为 B"），并明确指出造成混淆的表面相似点与决定性区分信号。

最终得到知识库 K，每条记录对应一个标签对的一条判别规则。

### 推理方法

- 对查询 q，检索 top-K 候选（K=10，嵌入模型为 Qwen3-Embedding-8B）；
- 用 PARTNER(·) 扩展候选集为 C′；
- 从 K 中筛出 C′ 中存在的标签对对应的规则 R；
- 在单次 LLM 调用中注入 C′ 与 R（提示格式见附录），模型输出最终标签。

### 与增大 K 的本质差异

增大 K 是一视同仁地引入更多候选（含大量无关标签）；困惑伙伴策略是选择性地加入模型已知难以区分的标签，同量级候选数下召回率和 F1 均显著更优（见图 4）。

## 6. 主要结论与发现

- 在 Qwen3-32B 主实验中，全方法在所有数据集 × 层级上均取得最佳 Macro F1：较第二优方法的增益在 LEDGAR L1、WOS L1、Flipkart L3 上统计显著，最高提升出现在 Flipkart L3（较零样本 +11.2pp；较最强检索基线 +4.4pp）。
- **两个机制是互补的**：困惑伙伴将 Flipkart L3 的候选集召回率从 86.0% 提至 98.1%（同时伴随 LLM 选择错误上升）；知识注入将 LLM 选择错误从 21.9% 降至 17.1%——伙伴解决"正确标签不在场"，知识解决"在场却选错"。
- **困惑伙伴优于盲目增大 K**：K=10+伙伴（平均 18 个候选）达 74.2 F1 / 98.1% 召回；纯检索需 K=50 才能追上召回率，且同等候选规模下 F1 显著更低。
- **成对规则优于逐标签描述**：成对格式上下文相关、目标明确，在所有层级上 F1 更高、选择错误更低。
- **跨模型可迁移**：Qwen3-235B 生成的知识应用于小模型普遍有效。Small（2–4B）在 Flipkart L3 上 +11.5pp，Medium（8–20B）+11.1pp；即便在扁平体系 LEDGAR 上小模型也提升 +6.3pp。固定复用单一知识库即可带来 6.6–10.3pp 提升，而针对各模型单独发现混淆对通常更优。
- **与微调对比的定位**：在干净、充足数据下微调模型最优（Flipkart L3：RoBERTa 81.7 vs 本方法 76.7）；但在 20% 标签噪声、10% 训练数据、各类测试扰动下本方法显著更稳健（如标签噪声 20% 时 72.1 vs 60.0/61.0）——适合通过托管 API 使用基础模型、不具备独立训练/部署基础设施的团队。
- **生成规则质量较高**：人工审查平均接受率 87.3%。

## 7. 优点与亮点

1. **问题定位精准**：从"标签在场却选错"这一检索后瓶颈入手，以错误分析直接驱动修复策略，思路清晰、逻辑闭环。
2. **无需微调**：适用于通过 API 访问前沿模型的工业场景，避免为每个分类体系训练与维护独立模型的生命周期成本。
3. **成本可控、知识可复用**：离线阶段一次生成，在线保持单次 LLM 调用；规则可跨模型规模迁移，解耦知识质量与推理成本。
4. **两种机制互补设计巧妙**：将错误分解为"检索未命中"与"LLM 选择错误"两类，分别用困惑伙伴与知识注入对症下药，消融实验清晰验证了各自贡献；同量级候选下优于简单增大 K，说明选择标签的依据是模型真实盲区而非通用相似度。
5. **鲁棒性评估充分**：对标签噪声、数据稀缺、9 种测试扰动与联合条件进行的与微调模型对比实验，提供了贴近实际部署的视角。
6. **规则可解释且质量受控**：生成的知识为自然语言判别规则，通过合并阶段降低噪声、以人类评估验证，辅助可审计的决策。

## 8. 不足与局限

1. **依赖带标注训练数据**：需在训练集上运行基线以识别混淆对，若数据不存在或分布偏移则需重新执行离线阶段；
2. **覆盖与成本的权衡未完全解决**：提高混淆覆盖率能提升质量但会显著拉长提示、增加推理延迟（如 75% 覆盖率下 WOS 输入 token 增至 6.0 倍）；论文未测试更大标签体系、多语言输入或时间漂移下该权衡的实际表现；
3. **生成的规则未自动验证**：尽管合并阶段降低噪声且人工接受率达 87.3%，但高利害场景仍需领域专家审核；个别剩余错误对源于分类体系自身的语义重叠/层级不一致（如 Fusion Wear 本身融合 Western 与 Ethnic 风格），非提示知识所能完全消除；
4. **统计效应不完全一致**：部分层级的增益未达统计显著性，提示在某些粗粒度上知识注入的边际收益有限；
5. **微调对比范围有限**：仅在 Flipkart L3 上对比，且未覆盖更大规模的预训练模型作为微调基线；在干净数据条件下本方法仍不及微调模型（差距约 4–5pp），若生产数据干净且充足，微调仍是更优选择；
6. **评估者偏差风险**：人工规则评估由论文作者完成，非盲、非独立，缺少领域专家参与与评分者间一致性报告；
7. **数据与泛化边界**：三个数据集均为公开英文基准，未验证电商/法律之外更多垂直领域及多语言/跨语言场景的有效性。
