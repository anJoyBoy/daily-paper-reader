## 摘要
流程挖掘（PM）为从事件数据中发现和优化运营流程提供了一个强大的框架。然而，PM技术的有效性严格依赖于结构化事件日志的可用性。迄今为止，事件日志通常由领域专家和流程挖掘专家费力地创建。这种高昂的成本导致大量组织知识（包括事件工单、手册和文本报告）未被充分利用。我们通过研究大语言模型（LLM）作为自动化数据转换器的有效性来解决这一瓶颈。我们提出了一个可扩展的框架，利用LLM作为数据转换器，弥合非结构化文本资源与结构化事件数据之间的差距。我们在一个新创建的文字到日志数据集上微调LLM，证明所得模型可以从非结构化资源中提取高保真事件日志。我们的结果表明，这种微调方法在性能上大幅优于少样本或零样本提示，突出表明微调是生成可靠事件数据的必要前提。我们得出结论，我们的方法为将以前未使用的数据提供给流程挖掘生态系统提供了一条有前景的流水线，有效扩展了使用PM进一步调查组织工作流程的可能性。

## Abstract
Process mining (PM) provides a powerful framework for discovering and optimizing operational processes from event data. However, the efficacy of PM techniques is strictly predicated on the availability of structured event logs. Thus far, event logs have often been laboriously created by domain and process mining experts. This costly effort causes large portions of organizational knowledge, including incident tickets, manuals, and textual reports, to remain underutilized. We address this bottleneck by investigating the efficacy of Large Language Models (LLMs) as automated data translators. We propose a scalable framework that leverages LLMs as data translators to bridge the gap between unstructured textual resources and structured event data. We finetune LLMs on a newly created text-to-log dataset, demonstrating that the resulting models can extract high-fidelity event logs from unstructured resources. Our results show that this finetuning approach outperforms few-shot or zero-shot prompting by a large amount, highlighting finetuning as a necessary pre-condition for generating reliable event data. We conclude that our method provides a promising pipeline for making previously unused data available to process mining ecosystems, effectively expanding the possibilities of using PM to further investigate organizational workflows.

## 1. 核心问题与研究动机

- **背景**：流程挖掘（PM）通过分析事件数据发现和优化运营流程，但其有效性严格依赖结构化事件日志的可用性。然而，传统上事件日志多由领域专家手工构建，成本高昂且耗时巨大。
- **痛点**：由于这种人力瓶颈，大量组织知识（如事故工单、操作手册、文本报告等）以非结构化文本形式存在而无法被 PM 技术直接使用，导致数据资源严重浪费。
- **核心问题**：能否利用大语言模型（LLM）将非结构化流程描述自动、可靠地转换为符合规范的结构化事件日志？也就是说，LLM 在"文本 → 事件日志"的翻译任务上能达到何种效果。
- **研究定位**：与既有工作把 LLM 用于直接生成完整流程模型不同，本文让 LLM 只负责"从文本中提取事件数据"，而将流程建模交给专门的 PM 算法完成。

## 2. 方法论：核心技术方案

- **核心思想**：将 LLM 视为"数据翻译器"（Data Translator），弥合非结构化文本与结构化事件数据之间的鸿沟。流程建模任务仍交给传统的流程发现算法执行，LLM 仅负责提供正确的输入数据。
- **整体流程（三段式）**：
  1. **数据生成阶段**：用前沿基础模型（GPT-5.1、Qwen3-max、Mistral-medium）将真实事件日志中的 XES 轨迹合成为对应的自然语言文本（如"警情报告""出院小结"），从而构建成对的文本-日志数据集。
  2. **模型微调阶段**：开源的指令微调 LLM 作为数据翻译器，以合成文本为输入、XES 格式事件轨迹为目标输出，进行 LoRA 参数高效微调（监督微调 SFT）。
  3. **评估阶段**：将测试文本输入模型生成 XES 事件日志，分别从单条轨迹和整体流程两个层面评估生成质量，并与原始真实日志对比；此外还用 Inductive Miner 和 Heuristics Miner 流程发现算法检验生成日志是否能够还原与原日志一致的过程模型。
- **关键设计细节**：
  - 每个训练样本包含系统提示、指令、一个 one-shot 演示（从训练集抽样，降低固定演示带来的偏差）以及目标输入-输出对。
  - 仅对模型回答的目标 tokens 计算损失，prompt tokens 被屏蔽。
  - LoRA rank = 16，可在单张 GPU 上完成训练。
  - 推理时，系统提示中显式提供允许的活动（activities）与属性（attributes）集合作为领域知识约束，该约束同时用于识别幻觉输出的来源。
  - 评估中对比零样本（zero-shot）、单样本（few-shot / one-shot）提示与微调（SFT + one-shot）三种设定。
- **核心评估公式**：
  - **n-gram 多样性比率**： \(R_n = \frac{\#\text{unique }n\text{-grams}}{\#\text{total }n\text{-grams}}\)
  - **平均嵌入距离**：\(D_{avg} = \frac{1}{N} \sum_{a \neq b} \lVert v_a - v_b \rVert\)，衡量文档间的语义差异
  - **Kendall Tau 相似度**：\(\tau(\sigma_1,\sigma_2) = \frac{C-D}{C+D}\)，衡量两个活动排序间的相关性
  - **归一化 Levenshtein 距离**：\(s(x,y)=1 - \frac{d(x,y)}{\max(|x|,|y|)}\)，衡量事件序列的编辑距离
  - **过程发现拟合度**：使用 fitness（拟合度）、precision（精确度）、F1 分数（两者的调和平均）量化挖掘模型与原始日志的偏差。

## 3. 实验设计

### 3.1 使用的数据集/场景

- **Road Traffic Fine Management Process 事件日志**（交通罚款管理流程，约 15 万条轨迹，平均每轨迹 ~4 个事件，231 个变体）：随机抽取 2,887 条轨迹，保留原始的变体比例结构。生成合成文本为"警情报告"（Police Reports）。

- 两个数据集均按 85% 训练 / 5% 开发 / 10% 测试划分。另有一个 held-out 实验：仅用 GPT-5.1 生成的三分之一文本训练，在 Qwen3 生成的文本上评估，以检验跨生成器泛化能力。

## 6. 主要结论与发现

1. **SFT 显著优于零样本和单样本提示**：在上述指标下（XML 有效输出率可高达 99%、变体数高保真、属性幻觉率 <1%），有监督微调大幅提高了事件日志的生成质量，而微调前的模型即使提供上下文示例，输出仍与原始日志出现明显偏差。
2. 经过微调后，Llama3.1-8B-Instruct 与 Ministral-8B-Instruct-2410 在轨迹序列一致性（Kendall’s Tau 与 Levenshtein 指标接近 1.0）以及整体过程发现质量（F1 ≈ 0.5–0.6，见 Inductive Miner；在 Heuristics Miner 下 F1 ≥ 0.9）上均接近真实数据水准。
3. **微调具有跨领域与跨分布泛化能力**：即便只在交通罚款文本上训练，对医疗摘要的迁移也有显著提升（F1 改善 4–12 个百分点），在 held-out 生成器实验上总体也保持优势（4–40 个百分点），说明模型学会了通用的"文本→日志"映射。
4. **开放权重小模型即可胜任**：不需要大规模前沿模型，相对较小的开源 LLM 在 SFT 后足够完成结构化数据翻译任务，为本地化部署提供了可行性。
5. 合成数据路径（前沿模型生成半合成文本）是解决 PM 领域数据短缺问题的有效手段，也是本文的独立贡献。

## 7. 优点

- **将 LLM 定位为单纯的数据翻译器**而非流程建模器，实现了关注点分离，架构清晰且灵活——PM 算法无需改变，仅需稳定的数据输入。
- **构造了高质量的合成数据集**：用多个前沿模型配合 5 种 persona 与多种提示模板生成多样化文本，词汇多样性指标与去嵌入验证均给出了正面证据，有效缓解了数据缺失问题。
- **打破循环依赖**：与 Buss et al.（用同一 LLM 生成文本并提取流程信息）不同，本文特意让不同模型承担不同角色（前沿模型生成 vs 小模型提取），避免了生成-提取之间的纠缠和风格偏差放大。
- **统一而纵深的两层评估框架**：既评价单轨迹（XML 合法性、长度、顺序、属性准确度），又评价整体流程（过程发现模型的 fitness、precision 与 F1），对"日志是否真的能直接用于流程挖掘"给出了较强证据。
- **考虑幻觉检测**：通过在系统提示中限定活动/属性集合，评估了模型"编造"内容的概率，这对部署该类管道极为实用。
- **相对透明**：作者公开了训练/评估代码与数据集样例，便于复现；论文也明确承认合成数据与真实文本风格差异是其局限而非隐性问题。
- 实验考虑了多种 LLM（Llama3.1、Ministral、Qwen2.5）之间的差异，并验证了跨领域与跨生成器性能，含金量较高。

## 8. 不足与局限

- **数据是合成的，非真实专家文本**：真实事故工单/警察报告往往是"表单+叙述"的混合结构，而合成数据基于日志描述生成的叙事文本与之存在分布差异；即使在语义提取层面这种差异可能不关键，但缺乏真实场景验证则难以确认其在实际 PM 落地中的直接可用性。
- **受限于 XES 传统的 case-centric 范式**：仅支持"一个案例一条轨迹"的事件模型，无法表示 OCEL（Object-Centric Event Log）中多对多的对象关系；而现代业务中对象中心日志被认为是更有前景的方向，这限制了该框架的可延展性。
- **对基率问题的评估盲点**：在人工标注质量检查中，由于大多数文本是高质量的，合成文本缺陷的实际数量过少（低基率），作者虽然通过 Cohen’s Kappa paradox 做了说明，但无法对少量失败案例做针对性的模式分析；同时报告者间一致性指标的置信度有限。
- **模型选择偏窄**：虽然覆盖了三个 ~8B 模型，但没有验证不同参数规模（如 70B）或不同基础结构（非 Instruct 预训练方式）上的效果，也缺乏与更大规模模型做深度横向对比的鲁棒性证据。
- **评估边界有限**：trace 级对比中，若事件长度不一致，计算 Kendall’s Tau 时对过短或过长的轨迹做了截断/填充，可能掩盖局部排序的真实错误；属性相似度简化为分类一致性/指数衰减向欧氏距离，忽略了属性间的语义相关性；对时间戳（“日期”）值的忠实性未像活动顺序一样深入评估。
- **未讨论 RL / 奖励模型或思维链（CoT）的可能增强**；作者在结论中也承认使用强化学习与可验证奖励可能进一步提升跨分布泛化表现。
- **整体精度仍达不到完美**：例如 Inductive Miner 下即使 SFT 也无法把过程模型的 精确度恢复到与原始日志完全一致的 0.40，说明日志中仍存在多余的轨迹行为；医疗跨领域与生成器迁移表现与训练数据差异较大时会出现较大性能下降。
