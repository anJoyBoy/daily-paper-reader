## 摘要
过程挖掘（PM）为从事件数据中发现和优化运营流程提供了强大的框架。然而，PM技术的有效性严格依赖于结构化事件日志的可用性。迄今为止，事件日志通常由领域专家和过程挖掘专家费力地创建。这种高昂的成本导致大量组织知识（包括事件工单、手册和文本报告）未被充分利用。我们通过研究大语言模型（LLMs）作为自动化数据转换器的有效性来解决这一瓶颈。我们提出了一个可扩展的框架，利用LLMs作为数据转换器，弥合非结构化文本资源与结构化事件数据之间的差距。我们在一个新创建的文本到日志数据集上微调LLMs，证明所得模型可以从非结构化资源中提取高保真的事件日志。我们的结果表明，这种微调方法在性能上大幅优于少样本或零样本提示，突出表明微调是生成可靠事件数据的必要前提。我们得出结论，我们的方法为将以前未使用的数据提供给过程挖掘生态系统提供了一条有前景的流水线，有效扩展了使用PM进一步研究组织工作流程的可能性。

## Abstract
Process mining (PM) provides a powerful framework for discovering and optimizing operational processes from event data. However, the efficacy of PM techniques is strictly predicated on the availability of structured event logs. Thus far, event logs have often been laboriously created by domain and process mining experts. This costly effort causes large portions of organizational knowledge, including incident tickets, manuals, and textual reports, to remain underutilized. We address this bottleneck by investigating the efficacy of Large Language Models (LLMs) as automated data translators. We propose a scalable framework that leverages LLMs as data translators to bridge the gap between unstructured textual resources and structured event data. We finetune LLMs on a newly created text-to-log dataset, demonstrating that the resulting models can extract high-fidelity event logs from unstructured resources. Our results show that this finetuning approach outperforms few-shot or zero-shot prompting by a large amount, highlighting finetuning as a necessary pre-condition for generating reliable event data. We conclude that our method provides a promising pipeline for making previously unused data available to process mining ecosystems, effectively expanding the possibilities of using PM to further investigate organizational workflows.

## 6. 论文的主要结论与发现

- **微调是必要条件而非锦上添花**：与零样本/少样本提示相比，SFT 在生成事件日志的准确性和结构性上实现了质的飞跃。例如，微调后的 Llama3.1-8B 在 434 条测试报告中生成 430 条有效 XES 轨迹，而零样本方法几乎无法产生任何合格输出。
- **可部署于本地小模型**：相对小型的开源 LLM（7B—8B 参数）经过微调即可胜任文本到事件日志的转换任务，无需依赖重量级前沿模型完成结构化抽取，这对实际部署具有重要意义。
- **良好的跨域泛化**：在警察报告语料上微调的模型迁移到医疗领域的出院小结时，F1 指标仍有显著提升（如 Inductive Miner + Llama 的 F1 从 0.09 提升至 0.13），说明模型学到的是文本到日志的一般映射能力，而非对单一领域的死记硬背。
- **合成数据策略有效**：利用前沿 LLM 生成合成文本作为训练数据，能够缓解真实配对数据短缺的问题，且生成的文本在语义保真度（0.95）和时间线索清晰度（0.98）上获得了人工评测的高分。
- **模型间存在明显差异**：Llama3.1-8B 与 Ministral-8B 的微调效果最好；Qwen2.5-7B 经微调后虽然格式合规率较高，但生成的轨迹存在活动缺失或序列错乱问题（Kendall's Tau 仅约 0.42），表明不同基础模型对 SFT 的响应能力有显著差异。

## 8. 不足与局限

- **合成数据与现实数据的偏差**：作者也坦承，合成"警察报告"体现的文本分布与现实中的警务文档（常为"表格+叙述"混合结构）存在较大差异。若迁移到真实、杂乱的非结构化文档环境，模型性能可能会显著降低。目前全流程的验证均基于合成文本，缺少真实语料的对照实验。
- **事件日志范式受限**：当前输出被约束为 XES 标准下的**案例为中心（case-centric）**日志，无法处理对象中心（object-centric）模型中多对多实体关系。
- **评估指标存在薄弱环节**：在过程层面的评估中，Inductive Miner 生成的模型 F1 值明显偏低（0.43—0.51 vs 原始日志的 0.58），说明生成的日志中仍存在行为偏差，实际可用性有待提升。
- **某些指标定义不够精确**：分类/数值属性相似度的计算未说明对不可比样本（如无法对齐的属性缺失时）的处理方式，语义等价文本（如同义词、语序替换）的相似性也可能被低估。
- **幻觉率统计偏差风险**：零样本设置下因合规轨迹数量极少（如 Qwen2.5 仅 2 条有效轨迹），1/2 的单项差值就会使比率呈 150% 的剧烈变化；Qwen 微调后属性幻觉率绝对数量反而高于 one-shot 设置，指标解释上不够稳健。
- **数据与算力信息透明度不足**：未披露 GPU 型号、训练时长等资源消耗信息，对训练集构建成本（调用前沿模型 API 的数量和费用）也未作说明，复现成本难以预估。
- **规模与覆盖面有限**：仅覆盖两个领域（交通罚单、医疗），测试集规模较小（警察日志约 434 条文本），过程变体较多时统计功效可能会受到削弱；未讨论文本输入是纯虚构生成文本时有偏差的叙事腔调对于抽取难度的影响。
