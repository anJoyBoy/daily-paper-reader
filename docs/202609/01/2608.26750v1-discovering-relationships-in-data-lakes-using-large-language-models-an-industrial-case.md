## 摘要
数据湖依赖元数据来保持可用性，然而在列关系发现任务中，这些元数据往往有限或信息量较弱，尤其是对于包含编码或缩写模式标签的、源自ERP的数据集。我们提出ColRel，一种两阶段方法，它利用摄取时可用的元数据和数据构建列嵌入。在编码模式之类的困难情形下，业务词典有助于更好地解释列名，并支持生成第二阶段所用的简短自然语言描述。在公开基准和一个工业ERP数据集上的实验表明，ColRel在语义相关、弱信号场景中尤为有效。

## Abstract
Data lakes rely on metadata to remain usable, yet this meta data is often limited or weakly informative for column relationship discovery, especially in ERP-derived datasets with coded or abbreviated schema labels. We propose ColRel, a two-stage method that builds column embeddings from metadata and data available at ingestion time. In difficult cases, such as coded schemata, business dictionaries help better interpret column names and support the generation of short natural-language descriptions used in the second stage. Experiments on public benchmarks and an industrial ERP dataset show that ColRel is particularly effective in semantically related, weak-signal settings.

## 2. 论文提出的方法论

### 2.1 核心思想

论文提出 **ColRel**，一种**两阶段列关系发现方法**：

- **Stage 1（嵌入检索）**：从摄取时可用的证据（schema 线索 + 代表性值）构建列嵌入，通过余弦相似度进行候选检索。
- **Stage 2（语义增强，可选）**：当信号弱时，利用**业务词典**辅助解释编码列名，并让 LLM 为每列生成简短的自然语言描述，注入嵌入输入以增强语义。

### 2.2 完整流程（五步）

1. **Column-to-Text（列转文本）**：为每列构建紧凑文本表示 `colText`，包含：
   - Schema 线索：原始列名、分词变体（如下划线/驼峰拆分）、数据类型
   - 代表性值：固定预算的非空值和频次高的值的混合样本

2. **Column Description Generation（LLM 描述生成）**：
   - 使用 GPT-4o-mini 生成简短的列语义描述 `colDesc`
   - 将 `colText` 与从**业务词典**中检索到的 code-to-label 映射、域提示、构造规则等拼接为 prompt
   - 描述严格基于已有证据，目标是"用自然语言说出列的最可能含义"

3. **Column Encoding（列编码）**：
   - 最终输入：`colInput(c) = colText(c) ∥ colDesc(c)`
   - 编码：`vc = f(colInput(c)) ∈ R^d`，使用 sentence embedding 模型

4. **Similarity Computation（相似度计算）**：
   - `score(a, b) = cos(va, vb)`
   - 对每个源列，按分数对目标列排序，返回 Top-k 候选

5. **Review and Validation（人工验证）**：
   - 用户审查排名靠前的建议，标记正确/错误，量化有限审查预算下的有效性

### 2.3 关键技术特点

- LLM 仅在**每列调用一次**（而非每对候选列），保持了大仓库场景的可扩展性
- 业务词典提供了**可解释的、领域锚定的语义知识**，是处理编码模式的关键
- 嵌入向量每列仅一个，检索高效

### 6.1 Joinable（可连接）场景

- **几乎逼近上限**：由于共享标识符和值重叠提供强实例证据，多数方法达到了接近完美的 Hit@5 和 MRR
- 差异主要体现在**对 schema 噪声的鲁棒性、排序一致性和运行时间**
- 在 ChEMBL-Noisy 上，经典方法 COMA-Schema 降到 Rec@|GT| = 0.18，Cupid 降到 0.31；嵌入方法中 BGE-m3 表现最好（Rec@|GT| = 0.79）

### 6.2 Semantically Related（语义相关）场景

- **经典方法在此场景下显著退化**，如 Public Housing 上 Jaccard 和 Cupid 的 Rec@|GT| 为 0.00，Cupid 需 422 秒
- **ColRel–Stage 2 效果最显著**：在 Public Housing 上，BGE-m3 的 Hit@5 从 Stage 1 的 0.65 提升到 **0.82**，MRR 从 0.37 提升到 **0.68**
- ChEMBL-Clean 上增益较小（因为基线已很高），ChEMBL-Noisy 上增益中等但稳定
- **结论**：在编码的 ERP 模式中，**语义增强对于在用户的短列表中最大化有用匹配至关重要**

### 6.3 总体结论

- ColRel 的通用性较好：只要能以 schema 线索 + 代表性值 + 业务词典来表示列，方法就可迁移到其他领域
- 结合业务词典和 LLM 描述的语义增强，在不改变嵌入和相似度计算 pipeline 的前提下显著提高了排序质量
