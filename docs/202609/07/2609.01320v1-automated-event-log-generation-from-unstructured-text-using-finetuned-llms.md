## 摘要
流程挖掘（PM）为从事件数据中发现和优化运营流程提供了强大的框架。然而，PM技术的有效性严格依赖于结构化事件日志的可用性。迄今为止，事件日志通常由领域专家和流程挖掘专家费力地创建。这种高成本的工作导致大量组织知识（包括事件工单、手册和文本报告）未被充分利用。我们通过研究大语言模型（LLM）作为自动化数据转换器的有效性来解决这一瓶颈。我们提出了一个可扩展的框架，利用LLM作为数据转换器，弥合非结构化文本资源与结构化事件数据之间的差距。我们在一个新创建的文本到日志数据集上微调LLM，证明了所得模型可以从非结构化资源中提取高保真事件日志。我们的结果显示，这种微调方法在性能上大幅优于少样本或零样本提示，突显了微调是生成可靠事件数据的必要前提。我们得出结论，我们的方法为将先前未使用的数据提供给流程挖掘生态系统提供了一条有前景的流水线，有效扩展了使用PM进一步调查组织工作流程的可能性。

## Abstract
Process mining (PM) provides a powerful framework for discovering and optimizing operational processes from event data. However, the efficacy of PM techniques is strictly predicated on the availability of structured event logs. Thus far, event logs have often been laboriously created by domain and process mining experts. This costly effort causes large portions of organizational knowledge, including incident tickets, manuals, and textual reports, to remain underutilized. We address this bottleneck by investigating the efficacy of Large Language Models (LLMs) as automated data translators. We propose a scalable framework that leverages LLMs as data translators to bridge the gap between unstructured textual resources and structured event data. We finetune LLMs on a newly created text-to-log dataset, demonstrating that the resulting models can extract high-fidelity event logs from unstructured resources. Our results show that this finetuning approach outperforms few-shot or zero-shot prompting by a large amount, highlighting finetuning as a necessary pre-condition for generating reliable event data. We conclude that our method provides a promising pipeline for making previously unused data available to process mining ecosystems, effectively expanding the possibilities of using PM to further investigate organizational workflows.

## 2. 论文提出的方法论

### 2.1 核心思想
将 LLM 定位为**数据翻译器（data translator）**，输入为自然语言流程描述（如警察办案报告、出院摘要），输出为结构化的 **XES 格式事件日志**（包含 trace、事件、活动、时间戳和属性），整个过程无需人工定义流程模型。

核心 pipeline 分为三个子阶段（对应论文图 1）：

```
真实事件日志 → 合成文本（用大规模前沿模型生成）
→ 对开源落模型（7B~8B级）进行监督微调
→ 对未知文本进行事件日志抽取与质量评估
```

### 2.2 主要技术环节

（1）**合成文本数据生成**
- 以真实 XES 事件日志为骨架，通过 API 调用三个强前沿模型（GPT-5.1、Qwen3-max、Mistral-medium），让模型将给定的 trace 序列化为自然语言文本；
- 设计了 5 种人设（用于增加文本风格多样性：性别、族裔、职业、性格、地点不同），面向每个日志设计了 3 种不同任务描述与提示词；
- 采样时采用随机温度（temperature 0.6~0.9，固定 top-p=0.9），加入随机性以保证文本多样性。

（2）**提示（Prompting）方法**
- **零样本（zero-shot）**：只提供任务指令；
- **少样本（few-shot / one-shot）**：任务指令加一条来自开发集的“文本—XES trace”演示对，并用随机采样避免过拟合。

（3）**LLM 监督微调（SFT）**
- 训练 3 个开源可本地部署模型：`Llama3.1-8B-Instruct`、`Ministral-8B-Instruct-2410`、`Qwen2.5-7B-Instruct`；
- 使用 LoRA 低秩适配（rank=16），保证单 GPU 可训练；
- 每个训练样本包含系统提示、指令、一条 one-shot 演示及目标 XES trace；损失只在目标 token 上计算，提示 token 被 mask。

（4）**评估框架**
- 论文指出：文本到日志自动生成缺乏统一评估范式，因此作者搭建了**双视角（两个层面）评估**：
  - **trace 级别**：XML 格式合法性/完整性、事件轨迹与原始日志的 Levenshtein 距离、Kendall's Tau、分类与数值属性相似度、幻觉属性/活动率；
  - **process 级别**：使用 Inductive Miner 和 Heuristics Miner 挖掘得到过程模型，与原始数据挖掘出的模型比较 fitness、precision 与 F1。

## 6. 论文的主要结论与发现

1. **SFT 是必要前提**：在 7B~8B 开源 LLM 上，SFT 可大幅提高生成事件的语法合法性和语义保真度；one-shot 远不及 SFT；zero-shot 在绝大多数模型上产出近乎无用（无法形成可解析 XES）。
2. **LLM 能抽取高保真文本事件数据**：SFT 后，Llama3.1-8B-Instruct 和 Ministral-8B-Instruct-2410 在 trace 层面（活动顺序与长度）与原日志非常接近，Levenshtein 得分均值 0.99～1.0，Kendall's Tau 均值 0.99。
3. **微调可降低变体数量偏移与幻觉率**：SFT 后变体数逼近原始 log；提供活动/属性白名单后，活动幻觉率接近 0；属性幻觉率整体较低（Qwen2.5 相对略高）。
4. **Process-level 质量对 SFT 敏感**：在过程模型层面，SFT 生成的 log 能显著提高 Inductive Miner/Heuristics Miner 模型与原始 log 的精度与 F1 的契合程度，F1 与原始结果更接近。微调后的 Llama 和 Ministral 在 Heuristics Miner 下甚至可实现 precision 1.0。
5. **一定规模上存在域间迁移能力**：在道路罚款语料上训练的 SFT 模型在脓毒症（医学域出院摘要）上也优于 one-shot，说明 LLM 学到的不单是格式匹配；但仍存在对训练文本分布的一定过拟合。
6. **合成数据自身可作为通用管道组件**：前沿模型产生的合成文本质量高、多样性较好，是自监督数据的可行来源。

## 9. 对未来研究的启示

- **从“单文本→单 trace”走向“多文档→跨对象日志”**：论文的 XES trace 范式本质上是一次性叙述切片，而真实组织的流程知识往往散落在多个关联文档（工单会话、邮件链、审批记录）中。将 LLM 能力拓展到多文档聚合与 **OCEL（Object-Centric Event Log）** 生成，是文本驱动 PM 更值得探索的方向。
- **把真实文本与合成文本按比例混合训练**：全合成设置的局限提示我们，未来应尝试“合成预训练 + 真实文本少量微调”的两阶段策略，用真实语料的噪声与模糊性增强模型的鲁棒性；也可以利用判别式分类器主动筛选合成文本中置信度低的样本送人工复核，形成更高效的人机协同数据管道。
- **在相同数据上对比 LLM-based 与经典 NLP 抽取基线**：仅与提示 / SFT 变体对比还不足以证明“文本到日志需要 LLM 监督微调”是必要条件，引入基于规则、序列标注或语义解析的传统抽取器作为下限基线，会让结论更扎实。
- **引入细粒度错误类型学（taxonomy of errors）**：将幻觉活动、事件乱序、属性缺失、trace 截断/合并等错误分门别类统计，而非只报道聚合距离指标，将有助于定位模型的薄弱环节，并指导更具针对性的数据增强。
- **将“文本可回溯性”作为评测维度**：生产环境中使用者需要知道日志中每个事件对应的原文依据。未来可要求模型输出事件—原文片段的对齐引用，既能降低幻觉，也能增强信任度。

## 10. 总体评价

总体而言，这是一篇定位务实、实验设计较完整的应用型研究。它的核心贡献不在于提出新的 LLM 架构或新的流程挖掘算法，而在于验证了一个重要且可复用的工程命题：**用先进模型合成文本、再用小规模开源模型监督微调，即可把非结构化流程文本可靠地转化为标准事件日志**。该结论直接回应了流程挖掘社区的数据准备瓶颈，也为其他结构化数据抽取任务（如文本到数据库记录、文本到 API 调用序列）提供了一个可参考的“合成—微调—多级评测”范式。

论文的亮点在于刻意将 LLM 的角色限制在数据翻译层，从而规避了“让 LLM 直接生成流程模型”的不可控性，既降低了部署门槛，又保住了下游流程发现算法的成熟优势。同时，论文对评估框架的搭建——尤其是 trace 与 process 双层面、多种距离度量与两种 Miner 的组合——展示了较强的严谨性，为后续研究提供了可复用的评测脚手架。

它的主要短板则集中体现在数据现实性与评测深度上：全合成文本、单方向跨域以及以原日志为唯一真值的还原式评估，都使结论的生态效度（ecological validity）存在局限。换言之，论文有力地证明了“在合成文本分布上，SFT 必要且有效”，但距离“真实组织文本可直接投产”仍有关键一步需要迈过。

对于目标读者（流程挖掘研究者、LLM 应用工程师、组织知识管理实践者），本文值得精读；若要据此复现或扩展，建议重点补做三件事：一是在真实工单/文书中验证效果；二是加入管线式非 LLM 基线；三是尝试多文档与 OCEL 场景，检验该方法在更丰富对象关系下的表现。
