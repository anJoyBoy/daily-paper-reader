## 摘要
流程挖掘（PM）为从事件数据中发现和优化运营流程提供了强大的框架。然而，PM技术的有效性严格依赖于结构化事件日志的可用性。迄今为止，事件日志通常由领域专家和流程挖掘专家费力地创建。这种高昂的成本导致大量组织知识（包括事件工单、手册和文本报告）未被充分利用。我们通过研究大型语言模型（LLM）作为自动化数据转换器的有效性来解决这一瓶颈。我们提出了一个可扩展的框架，利用LLM作为数据转换器，弥合非结构化文本资源与结构化事件数据之间的差距。我们在一个新创建的文本到日志数据集上对LLM进行微调，证明所得模型可以从非结构化资源中提取高保真事件日志。我们的结果表明，这种微调方法在性能上大幅超越少样本或零样本提示，突显了微调作为生成可靠事件数据的必要先决条件。我们得出结论，我们的方法为将先前未使用的数据提供给流程挖掘生态系统提供了一条有前景的流水线，有效扩展了使用PM进一步调查组织工作流程的可能性。

## Abstract
Process mining (PM) provides a powerful framework for discovering and optimizing operational processes from event data. However, the efficacy of PM techniques is strictly predicated on the availability of structured event logs. Thus far, event logs have often been laboriously created by domain and process mining experts. This costly effort causes large portions of organizational knowledge, including incident tickets, manuals, and textual reports, to remain underutilized. We address this bottleneck by investigating the efficacy of Large Language Models (LLMs) as automated data translators. We propose a scalable framework that leverages LLMs as data translators to bridge the gap between unstructured textual resources and structured event data. We finetune LLMs on a newly created text-to-log dataset, demonstrating that the resulting models can extract high-fidelity event logs from unstructured resources. Our results show that this finetuning approach outperforms few-shot or zero-shot prompting by a large amount, highlighting finetuning as a necessary pre-condition for generating reliable event data. We conclude that our method provides a promising pipeline for making previously unused data available to process mining ecosystems, effectively expanding the possibilities of using PM to further investigate organizational workflows.

## 6. 主要结论与发现

- **微调是必要前提**：零样本和单样本提示生成的事件日志在语法合法性、事件顺序保真性和变体分布方面都不理想；只有经过 SFT 后的 7–8B 级开源模型才能稳定地输出高保真的 XES 日志。
- Trace 级结果：
  - Llama3.1-8B-Instruct 微调后生成 430/434 条有效轨迹；Llama3.1 与 Ministral 的归一化 Levenshtein 均值达到约 0.99/1.0，Kendall's Tau 均值约 0.99；
  - 微调后变体数量与原始日志（43 个）几乎一致（46 与 43），而 one-shot 下则在 129 以上；
  - 幻觉率在合法 traces 中极低，活动级幻觉率几乎为零。
- 过程级结果：
  - Inductive Miner 下所有方法 fitness 均为 1.0，但微调显著提升 precision 与 F1（Llama3.1 微调后 F1≈0.51，接近原始日志对应 F1≈0.58）；
  - Heuristics Miner 下微调模型生成的日志所发现的模型 precision 达 0.90–1.0，与原始日志一致，F1 最高接近 0.90。
- 跨域与泛化：文本到日志映射能力可以直接迁移到医学领域中超出训练分布的文本类型和未见过的文本生成器；留出生成器实验中 H euristics Miner 下 F1 增长达 +36～+40 pp。说明微调学到了通用“文本→结构化日志”映射而非仅对训练分布的记忆。
- 合成数据的生成质量较高：文本按事件顺序和日期线索来忠实还原 traces，法度与时间清晰度量约为 0.95–0.98（受 Kappa paradox 影响标注一致性偏低）。

## 7. 优点

- 提出了“数据翻译器”角色分工：LLM 不要直接承担过程建模与挖掘职责，只负责为成熟过程发现算法提供结构化数据——把任务边界拆分到一个更可控的层面。
- 完整覆盖了“数据合成 → 模型微调 → trace 级与过程级评估”的闭环，这为后续开展类似任务提供了可供借鉴的流水线与公开资源（仓库中开放代码与数据集片段）。
- 对合成文本做了多维度质量控制（长度分布、n-gram 比率、嵌入距离、人工标注），能较好地避免合成数据失真影响下游结论的风险。
- 对比了三个来源不同、规模相似的模型，并同时报告 trace 级与过程模型级指标；过程级指标还使用两种差异较大的 Miner 算法做交叉验证，提高了结论可信度。
- 强调使用可在本地部署的小型开源模型开展流程挖掘，贴近企业隐私与实际部署需求。
- 跨域迁移与“未见生成器”实验提升了结论外推范围，显示了方法的可推广性。

## 8. 不足与局限

- 数据全部为合成文本。论文承认合成“警察报告”与真实警署形式/叙事混合的文档分布存在差距，且未使用真实非结构化文档验证，可能夸大方法的实际表现。
- 输出限于 XES 的单案例（case-centric）范式，尚不支持 OCEL 这种面向对象的、多对多关系的事件日志格式。
- 对 few-shot 演示数量未做消融：仅使用一条演示且未评估 zero/few-shot 之外的长输入、Prompt 工程变体对结果的潜在增益。

- 对计算资源与训练耗时未做明确报告，可能影响他人复现时的成本预估。
- 由于原始任务要求输出完全规范化的 XES，本文的评估对非法输出采取直接剔除策略（“NA”），对真实应用场景中部分失败的成本考虑不足。
