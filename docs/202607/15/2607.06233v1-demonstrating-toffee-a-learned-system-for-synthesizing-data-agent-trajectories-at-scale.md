## 摘要
基于大语言模型的数据智能体在数据驱动决策中扮演着越来越重要的角色。然而，现有的数据智能体难以泛化到未见过的数据环境和分析工作流，尤其在异构的企业环境中。这导致对合成高质量数据智能体轨迹的需求日益增长，这些轨迹能够捕捉给定数据环境中的复杂分析工作流。此类轨迹支持两个关键的下游用途：它们可以作为监督微调数据，使数据智能体模型适应目标领域；也可以作为上下文学习示例，指导通用大语言模型在陌生数据环境中工作。因此，我们引入了TOFFEE，这是一个通过蒙特卡洛树搜索（MCTS）结合自适应模型选择和跨任务前缀复用来从给定数据环境合成高质量数据智能体轨迹的系统。我们展示了TOFFEE能够有效地为跨异构环境的复杂分析任务生成可扩展的轨迹数据。在本演示中，我们展示了TOFFEE的系统框架，包括其任务池构建、轨迹探索器和学习成本模型。我们还介绍了TOFFEE的Web界面及其工作流，并演示了两个端到端场景：用于数据智能体微调的轨迹合成，以及演示增强的数据智能体推理。

## Abstract
LLM-powered data agents are playing an increasingly important role in data-driven decision making. However, existing data agents struggle to generalize to unseen data environments and analytical workflows, especially in heterogeneous enterprise settings. This creates a growing need for synthesizing high-quality data agent trajectories that capture complex analytical workflows for given data environments. Such trajectories support two key downstream uses: they can serve as supervised finetuning (SFT) data that adapts data agent models to the target domain, and as in-context learning (ICL) demonstrations to guide general-purpose LLMs in unfamiliar data environments. Thus, we introduce TOFFEE, a system for synthesizing high-quality data agent trajectories from given data environments via Monte Carlo Tree Search (MCTS) with adaptive model selection and cross-task prefix reuse. We show that TOFFEE can effectively generate scalable trajectory data for complex analytical tasks across heterogeneous environments. In this demonstration, we present the system framework of TOFFEE, including its task pool construction, trajectory explorer, and learned cost model. We also introduce the web interface of TOFFEE and its workflow, and demonstrate two end-to-end scenarios: trajectory synthesis for data agent finetuning, and demonstration-augmented data agent reasoning.

## 2. 方法论：核心思想、关键技术细节

### 核心思想
TOFFEE 是一个**预算感知的轨迹合成系统**，通过**蒙特卡洛树搜索（MCTS）** 结合**自适应模型选择**和**跨任务前缀复用**，从给定数据环境自动合成高质量数据智能体轨迹。系统分为三个主要阶段：任务池构建、轨迹探索、轨迹导出与下游使用。

### 关键技术细节

#### 2.1 任务池构建（Task Pool Construction）
- **输入**：用户连接的数据环境（数据库、CSV、JSON、Markdown等），或从现有基准（Spider、LiveSQLBench、SpreadsheetBench）中采样。
- **流程**：
  1. **环境画像**：收集模式元数据和样本行。
  2. **依赖发现**：运行预定义SQL模板发现数据依赖（如共享客户ID、按地区订单取消率差异）。
  3. **问题生成**：LLM将每个依赖表述为有意义的数据智能体问题。
  4. **执行验证**：对每个候选任务重放解决方案步骤，确认结果稳定且依赖执行证据；拒绝无数据访问即可回答的问题。最终保留具有**确定性答案**和**已验证执行证据**的任务。

#### 2.2 轨迹探索器（Trajectory Explorer）
- 基于MCTS的树搜索：每个节点是分析状态，每条边是工具调用（SQL查询、Python脚本等），由特定LLM配置生成。
- **关键特点**：
  - 从**共享前缀**开始（跨任务复用同一数据环境的常见操作如模式发现、数据画像），仅运行一次。
  - 在每次扩展时，调用**学习成本模型（LCM）** 选择分支宽度和推理配置（受剩余预算约束）。
  - 遇到执行错误时，不丢弃部分轨迹，而是分支进入**修复路径**，保留错误-诊断-修复序列作为训练数据。
  - 当确定性验证器确认执行输出与任务构建时的证据匹配且最终答案正确时，存储轨迹。

#### 2.3 学习成本模型（Learned Cost Model, LCM）
- **作用**：预算感知的控制器，从当前分析状态和剩余API预算中选择LLM与推理配置。
- **工作方式**：
  - 提取状态特征向量（轨迹进度、模式覆盖率、最近错误历史）。
  - 对每个可行配置（操作符、模型、上下文长度、推理努力等），通过**预测奖励μ**与**探索奖励σ**（对少探索配置的奖励）结合评分。
  - 根据排名最高配置间的分歧度设置分支宽度K（预算缩小时K减小）。
- **在线学习**：探索器与LCM形成闭环，每步后根据执行成功和分析进度计算奖励，通过**岭回归**更新LCM的赌博机参数，改进后续路由和分支决策。

#### 2.4 轨迹导出与下游使用
- **SFT**：轨迹变成多轮训练样本（如TOFFEE-9B、TOFFEE-27B，基于Qwen3.5-9B/27B微调）。
- **ICL**：最高质量轨迹作为工作示例（演示）：用户提问时，系统检索相似轨迹注入提示，引导模型遵循已验证的工作流。
