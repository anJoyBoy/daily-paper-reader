## 摘要
机器学习工程代理每次竞赛都从零开始，浪费计算资源重新发现已知技术。我们提出HASTE，一个分层多智能体系统，将跨竞赛知识组织为三个范围层级（全局、领域和竞赛特定），每个层级对应一个匹配的智能体级别。一个协调器负责协调领域专家，并通过LLM驱动的抽象促进层级间的学习。控制消融实验为层级加载提供了证据：在8个竞赛中保持159个技能库存不变，层级加载实现了100%的奖牌率，而平面加载仅达到62.5%，与不加载技能相同的奖牌率，且消耗两倍的输出令牌。在完整的MLE-Bench Lite基准测试（22个Kaggle竞赛）上，HASTE使用Claude Sonnet 4.6在每竞赛12小时的限制下达到了77.3%的奖牌率。在冷启动运行中，系统初始没有积累技能。在热启动运行中，系统重新加载从先前竞赛中学到的技能，仅使用全局和领域级技能进行跨竞赛迁移。热启动使用的精炼迭代次数减少52%，且代理保留的建议变更比例从低库存时的42%上升到拥有50+技能后的85%。这些结果表明，更好的知识组织可以在一定程度上替代机器学习工程代理中的模型强度和计算预算。

## Abstract
ML engineering agents waste compute rediscovering known techniques because every competition is a cold start. We present HASTE, a hierarchical multi-agent system that organizes cross-competition knowledge into three scope tiers (global, domain, and competition-specific), each coupled to a matching agent level. An orchestrator coordinates domain specialists and promotes learning between tiers via LLM-driven abstraction. A controlled ablation provides evidence for scoped loading: holding a 159-skill inventory constant across 8 competitions, tiered loading achieves a 100% medal rate while flat loading reaches only 62.5%, the same medal rate as loading no skills, and consumes 2x the output tokens. On the full MLE-Bench Lite benchmark (22 Kaggle competitions), HASTE reaches a medal rate of 77.3% using Claude Sonnet 4.6 at 12h per competition. In a cold-start run, the system begins with no accumulated skills. In warm-start runs, it reloads skills learned from earlier competitions, using only global and domain-level skills for transfer across competitions. Warm starts use 52% fewer refinement iterations, and the fraction of proposed changes kept by the agent rises from 42% at low inventory to 85% once 50+ skills are available. These results suggest that better knowledge organization can partly substitute for model strength and compute budget in ML-engineering agents.

### 2. 论文提出的方法论：核心思想、关键技术细节

-   **核心思想**：**层次化技能积累与作用域限制加载**。通过构建一个三层级的技能库，并结合一个匹配的智能体分层架构，在运行时只加载与当前任务范围相匹配的技能，从而保持提示清晰并避免无效信息干扰。

-   **关键技术细节**：
    1.  **技能层次（Skill Hierarchy）**：知识被组织成三个范围层级：
        -   **全局级（Global）**：适用于所有ML任务的通用技能，如过拟合、欠拟合的诊断与处理。
        -   **领域级（Domain）**：适用于特定数据领域（如表格、NLP、视觉）的技能，如特定领域的最佳模型选择。
        -   **竞赛级（Competition）**：与特定竞赛数据集强相关的技能，适用于重新运行同一竞赛。
    2.  **智能体层次（Agent Hierarchy）**：
        -   **协调器（Orchestrator）**：负责任务分配（分类竞赛所属领域）、日程调度（先运行种子任务）以及**技能推广**。后者在一个竞赛完成后，使用LLM评估其学习到的经验，并决定将其提升到更高层级（从竞赛级到领域级或全局级）。
        -   **领域专家（Specialist）**：每个领域（如表格、NLP、视觉）都有一个专门的智能体，它只会加载全局级和其对应领域的技能。
    3.  **执行循环（Execution Loop）**：每个领域专家针对一个竞赛，执行一个五阶段的流水线：
        -   **任务分析**：解析元数据、数据集特征，选择交叉验证策略。
        -   **原型筛选**：提出并测试三个不同策略的模型，选出最优和次优进行下一步。
        -   **自适应精炼**：对最优和次优模型执行一个线性的“探索→优化→微调”循环。该循环只有连续两次没有改进时才自动升级到下一阶段，并且任何导致分数下降的更改都会被自动回滚。
        -   **集成**：对最优模型的多个检查点进行集成。
        -   **产生学习**：LLM反思整个实验历程，产生结构化的学习经验，包含成功和失败模式。

-   **算法流程（文字说明）**：
    1.  **初始化**：协调器将所有竞赛按领域分类。
    2.  **技能加载**：在运行某个竞赛时，协调器为该竞赛加载全局技能、相应领域的领域技能和该竞赛的特定技能。
    3.  **专家执行**：领域专家加载这些技能作为先验知识，运行一个线性的精炼循环来优化代码。
    4.  **学习与推广**：竞赛结束后，专家产生学习经验，协调器使用LLM对这些经验进行抽象和评估，决定是保留为竞赛级技能，还是抽象提升到领域级或全局级。
    5.  **重复与积累**：在后续竞赛中，系统加载之前积累并推广的高层级技能，实现迁移。

### 3. 实验设计：数据集 / 场景 / Benchmark / 对比方法

-   **数据集/场景**：涵盖图像、文本、表格和音频等多种数据领域的竞赛任务，如狗 vs. 猫分类、毒性评论分类、纽约出租车费用预测等。

    -   **消融实验**：重点对比了三种技能加载策略：

### 6. 论文的主要结论与发现

1.  **知识组织比技能数量更重要**：固定技能库存的消融实验表明，不加载任何技能与平面加载所有技能效果一样差（62.5%奖牌率），而层级加载则实现了100%的奖牌率。这说明，无序地塞入知识不仅无益，甚至有害（增加成本却不提升性能）。
2.  **层级加载能显著提升性能**：在完整的MLE-Bench Lite上，HASTE使用Claude Sonnet 4.6和12小时预算达到了77.3%的奖牌率，与使用更强模型和更长预算的顶级系统在同一性能区间。
3.  **技能积累提升迁移效率**：热启动（加载技能）比冷启动（无技能）减少52%的精炼迭代，并将代理自身提出的有效变更的保留率从42%提升至85%。这表明，好的先验知识能大幅减少无效尝试。
4.  **线性精炼循环的有效性**：作者证明，当一个强大的、结构化的先验知识被加载时，一个简单的线性精炼循环就足以匹敌更复杂的树搜索或进化算法，知识大大缩小了有效搜索空间。
5.  **效率提升显著**：层级加载在令牌消耗上比平面加载更具效率（每枚奖牌消耗284K vs 756K令牌）。

### 7. 优点：方法或实验设计上的亮点

-   **方法创新性强**：将层次化知识组织与作用域加载引入ML工程自动化领域，并给出了强有力的证据，思路清晰且新颖。
-   **消融实验设计精妙**：通过“固定库存”来测试“不同加载方式”的影响，非常干净地分离了“知识量”和“知识组织”两个因素带来的增益，有力地支持了论文核心论点。这是该工作最大的亮点。
-   **强调“失败”经验的价值**：系统明确记录和推广失败的经验（“什么不该做”），这在许多系统中被忽视，但能有效节省未来的探索成本。
-   **实践导向**：系统通过LLM进行技能抽象和推广，最终产物是可读的纯文本文件，实用性强，易于理解和维护。
-   **在有限资源下达成高性能**：论文证明了“巧干”可以部分替代“硬干”，这对于资源受限的研究者和应用场景具有重要价值。

### 8. 不足与局限

-   **单种子实验**：如前所述，这是最主要的局限。缺乏统计显著性验证，结果的泛化性和稳定性有待确认。
-   **技能库的初始积累过程**：技能库本身也是在层级推广机制下积累起来的，这导致消融实验中的“平面加载”或许并不完全公平，因为技能库的表述本身就是为层级结构优化的。一个完全在平面记忆下运行的系统表现会如何，是一个待探索的问题。
-   **规模尚小**：技能库总共有159条，竞赛集为22个。是否能有效扩展到MLE-Bench的75个或更多竞赛，以及技能库膨胀到数千条时的管理策略（如是否需要向量检索），有待验证。
-   **未进行全组件消融**：除了技能加载方式外，系统集成了多个工程组件（如原型筛选、失败模式分类等）。论文没有对这些组件进行逐一消融，以确定每个组件的独立贡献。
-   **应用限制**：目前的系统高度依赖于LLM（特别是用于抽象和推广的技能），其性能受限于底层LLM（Claude Sonnet 4.6）的能力。此外，该设计主要针对Kaggle竞赛这种有明确指标、数据和提交模式的场景，迁移到更开放、更复杂的ML工程任务中可能存在挑战。
