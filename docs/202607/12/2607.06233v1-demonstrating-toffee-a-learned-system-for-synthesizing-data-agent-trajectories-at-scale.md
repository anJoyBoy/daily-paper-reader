## 摘要
基于大语言模型的数据代理在数据驱动决策中扮演着越来越重要的角色。然而，现有的数据代理难以泛化到未见过的数据环境和分析工作流，尤其是在异构的企业环境中。这导致了对合成高质量数据代理轨迹的日益增长的需求，这些轨迹能够捕获给定数据环境下的复杂分析工作流。此类轨迹支持两个关键的下游用途：它们可以作为监督微调（SFT）数据，使数据代理模型适应目标领域；也可以作为上下文学习（ICL）示例，指导通用大语言模型在陌生数据环境中工作。因此，我们引入了TOFFEE系统，该系统通过蒙特卡洛树搜索（MCTS）结合自适应模型选择和跨任务前缀重用，从给定的数据环境中合成高质量的数据代理轨迹。我们展示了TOFFEE能够在异构环境中为复杂分析任务有效生成可扩展的轨迹数据。在本演示中，我们介绍了TOFFEE的系统框架，包括其任务池构建、轨迹探索器和学习成本模型。我们还介绍了TOFFEE的Web界面及其工作流程，并展示了两个端到端场景：用于数据代理微调的轨迹合成，以及演示增强的数据代理推理。

## Abstract
LLM-powered data agents are playing an increasingly important role in data-driven decision making. However, existing data agents struggle to generalize to unseen data environments and analytical workflows, especially in heterogeneous enterprise settings. This creates a growing need for synthesizing high-quality data agent trajectories that capture complex analytical workflows for given data environments. Such trajectories support two key downstream uses: they can serve as supervised finetuning (SFT) data that adapts data agent models to the target domain, and as in-context learning (ICL) demonstrations to guide general-purpose LLMs in unfamiliar data environments. Thus, we introduce TOFFEE, a system for synthesizing high-quality data agent trajectories from given data environments via Monte Carlo Tree Search (MCTS) with adaptive model selection and cross-task prefix reuse. We show that TOFFEE can effectively generate scalable trajectory data for complex analytical tasks across heterogeneous environments. In this demonstration, we present the system framework of TOFFEE, including its task pool construction, trajectory explorer, and learned cost model. We also introduce the web interface of TOFFEE and its workflow, and demonstrate two end-to-end scenarios: trajectory synthesis for data agent finetuning, and demonstration-augmented data agent reasoning.

- **核心动机**：合成高质量的数据代理轨迹（trajectories）——即多步推理、工具调用和执行结果的序列——可以为下游提供两种关键用途：作为监督微调（SFT）数据使代理适应目标领域，或作为上下文学习（ICL）示例引导通用LLM在陌生数据环境中工作。但大规模获取此类轨迹面临三大挑战：如何自动构建真实可解的任务（C1）、如何在巨大搜索空间下高效合成高质量轨迹（C2）、以及如何根据每一步的难度选择合适的推理配置（C3）。
- **整体意义**：TOFFEE系统旨在解决上述挑战，为数据代理提供可扩展、高质量的轨迹合成方法，从而提升数据代理在真实企业环境中的泛化能力。

## 2. 论文提出的方法论：核心思想、关键技术细节

TOFFEE由三个主要阶段组成：

### 2.1 任务池构建（Task Pool Construction）
- **核心思想**：避免直接提示LLM生成任务导致琐碎或不可解问题。而是通过轻量脚本探查数据环境，发现数据依赖（如共享键、趋势等），然后将每个依赖反向转化为多步分析任务，并验证任务可解且有意义。
- **流程**：
  1. 分析环境（连接数据库、文件等），收集元数据和样本行。
  2. 运行预定义的SQL模板发现数据依赖（如连接键、异常模式）。
  3. 利用LLM将每个依赖表述为有意义的分析问题。
  4. 执行验证：确认答案可稳定复现，并拒绝LLM无需访问数据即可回答的问题。只保留有确定性答案和验证执行证据的任务。

### 2.2 轨迹探索器（Trajectory Explorer）
- **核心思想**：基于蒙特卡洛树搜索（MCTS）进行探索，而不是单次生成或Best-of-N采样。每个节点是分析状态，边是工具调用。搜索从跨任务共享前缀（如模式发现）开始，减少冗余。
- **机制**：在每一步扩展时，调用学习成本模型（LCM）选择分支宽度和推理配置。遇到执行错误时不丢弃部分轨迹，而是分支到修复路径，保留错误-诊断-修复序列作为训练数据。轨迹被存储的条件是：其执行输出重现任务构建时的证据，且最终答案与验证的答案键匹配。

### 2.3 学习成本模型（Learned Cost Model, LCM）
- **核心思想**：预算感知的控制器，根据当前状态和剩余预算选择LLM及推理配置（模型、上下文长度、推理努力等）。例如，将简单的模式发现路由到小型模型，将复杂的多表连接路由到大型模型。
- **细节**：提取状态特征向量（轨迹进展、模式覆盖、错误历史等）。为每个可行配置预测奖励μ和探索奖励σ，设置分支宽度K根据配置间分歧度及预算动态调整。闭环反馈：执行后计算奖励，通过岭回归更新LCM的bandit参数。

### 2.4 轨迹导出与下游使用
- **SFT**：轨迹变为多轮训练样本，训练出TOFFEE-9B和TOFFEE-27B模型。
- **ICL**：最高质量轨迹作为工作示例，用户提问时检索相似轨迹注入提示。
