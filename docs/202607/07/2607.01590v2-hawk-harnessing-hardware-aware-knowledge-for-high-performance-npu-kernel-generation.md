## 摘要
为神经处理单元（NPU）开发高性能内核是一个关键行业瓶颈，需要开发人员手动处理隐式的硬件约束和严格的内存层次结构。虽然大语言模型提供了巨大的自动化潜力，但由于根本上缺乏硬件特定的先验知识，它们在NPU上会灾难性地失败。从类似NPU内核中简单移植代码片段可能通过编译器，但通过盲目违反底层硬件约束，会持续触发运行时崩溃和性能下降。为克服这一问题，我们引入了Hawk，一个免训练框架，通过三个核心模块利用硬件感知知识：（1）运行时知识合成模块，采用三部分可执行知识表示，将错误上下文与可执行语义固有地耦合；（2）瓶颈感知知识检索模块，实现二维检索范式，将查询投影到正交的句法空间和硬件对齐的语义空间中；（3）效果驱动的知识蒸馏模块，利用LLM驱动的语义仲裁，基于经验执行反馈通过剪枝错误和合并冗余持续蒸馏知识。在真实NPU工作负载上的广泛评估表明，Hawk将生成准确率从49.4%提升至80.0%，同时相比最先进的基线实现了高达2.2倍的执行加速。

## Abstract
Developing high-performance kernels for Neural Processing Units (NPUs) is a critical industry bottleneck, requiring developers to manually navigate implicit hardware constraints and strict memory hierarchies. While large language models offer immense automation potential, they fail catastrophically on NPUs due to a fundamental lack of hardware-specific priors. Naively transplanting code snippets from similar NPU kernels may pass the compiler, but it consistently triggers runtime crashes and performance degradation by blindly violating underlying hardware constraints. To overcome this, we introduce Hawk, a training-free framework that harnesses hardware-aware knowledge through three core modules: (1) Run-Time Knowledge Synthesis Module, which employs a Triple-Part Executable Knowledge Representation to inherently couple the error context with executable semantics; (2) Bottleneck-Aware Knowledge Retrieval Module, which implements a 2D-Retrieval paradigm to project queries into orthogonal syntactic and hardware-aligned semantic spaces; and (3) Effect-Driven Knowledge Distillation Module, which leverages LLM-driven semantic arbitration to continuously distill the knowledge by pruning errors and consolidating redundancies based on the empirical execution feedback. Extensive evaluations on real-world NPU workloads demonstrate that Hawk elevates generation accuracy from 49.4% to 80.0%, while achieving up to a 2.2x execution speedup over state-of-the-art baselines.

- **研究意义**：提出了一种无需模型训练的框架Hawk，通过显式地整合硬件感知知识，使LLM能够生成功能正确且高性能的NPU内核，避免传统微调方法在API更新时的高昂再训练成本。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- **训练自由的框架**：基于上下文学习理论，维护一个外部知识库，动态检索与当前任务相关的硬件感知知识，指导LLM避免编译和性能陷阱。
- **三大核心模块**：运行时知识合成、瓶颈感知检索、效果驱动蒸馏。

### 关键技术细节

#### 2.1 Run-Time Knowledge Synthesis Module（运行时知识合成）
- **挑战**：知识形态异构（自然语言策略、伪代码、可执行代码），直接拼接导致token爆炸或丢失句法精度。
- **方案**：**Triple-Part Executable Knowledge Representation**（三部分可执行知识表示）：
  - **元数据层**（索引）：操作符类型、数据类型、CANN版本、硬件瓶颈标签（带宽、分块等）。
  - **语义层**（推理）：自然语言解释优化为何适用及适用条件，附有性能数据。
  - **代码层**（引用）：精确的可执行Ascend C代码片段。
- **触发条件**：仅当满足以下之一时才触发知识合成：迭代难度≥2轮、文档与实际硬件行为不符、性能提升超过阈值、采用结构更优的替代方案。
- **冷启动**：通过离线三阶段管道从人类专家内核中预沉淀158条初始知识条目。

#### 2.2 Bottleneck-Aware Knowledge Retrieval Module（瓶颈感知检索）
- **挑战**：传统基于文本或功能相似度的检索无法捕捉硬件约束，相同数学操作的不同实现可能因内存布局、张量形状而需要完全不同的硬件策略。
- **方案**：**2D-Retrieval机制**（二维检索）：
  - **句法精确度**（syntactic exactness）：使用BM25算法匹配API签名、错误码等精确关键词。
  - **硬件对齐语义相似度**（hardware-aligned semantic similarity）：使用稠密嵌入（Qwen3-embedding-8B）编码查询和知识，计算余弦相似度。
  - **融合**：采用**Reciprocal Rank Fusion (RRF)** ，公式：
    \[
    S(K_i, Q) = \sum_{r \in \{syn, sem\}} \frac{1}{k + \text{rank}_r(K_i)}
    \]
    其中常数k=60。RRF将两个维度的排名转化为倒数秩，避免手动调参。
- **反馈驱动的迭代检索**：若首次检索失败，Agent根据执行反馈重构查询（诊断语义偏移 + 对比排除），重新计算相似度，迭代直到瓶颈解决。

#### 2.3 Effect-Driven Knowledge Distillation Module（效果驱动蒸馏）
- **挑战**：知识库会积累错误和冗余条目，4.4%的未验证知识就导致准确率从84%暴跌至28%。
- **方案**：
  - **经验验证与边界精炼**：运行时对应用知识导致失败的分支进行验证：若知识根本错误则永久剔除；若正确但误用则添加使用边界（如限制张量大小）。
  - **冲突仲裁**：周期性采样共享标签的知识对，若存在逻辑冲突（如一个要求PipeBarrier，另一个为最大化流水线省略），通过经验执行结果裁决：淘汰劣质或合并为条件规则。
  - **语义合并**：对功能重叠的近似条目进行语义融合：提取公共基线、整合差异为条件分支、合成唯一解释，减少冗余。

### 整体工作流程（两阶段）
- **阶段1：知识引导生成与合成**（步骤1-8）：
  1. 接收内核生成任务。
  2. 通过瓶颈感知检索从知识库获取前K条知识。
  3. Agent利用知识生成内核代码。
  4. 编译、执行，收集反馈。
  5. 若失败，迭代检索并修正查询。
  6. 成功后将新洞察转化为三部分知识格式存入知识库。
- **阶段2：知识蒸馏**（步骤9-14）：
  1. 主验证代理协调多个子代理并行验证知识条目。
  2. 根据执行反馈剔除错误、合并冗余，保持知识库高质量。

## 6. 论文的主要结论与发现

1. **LLM在NPU内核生成上的失败根本原因是缺乏硬件感知先验知识**：77.8%的错误是语法级（API幻觉/误用），20.6%是硬件级（如UB溢出）。

- **训练自由**：无需模型微调，通过外部知识库即可适应API更新，避免再训练成本。

- **瓶颈感知检索（2D-Retrieval + RRF）** ：融合句法匹配与硬件语义对齐，精准捕获根因优化策略。

- **完整的消融与可扩展性分析**：系统验证了每个模块的必要性以及框架向复杂操作符和弱模型的泛化能力。
