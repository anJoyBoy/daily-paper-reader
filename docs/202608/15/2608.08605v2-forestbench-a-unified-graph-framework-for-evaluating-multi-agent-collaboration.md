## 摘要
基于大型语言模型（LLM）的多智能体系统（MAS）正在迅速普及，但其异构的执行轨迹无法为跨方法的评估提供共同基础。仅关注结果的基准测试丢弃了协作信息，而LLM作为评判者的评估则需要额外的、依赖于模型的推理，并且可能随LLM和评分标准而变化。我们引入了一个可泛化的评估框架，将原生MAS轨迹映射到统一协作图的共享空间中，使得不同方法能够在相同的表示、参考集和指标面板下进行评估。候选图与查询特定的参考森林进行比较。每个森林都是基准提供的已验证成功图的集合：它记录了代表性MAS方法完成任务的多种方式，而非规定唯一的最优过程。我们将该框架实例化为ForestBench，从七个公开数据集中筛选出844个需要协作的查询，为每个查询预计算十个成功的、以目标为条件的参考图，并评估六个代表性的MAS框架。通过受控主干、参考构建和扰动研究，我们测试了评估的稳定性和范围。一旦基准森林构建完成，ForestBench可在几毫秒内对轨迹进行评分，无需进一步的LLM推理，为比较不同的MAS协作轨迹提供了可复用的结构基础。

## Abstract
Multi-agent systems (MAS) built on Large Language Models (LLMs) are proliferating rapidly, but their heterogeneous execution traces provide no common basis for evaluation across methods. Outcome-only benchmarks discard collaborations, whereas LLM-as-Judge evaluation requires additional, model-dependent inference and can vary with the LLM and rubric. We introduce a generalizable evaluation framework that maps native MAS traces into a shared space of unified collaboration graphs, enabling different methods to be evaluated under the same representation, reference set, and metric panel. Candidate graphs are compared with a query-specific reference forest. Each forest is a benchmark-provided collection of verified-success graphs: it records diverse ways in which representative MAS methods can complete the task, rather than prescribing a unique optimal process. Instantiating the framework as ForestBench, we filter $844$ collaboration-necessary queries from seven public datasets, precompute ten successful target-conditioned reference graphs per query, and evaluate six representative MAS frameworks. Controlled backbone, reference-construction, and perturbation studies test the stability and scope of evaluation. Once the benchmark forests are built, ForestBench scores a trace in milliseconds without further LLM inference, providing a reusable structural basis for comparing diverse MAS collaboration traces.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想

将 MAS 执行轨迹统一映射为**协作图（Collaboration Graph）**，每个候选图与一个查询特定的**参考森林（Reference Forest）**进行比较。参考森林由多条已验证成功的协作结构（参考树）组成，保留了成功协作的多样性。

### 2.2 关键技术细节

**（1）图抽象（Graph Abstraction）**

- 每个原子动作（agent action）为节点，信息传递为边：
  \[
  G(\tau) = (V, E, \phi)
  \]
- \(\phi\) 为节点标注：发出智能体、规范化角色 \(r \in R\)、动作文本内容。
- 由于每个动作都有唯一时间戳且只能消费已产生的信息，图天然为**有向无环图（DAG）**。
- 投影是有损的：丢弃框架特定的运行时状态和精确时钟交错，仅保留角色、动作和依赖关系——这正是实现跨框架可比较的关键。

**（2）参考森林（Reference Forest）**

- 每个查询 \(q\) 的参考森林定义为：
  \[
  F(q) = \{(G_k, q_k)\}_{k=1}^{K(q)}
  \]
- 每个 \(G_k\) 是已验证成功（达到正确目标答案）的参考图；
- 图在元数据层面具有“树”的意象——记录一种成功的协作成长模式；
- 森林不是唯一最优过程的枚举，而是基准提供的**参考集合**，覆盖多种协作范式。

**（3）核心指标：Forest Match**

- 逐对图相似度：

\[
\text{sim}(G, G') = \alpha\,s_{\text{node}} + \beta\,s_{\text{edge}} + \gamma\,s_{\text{topo}}
\]

默认权重 \((\alpha, \beta, \gamma) = (0.4, 0.4, 0.2)\)。

- \(s_{\text{node}}\) 和 \(s_{\text{edge}}\) 分别基于**角色多重集**和**角色类型化边指纹**的 Jaccard 相似度，对智能体重命名和独立动作置换具有不变性；
- \(s_{\text{topo}}\) 衡量图的规模匹配度（节点数和边数的比值），避免奖励冗长；
- 每个参考图带权重 \(w_k = q_k / \max_{k'} q_{k'}\)，Forest Match 为加权平均：

\[
\text{FM}(G, F(q)) = \frac{\sum_{k=1}^{K(q)} w_k\,\text{sim}(G, G_k)}{\sum_{k=1}^{K(q)} w_k}
\]

**（4）辅助指标面板**

- **Accuracy**：任务最终正确率；
- **Node Validity**：产生的动作中被下游消费的比例（反映无效工作）；
- **Mean Uptake**：下游内容在语义上使用上游内容的程度（基于嵌入余弦相似度）；
- **Content Redundancy**：归一化内容哈希的重复度；
- **Tokens**：总 token 消费；
- **Efficiency**：图并行度/活动智能体数。

所有指标均为候选图 \(G(\tau)\) 的确定性函数，**无需额外 LLM 调用**，每条轨迹毫秒级完成评分。

## 3. 实验设计：数据集、Benchmark 与对比方法

### 3.1 数据来源与筛选

- 原始查询来自七个公开数据集，覆盖四大任务类别：
  - **推理**：GPQA、MMLU、MATH-500、GSM8K
  - **代码生成**：SWE-bench-Verified
  - **工具使用**：Terminal-Bench
  - **多跳搜索**：WideSearch
- 通过**轨迹适切性流水线（TSP）**筛选，三个维度同时达标：
  - 深度 \(d(q) \ge 5\)（要求多步推理）
  - 宽度 \(w(q) \ge 0.5\)（技能多样性，规范化 Shannon 熵）
  - 可分解性 \(\delta(q) \ge 0.5\)（可划分为独立子任务）
- 最终得到 **844 个查询**（推理 55.9%、多跳 QA 23.7%、代码 15.8%、工具使用 4.6%）。

### 3.2 参考森林构建

- 每个查询使用**六种代表性 MAS 框架**作为参考生成器：
  - Multi-agent Debate、Swarm、AutoGen、MetaGPT、MAS-GPT、AFlow
  - 外加单智能体 CoT 结构锚定
- 目标答案作为条件（target-conditioned），每查询保留 **10 条验证成功的参考图**，共 8,440 条参考轨迹。

### 3.3 被评估的候选框架

同六种框架：MAS-GPT、AutoGen、MetaGPT、Swarm、AFlow、Debate。默认骨干为 DeepSeek-V4-Flash，亦使用 Claude-Sonnet-4.6、GPT-5.5、Qwen3.6-Plus 进行对比和鲁棒性测试。

### 3.4 评估协议

- 每框架×每查询运行 3 个随机种子，总计约 15,192 条轨迹；
- 候选与参考同源时采用**留一法（LOO）**，避免同框架直接对比。

## 6. 论文的主要结论与发现

1. **准确性无法区分方法，但结构信号可以**：
   - 六种框架 Accuracy 仅在 0.531~0.569 之间（跨度 0.038）；
   - Forest Match 跨度达 0.316~0.421，揭示了明显的结构差异。

2. **森林比单一参考树更有效**：
   - 跨骨干排序完全一致，留出参考生成器后 Top-3 保持 6/7，开放条件构建后 top-3 仍保持；
   - 验证了“多种成功协作结构”而非“单一最优过程”的合理性和稳定性。

3. **框架 vs. 骨干效应可分离**：
   - 框架结构先验跨骨干表现稳定（交叉骨干距离 0.171 < 骨干内距离 0.181）；
   - 编排增益取决于骨干：DeepSeek-V4 上平均增益 −0.002，GPT-5.5 上 −0.039，Claude-S4.6 上 −0.069，说明强骨干下增加智能体并不必然带来收益。

4. **结构指标暴露隐性差异**：
   - Debate 准确率最高但 Forest Match 最低，Best Similarity 仅 0.284；
   - AFlow 内容冗余度为 0.167，约为次高者的 3 倍；
   - Swarm 是唯一 Node Validity < 1 的框架。

5. **失败模式分为结构性和内容性两类**：
   - Debate 和 MAS-GPT 的所有失败轨迹均为结构性失败（100%）；
   - AutoGen 和 MetaGPT 分别有 33.3% 和 23.9% 的轨迹结构合理但内容出错。

6. **评估成本极低**：构建完成后评分无需 LLM 推理，比 LLM-as-Judge 快约 2,900 倍。

## 7. 优点（方法/实验亮点）

1. **统一图表示**：将异质轨迹映射为统一 DAG，在不损失角色、依赖与信息流的前提下实现跨框架比较，设计优雅且可操作性强。
2. **参考森林而非单参考树**：充分尊重成功协作的多样性，避免结构性偏向单一范式，是一个非常合理的权衡设计。
3. **零推理评分的可复用性**：森林构建一次、永久复用，评估阶段无需任何 LLM 调用，大幅降低计算与成本门槛。
4. **全面且诚实的鲁棒性测试**：从骨干、生成器、条件构建、扰动、权重、阈值、数据源七个维度验证稳定性，覆盖面广。
5. **诊断性指标面板**：除综合分数外还提供 Node Validity、Uptake、Redundancy 等辅助指标，能区分不同失败机制，实用性高。
6. **对结论边界的把握诚实**：反复强调“结构相似性≠绝对质量”“参考集非唯一最优”，避免过度声明因果性。

## 8. 不足与局限

1. **参考森林覆盖有限**：参考图仅从六个预设范式加一个 CoT 锚生成，无法覆盖尚未出现或不在集合内的协作模式；新生范式可能因结构差异大而得分偏低，存在范式偏向风险。
2. **角色规范化依赖人工别名表**：跨框架角色映射通过 per-framework alias table 完成，若框架角色词汇差异大，容易产生不一致映射。
3. **辅助指标依赖语义嵌入**：Mean Uptake 和 Content Redundancy 依赖嵌入模型和阈值选择（\(\theta_u\)），文中未详细讨论嵌入模型的敏感性和选择依据。
4. **硬件信息缺失**：全文未报告 GPU 类型、数量、训练/推理时长等具体算力配置，影响实验的可复现性细节。
