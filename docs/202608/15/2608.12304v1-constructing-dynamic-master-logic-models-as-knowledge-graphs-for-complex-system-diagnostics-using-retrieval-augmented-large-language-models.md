## 摘要
动态主逻辑（DML）提供了一种分层框架，通过将功能目标与底层结构元素相关联来表示系统行为。然而，DML构建通常依赖专家对技术文档的解读，限制了其在复杂系统中的可扩展性。本研究提出了一种框架，利用检索增强生成和大语言模型作为使能工具，从系统描述中自动构建DML模型，并将其表示为知识图谱（KG-DML）。在先前针对小规模系统研究的基础上，该框架将自动化KG-DML构建与评估扩展至规模更大、更复杂的系统。模型构建通过定向检索贯穿DML层级结构，同时保留功能依赖关系与显式逻辑关系。所得到的KG-DML支持诊断推理、安全评估、向上故障传播及向下依赖追踪。一种多级验证方法评估了各层级的精确率与召回率、逻辑门一致性以及整体结构完整性。将所提方法应用于一座退役沸水反应堆的低压冷却剂注入系统，验证了重复运行下重建结果的一致性。结果表明，自动化KG-DML构建可将技术文档转化为可用于诊断和可靠性分析的可执行功能模型。

## Abstract
Dynamic Master Logic (DML) provides a hierarchical framework for representing system behavior by linking functional objectives to underlying structural elements. However, DML construction typically relies on expert interpretation of technical documentation, limiting scalability for complex systems. This study presents a framework for automated construction of DML models from system descriptions and their representation as Knowledge Graphs (KG-DML), using Retrieval-Augmented Generation and Large Language Models as enabling tools. Building on prior work with small-scale systems, the framework extends automated KG-DML construction and evaluation to substantially larger and more complex systems. Model construction proceeds across the DML hierarchy using targeted retrieval while preserving functional dependencies and explicit logical relationships. The resulting KG-DML supports diagnostic reasoning, safety assessment, upward failure propagation, and downward dependency tracing. A multi-level validation methodology evaluates layer-specific precision and recall, logical gate consistency, and overall structural integrity. Application to the Low-Pressure Coolant Injection system of a decommissioned Boiling Water Reactor demonstrates consistent reconstruction across repeated runs. The results show that automated KG-DML construction can transform technical documentation into executable functional models for diagnostic and reliability analysis.

### 2. 论文提出的方法论（核心思想、关键技术细节、公式与流程）

#### 2.1 核心思想
- 将模型构建从"一次性全图生成"改为一套**受约束的结构化提取**流程，通过预定义模式（schema）、有界作用域和结构化生成，限制 LLM 的自由度，降低幻觉和输出不一致的风险。
- 采用 **分层逐层构建**：按 DML 层级（目标→功能→子功能→组件→成功条件）顺序生成，每一层以前一层已确认的父节点作为检索和提取条件。
- RAG 机制仅在每一层检索与该层语义定义和既有父节点相关的文档片段，从而支持从大规模文档中提取信息，避免上下文窗口限制。

#### 2.2 关键技术细节

**Stage 1：文档预处理与嵌入**
- 标准化组件标识符、扩充缩写、解析指代歧义，以提升检索可靠性。
- 段落式分块（每块 ≤1500 字符，相邻块重叠 150 字符），使用 `text-embedding-3-small` 嵌入并存入向量数据库。

**Stage 2：逐层模型构建**
- 维护一个主 JSON 作为中间模型表示，记录已确认的节点与关系。
- 每一层处理时，构建检索查询，查询由"该层的语义定义 + 父节点"共同构成。
- 使用余弦相似度检索 top-K（K=10）相关文档块作为证据，提供给 LLM。
- LLM（GPT-4o，温度参数设为 0）按预定义 JSON 模式生成候选元素及逻辑关系，经过结构验证后并入主 JSON。

**Stage 3：知识图谱合成与导出**
- 将主 JSON 通过算法（Algorithm 1）转换为 Neo4j 的 Cypher 查询语句。
- 支持嵌套布尔逻辑门（AND/OR），以中间门节点表示，递归处理子门以保真多级逻辑结构。

**核心公式（Eq. 1——余弦相似度）**

cos(q, dᵢ) = q·dᵢ / (||q|| ||dᵢ||)

其中 q 为检索查询嵌入，dᵢ 为第 i 个文档分块嵌入，用于计算相似度并挑选支持证据。

**核心公式（Eq. 2——完整性分数）**

IntegrityScore = 100 × [Σ(wₗ × Fₗ) / Σwₗ] × exp(−E_structural / ((N_nodes + N_links) × S))

其中 Fₗ 是第 l 层的 F2 分数，wₗ 为层级权重，E_structural 为加权结构惩罚（缺失节点、缺失链接、门不匹配、孤立节点），S 为惩罚缩放因子。

#### 2.3 模型交互层
- **向上传播**：从组件/成功条件层向上传播成功概率，支持嵌套布尔门结构，处理多故障场景。
- **向下传播**：从查询节点向下枚举最小成功路径集，遵循布尔逻辑（AND 组合 / OR 替代路径）；对冗余相同组件，以定性注释形式提示共因失效（CCF）风险。
- **图增强检索（Graph-RAG）**：LLM 生成 Cypher 查询，图数据库执行结构检索并返回子图，LLM 仅负责格式化回应。
