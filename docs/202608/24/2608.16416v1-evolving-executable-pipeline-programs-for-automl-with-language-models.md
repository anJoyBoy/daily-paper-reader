## 摘要
自动化机器学习（AutoML）系统在预先指定的预处理算子、学习器和超参数空间内搜索流水线：它们可以选择和调整已知组件，但无法在该空间之外生成结构。我们提出LACE，一个AutoML框架，它转而搜索完整的可执行流水线程序：一个演化循环维护一个由scikit-learn兼容的Python类组成的种群，并由大型语言模型充当变异算子。据我们所知，LACE是首个以这种方式形式化通用表格流水线AutoML的框架，在标准化OpenML任务上、在泄漏受控的协议下进行评估，该协议不向生成器提供数据集身份。由于每个候选者都是普通Python代码，返回的流水线及其产生该流水线的搜索过程可以直接检查和编辑，而不仅仅是通过框架的模型对象。在68个OpenML分类任务上，使用GPT-5.4-mini的LACE显著优于auto-sklearn、H2O和固定XGBoost基线，与所评估的最强基于搜索的系统AutoGluon相比无显著差异，同时覆盖了完整的基准。较新的表格基础模型在它们支持的任务子集上更准确，但应用的是固定的预训练预测器，而不是返回可编辑的任务特定程序。因此，LACE的贡献不在于原始准确率，而在于由代码定义的搜索空间：完整的覆盖率、从业者可以直接复用的流水线，以及通过编辑提示而不是框架来扩展组件集的能力。

## Abstract
Automated machine learning (AutoML) systems search for pipelines within a space of preprocessing operators, learners, and hyper-parameters specified in advance: they can select and tune known components, but cannot produce structure outside that space. We present LACE, an AutoML framework that instead searches over complete executable pipeline programs: an evolutionary loop maintains a population of scikit-learn-compatible Python classes, and a large language model acts as the variation operator. To our knowledge, LACE is the first to formulate general tabular pipeline AutoML this way, evaluated on standardized OpenML tasks under a leakage-controlled protocol that withholds dataset identity from the generator. Because every candidate is ordinary Python, the returned pipeline and the search that produced it can be inspected and edited directly, rather than only through a framework's model objects. On 68 OpenML classification tasks, LACE with GPT-5.4-mini significantly outperforms auto-sklearn, H2O, and a fixed XGBoost baseline, with no detectable difference against AutoGluon, the strongest search-based system evaluated, while covering the full benchmark. Newer tabular foundation models are more accurate on the subset of tasks they support, but apply a fixed pretrained predictor rather than returning an editable task-specific program. LACE's contribution is therefore not raw accuracy but a search space defined by code: complete coverage, pipelines practitioners can reuse directly, and a component set extended by editing the prompt rather than the framework.

### 2.1 核心思想
- 将AutoML形式化为**在可执行程序空间P中的搜索**，候选程序实现一个固定接口：`__init__(X, y, ...)`拟合一次模型，`__call__(X)`返回预测结果。
- 与传统AutoML不同（P是预定义可枚举空间），此处P由生成器在接口和包约束下能产生的程序隐式定义。

### 2.2 问题形式化

- 每个官方训练折进一步划分为内训练集 \( D_{tr} \) 和内验证集 \( D_{val} \)。
- 适应度函数为：

\[
f(p) = \frac{1}{K} \sum_{k=1}^{K} m(p; D^{(k)}_{tr}, D^{(k)}_{val})
\]

- 搜索只使用内验证分数；官方测试折在搜索结束后用于最终评估，全程不参与搜索。

### 2.3 信息边界（泄漏控制）
- 生成器（LLM）仅接收**粗略任务摘要**：任务类型、样本数（千位取整）、布尔/整数/实值特征数量。数据集名称、任务ID、特征名、目标语义、类别分布和评估指标均不提供。
- 评估器拥有完整任务访问权限，用于执行候选程序并返回分数或错误信息。

### 2.4 进化优化流程
- 采用**(μ+λ)进化策略**，μ=4个父代，λ=12个子代，候选预算B=100（含无效和超时候选）。
- 初始种群由LLM根据任务摘要和接口约束生成4个候选。
- 每个子代通过：均匀随机选择父代 → 提供父代码、评估反馈、种群摘要和一个随机变异指令 → LLM生成新程序。
- 三个变异指令：更换模型族、优化预处理、增删集成成员。
- 精英截断选择：保留μ+λ中最好的μ个。
- 搜索结束返回最优候选，在官方测试折上重新拟合并评估一次。

### 2.5 候选评估与反馈
- 候选在隔离子进程中运行，有墙钟超时（重任务4小时，其他1小时）。
- 成功返回内验证分数；失败返回最差适应度+首个错误及源码行号。
- 预处理器在评估前对数据做分裂安全的序数编码、布尔转换和缺失值填充。

### 2.6 提示词约束
- 仅允许scikit-learn、NumPy、SciPy、pandas。
- 单个估计器或至多3个学习器的简单集成；单个共享预处理阶段；禁止内部交叉验证、模型选择和超参数搜索（通过构造器参数暴露可调值）。
- 这些约束是提示性而非强制性的，论文在事后通过静态审计验证合规性。

## 3. 实验设计

### 3.1 基准与数据集
- **全部68个OpenML分类任务**（amlb-classification-all套件），样本量从100到4,898,431，特征数从4到10,000，覆盖小数据到大规模高维场景。
- 评估协议：OpenML预定义的1次重复×10折，67个任务用accuracy，1个任务（360114）用ROC-AUC。

### 3.2 对比方法
- **经典AutoML系统**：AutoGluon-Tabular 1.4.0、auto-sklearn 0.15.0、H2O AutoML 3.46.0.10。
- **表格基础模型**：TabPFN v2.5、TabPFN v3、TabICL 2.1.1。
- **固定基线**：XGBoost 3.2.0（固定参数、无HPO）。
- **LACE变体**：三种LLM骨干——GPT-5.4-mini、DeepSeek-V4-Flash、Qwen3-Coder-Next（4-bit量化本地部署）。

### 3.3 时间预算控制
- 每个基线获得与对应LACE任务重复相同的墙钟时间预算。
- 搜索型AutoML基线限制使用非神经网络经典学习器；TabPFN/TabICL在自己的环境中评估。

## 4. 资源与算力
- **论文未明确说明GPU型号与数量**。实验在共享异构计算集群上运行，未做硬件归一化。
- 全部计算量：102,000次计划候选评估（68任务×5重复×3骨干×100候选），每次候选有1–4小时的墙钟上限。
- 单任务单重复的LACE运行时长从约0.7小时到241小时不等；最重的任务（如360112、189355）超过228小时。
- 作者明确指出这是"共同基础设施下的对比"，而非严格计算平价基准，并提到异构集群妨碍与先前工作的严格运行时比较。

## 5. 实验数量与充分性

### 5.1 实验数量
- 主实验：68任务×5重复×3骨干 = 1,020次完整运行（实际记录101,959条候选记录）。
- 消融实验：配置消融（crossover、后代数、父选择、变异指令）在3个开发任务上；骨干筛选在3个任务上比较7个LLM。
- 基础模型消融：5个任务上对比默认/被动/显式条件，2种骨干×2种TabPFN版本。
- 最终流水线审计：1,020个最终程序全量静态分析+人工复核。

### 5.2 充分性与公平性
- **充分之处**：5次重复覆盖随机性；统一的OpenML预定义划分保证可比性；时间匹配预算控制计算量差异；多种统计检验（Wilcoxon配对符号秩+Holm校正）支撑结论；泄漏控制协议严谨。
- **不足与不公风险**：
  - 仅覆盖单一基准套件（表格分类），未涉回归任务。
  - 异构集群不支持严格计算平价比较。
  - 开发/筛选任务（190146、359970、359974）包含在主基准中，可能轻微高估特定配置的有效性。
  - 基础模型消融仅5个任务，无法做显著性检验。
  - 审计是目标性静态分析而非完备性证明。

## 6. 主要结论与发现

- **LACE(GPT-5.4-mini)在45个共同任务上均秩4.71**，与AutoGluon无显著差异（33胜35负，pHolm=0.66），显著优于auto-sklearn、XGBoost和H2O（pHolm<0.01）。
- **覆盖全基准68/68任务**：所有LACE变体、AutoGluon、auto-sklearn、XGBoost、H2O全部覆盖；而TabPFN v2.5仅45/68、TabPFN v3为62/68、TabICL为67/68。失败感知分析中LACE(GPT-5.4-mini)秩4.50，与AutoGluon（4.59）基本持平。
- **TabPFN v3和TabICL在其支持的任务上显著优于LACE**，但中位差距很小（0.34和0.26个百分点）；TabICL平均差异甚至略逊于LACE(+0.22)。
- **演化搜索显著改善零样本流水线**：首候选有效性从37.6%（Qwen3）到79.7%（GPT-5.4-mini），最终全部有效；在193个骨干-任务单元中190个在官方测试中改进，中位增益2.99个百分点；GPT-5.4-mini全部66个单元改进，中位增益4.53点。
- **生成的流水线结构多样**：70,998个有效候选中65,298个（92%）具有唯一结构签名；73.3%的最终流水线组合了至少两个学习器；69.4%使用梯度提升，52.5%使用森林/极端随机树。
- **8.7%的最终流水线（89/1020）直接以NumPy/Python手写预测组合逻辑**，展示了源代码级别的可检查性和可编辑性。
- **搜索空间受提示词中声明的组件影响而非包可用性**：未提及的已安装TabPFN从未被使用；显式声明后74.5%（DeepSeek）和42.0%（GPT-5.4-mini）的候选开始使用。
- **合规审计**：22个确认违规（5个外部折构造、13个四学习器集成、4个预测时拟合），GPT-5.4-mini仅2个，排除后所有统计结论不变。

## 7. 优点

- **搜索表示新颖且突破性强**：首次将通用表格AutoML形式化为LLM驱动的可执行程序进化，搜索空间由代码定义而非固定语法。
- **泄漏控制严谨**：生成器仅接收粗略摘要，不暴露数据集身份，降低基准污染风险；官方测试折在整个搜索过程中严格隔离。
- **评估协议标准化**：使用OpenML预定义划分、任务特定指标、五重复；每个基线获得相同时间预算。
- **输出可检查、可编辑、可复用**：返回的流水线是普通Python代码，可直接在框架外修改使用，优于黑盒模型对象和固定预训练预测器。
- **审计意识强**：对生成程序的约束进行静态审计和人工复核，而非假定提示词被遵守，并检验了违规排除对结论的敏感性。
- **消融与筛选详尽**：对配置项（crossover、后代数、父选择、变异指令）、骨干模型进行了系统筛选；基础模型消融设计巧妙，区分了"环境可用"与"提示词声明"的差异。
- **诚实呈现局限**：明确指出单一基准套件、异构基础设施、审计不能证明无违例等边界。

## 8. 不足与局限

- **基准覆盖单一**：仅68个分类任务，未包含回归、多标签或时间序列任务；结论在更广泛AutoML场景的泛化性未验证。
- **计算成本极高**：102,000次候选评估，单候选最长4小时，最重任务单次重复超240小时，实际部署成本门槛高。
- **LLM预训练污染风险只能降低无法消除**：尽管不提供数据集名称，公共基准仍可能出现在预训练数据中，存在推理层面的泄漏可能。
- **无严格计算平价**：异构集群与时间匹配预算只是"共同基础设施下的对比"，非硬件归一化的严格比较。
- **生成器默认超参数未做外部调优**：所有评分来自LLM选择默认值，已暴露的超参数空间与外部调优器的组合效果未测量。
- **统计功效有限**：基础模型消融仅5个任务，无法做显著性检验；开发/筛选任务与主基准重叠，少量消融结论证据有限。
- **审计非完备**：静态分析只针对声明的检测器，不能排除其他未发现的非合规形式；22个违规确认分布在较弱骨干中较多（Qwen3占13个）。
- **依赖商用API模型**：最强结果依赖GPT-5.4-mini，存在可访问性和成本问题；本地模型（Qwen3）有效性明显较低（46.8%候选有效）。
- **搜索效率有提升空间**：中位运行在候选50处已完成91%最终改进，固定100候选预算存在浪费，但自适应/早停预算尚未验证。
