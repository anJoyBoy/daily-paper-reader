## 摘要
实际的分子逆向设计很少是单次生成问题；它通常采取闭环候选池扩充的形式，在有限的oracle预算下，目标是提高生成的分子中符合期望属性特征的比例。贝叶斯优化（BO）为此类场景提供了自然框架，然而标准高斯过程代理通常在压缩的连续嵌入中运行，这丢弃了化学家在决定下一步探索方向时自然使用的子结构和参考相似性信号。我们提出了\method，这是一个闭环框架，其中代理而非生成器被视为设计选择的焦点，并使用一个冻结的大语言模型实例化，该模型直接以任务指令、SMILES级优化历史和oracle反馈的原始文本形式进行推理。在每次迭代中，代理返回一个结构化的决策信号，该信号在探索与利用原则下选择信息丰富的参考分子，并可附带简洁的指导语句。该信号被转换为下一轮冻结分子生成器的条件文本，从而生成可检查的自然语言优化轨迹。在MolQA药物和材料设计任务上的实验表明，\method优于单次提示，与基于GP的BO基线相当或更强，并揭示了一个领域相关的接口：仅参考转移对二元药物靶标效果最佳，而添加简洁的代理摘要对连续材料更有利。

## Abstract
Practical molecular inverse design is rarely a one-shot generation problem; it often takes the form of closed-loop candidate-pool enrichment, where under a limited oracle budget the goal is to \emph{increase the fraction of generated molecules that match a desired property profile}. Bayesian optimization (BO) offers a natural framework for this setting, yet standard Gaussian-process surrogates typically operate in compressed continuous embeddings, which discard the substructural and reference-similarity signals that chemists naturally use to decide where to look next. We propose \textbf{\method}, a closed-loop framework in which the surrogate, rather than the generator, is treated as the locus of design choice, and instantiate it with a frozen large language model that reasons directly over the task instruction, SMILES-level optimization history, and oracle feedback in their native textual form. At each iteration, the surrogate returns a structured decision signal that selects informative reference molecules under an exploration and exploitation principle, optionally with a concise guidance sentence. This signal is converted into next-round conditioning text for a frozen molecular generator, yielding an inspectable optimization trace in natural language. Experiments on MolQA drug and material design tasks show that \method improves over one-shot prompting, is competitive with or stronger than GP-based BO baselines, and reveals a domain-dependent interface: reference-only transfer works best for binary drug targets, while adding a concise surrogate summary is more beneficial for continuous material

## 2. 论文提出的方法论

### 核心思想

- 将分子逆向设计建模为闭环候选池扩充问题：生成器产生分子 → oracle 打分 → 代理读取历史 → 输出下一轮条件信号 → 再次生成。
- 用冻结 LLM 替代 GP 作为代理（surrogate），直接在原始文本上推理，而不是在压缩向量中拟合代理模型。
- 代理输出结构化信号 `u_t = (r_t, R_t, g_t)`，其中 `r_t` 为轨迹分析文本，`R_t` 为从历史中选出的 top-k 参考分子，`g_t` 为可选的单句指导摘要。

### 关键技术细节

- **任务对齐分数**：
  - 药物任务（二元分类）：若目标标签为 1，分数等于 oracle 输出的阳性概率；若目标标签为 0，分数为 1 − 概率。
  - 材料任务（连续回归）：分数定义为 `exp(-|log10(1 + ŷ) − log10(1 + y*)| / σ)`，在 log 空间中度量预测与目标的偏差。
- **LLM 语义代理**：
  - 输入包括原始指令、任务 oracle 类型、目标值、当前历史 `D_t−1`、当前轮次以及 BO 式选择原则。
  - 输出遵循严格格式：`ANALYSIS`、`SELECTED`，可选 `GUIDE_FOCUS`。
  - 通过提示词中的“探索 vs. 利用”原则，要求代理不要只选最高分分子，而是兼顾高分结构（利用）与多样性/异常结构（探索）。
- **GP-BO 基线**：
  - 将 Llamole 生成的 768 维 DiT conditioning embedding 用 PCA 压缩到 30 维。
  - 使用 Matérn-5/2 核（ARD）拟合对齐分数，LogEI 作为采集函数。
  - 将 GP 提议 embedding 附近的 top-k 历史分子作为参考注入下一轮 prompt。
- **闭环流程**：
  - 第 0 轮为 warm start，仅使用原始指令生成 30 个分子；
  - 第 1 轮起，每轮由代理生成参考集（+指导句），构造下一轮 prompt，生成 10 个新分子；
  - 历史不断累积，总优化轮数 T = 5。
- **领域相关接口**：
  - 药物任务使用 top-k 仅参考模板；
  - 材料任务使用 top-k + 指导句模板；
  - 消融实验表明该选择不是随意的，而是与 oracle 类型相关的。

## 6. 论文的主要结论与发现

- **闭环迭代优于一次生成**：随机参考、GP-BO 和 BoMolLLM 均普遍超过 Llamole-OneShot，说明引入 oracle 反馈本身就能带来提升。
- **BoMolLLM 与 GP-BO 相当或更强**：在几乎所有设置下匹配或超越 GP-BO；在 Mistral 和 Llama backbone 的药物任务三个靶标上均取得最优 AUC。
- **跨 backbone 可迁移**：同一 LLM 代理机制无需修改即可用于 Qwen、Mistral、Llama 三种生成器。
- **指导句的价值取决于 oracle 类型**：对连续目标的材料任务，增加单句代理摘要普遍有帮助；对二元药物任务则无一致增益。
- **代理展现出 BO 式行为**：随着轮次增加，代理所选参考的历史分数分位数上升（利用增强），与当前 top-history 集合的 Tanimoto 距离下降（探索减弱），呈现“先探索、后利用”的过渡。
- **搜索预算更有效**：t-SNE 可视化表明 BoMolLLM 生成的高分分子占比更高，且没有坍缩到单一簇。
- **更多轮数带来更好效果**：在 BACE 和 O₂ 上，从 3 轮增加到 11 轮，BoMolLLM 持续优于 one-shot，且性能持续提升。

## 7. 优点

- **视角新颖**：明确将代理作为闭环优化的“设计选择焦点”，而不是替换或重训生成器，为 LLM 与 BO 的结合提供了清晰定位。
- **保留化学语义信号**：直接在 SMILES、分数、文本历史上推理，避免了 GP 在压缩嵌入中丢失子结构和参考相似性信息的问题。
- **可解释性强**：代理输出自然语言分析和短指导句，使优化轨迹可检查、可审计；这是数值型 GP 代理无法提供的。
- **框架可替换代理**：GP 和 LLM 代理能在同一闭环框架下直接对比，隔离了“代理”这一变量。
- **工程成本低**：生成器与代理均为冻结模型，不需要为每个目标重新训练生成器。
- **实验设计较全面**：跨 3 个 backbone、6 个任务，包含消融、机制分析、收敛分析、可视化与案例研究，能支撑主要结论。
- **诚实讨论局限**：在 Limitations 中明确承认了 oracle 保真度、LLM 非校准性、依赖 prompt 等局限。

## 8. 不足与局限

- **缺乏真实实验验证**：oracle 是随机森林代理模型，不是真实实验、对接、合成性或下游多属性筛选；结果只能说明 oracle-guided 候选池扩充有效，不能直接说明分子在真实世界中有价值。
- **LLM 代理缺乏概率校准与理论保证**：它不产生显式后验不确定性，也没有经典 BO 的遗憾界或收敛性保证。
- **行为依赖性强**：代理行为可能依赖 prompt 措辞、底层 LLM 能力、历史中分子分布以及参考数量 k 等选择，论文对这些因素的敏感性分析较少。
- **最优接口需要领域调优**：药物与材料需要不同 prompt 接口，说明方法并非完全即插即用。
-

- **计算与规模开销**：尽管生成器与代理均为冻结模型，但每一轮都需要将不断增长的历史文本输入 LLM，并执行多次生成与打分；随着轮次增加，prompt 变长、token 成本上升，对高频 oracle 调用或大规模筛选场景可能成为实际瓶颈。
- **未显式建模 oracle 不确定性**：框架将 oracle 分数视为真实标签，未引入对 oracle 噪声或置信度的刻画；当 oracle 为低质量模型或存在对抗性偏差时，代理的参考选择可能被误导。
- **评价指标侧重均值**：主实验仅报告轨迹级平均 AUC 或 MAE(log10)，未提供方差、最坏情况或分布尾部信息，无法反映生成池中极端失败样本的影响。
- **外部基线对比不够完全公平**：外部 LLM 一次提示基线未使用图约束解码，导致生成无效率显著偏高，只能作为一种“无领域约束”的下限参考，不能与完整框架直接等价比较。
- **失败模式分析不足**：论文未深入讨论 BoMolLLM 在哪些具体任务或 backbone 下未能超越 GP-BO，也没有说明这些失败是由生成器能力、历史积累还是代理选择导致的。

## 9. 整体总结与展望

- 总体来看，BoMolLLM 的核心贡献在于将“代理”重新定位为闭环分子逆向设计中的关键设计对象：用冻结 LLM 在原始文本历史上进行语义推理，替代在压缩嵌入空间中拟合的 GP 代理。这种做法既保持了贝叶斯优化式的探索-利用平衡，又提供了可审计、可解释的决策轨迹。
- 实验结果说明，在候选池扩充这一与实际分子设计更贴近的设定下，LLM 语义代理可以作为 GP-BO 的轻量替代方案，并具有跨 backbone、跨任务的一定泛化能力。
- 未来的工作有待解决其理论保证缺失、oracle 真实性、提示鲁棒性、以及多目标/多约束场景下的扩展问题；同时，将 LLM 代理与更高效的检索或结构约束生成器结合，可能进一步提升其实用性。
