## 摘要
约束满足问题的算法选择需要提取能够捕捉问题结构的特征。手动设计特征提取器需要深厚的领域专业知识，并且当新的问题类别出现时很快成为瓶颈。我们提出一种自动化方法，使用大语言模型（LLMs）在智能体的检查-修复-验证循环中合成可执行的Python脚本，这些脚本作为可解释的、针对特定问题的特征提取器。给定一个高级MiniZinc模型和一个实例，LLM智能体生成代码来构建类型化图表示，并计算诸如图密度、变量聚类和约束紧密度等结构属性。我们在三个组合问题（车辆路径规划、汽车排序、定长纠错码）上评估了我们的方法，使用了五个最先进的求解器组合。合成的特征提取器产生的算法选择器在测试集准确率上持续优于专家精心设计的mzn2feat特征（在FLECC上最高提升8.3个百分点）以及基于Transformer的最佳trans2feat变体。同时，合成的特征提取器保持可检查性。

## Abstract
Algorithm selection for constraint satisfaction problems requires extracting features that capture problem structure. Manually designing feature extractors demands deep domain expertise and quickly becomes a bottleneck when new problem classes appear. We present an automated approach that uses Large Language Models (LLMs) in an agentic check--fix--verify loop to synthesize executable Python scripts that act as interpretable, problem-specific feature extractors. Given a high-level MiniZinc model and an instance, the LLM agent generates code that constructs a typed graph representation and computes structural properties such as graph density, variable clustering, and constraint tightness. We evaluate our approach on three combinatorial problems (vehicle routing, car sequencing, fixed-length error-correcting codes) with a portfolio of five state-of-the-art solvers. The synthesized extractors yield algorithm selectors that consistently outperform both expert-curated mzn2feat features (up to $8.3$ percentage points (pp) test-set accuracy on FLECC) and the best transformer-based trans2feat variants. In the meanwhile, the synthesized feature extractors remain inspectable.

## 8. 局限性

- **对 LLM 后端能力的强依赖**：10 次合成实验中，商用强模型（o4-mini、Claude Sonnet 4）成功率为 10/10，而弱开源模型（Llama 3.3-8b-instruct）在四步协议下全部失败；表明该方法目前高度依赖前沿模型的服务可用性与成本，若脱离商用 API 则复现门槛陡增。
- **特征维度固定的次优性**：50 维是预实验中人工选定的折中值，但不同问题族的最优维度未必一致；论文虽给出"约 10 个特征后 mzn2feat 停滞、LLM2feat 持续提升"的曲线，却未系统搜索每个问题的最优维度。
- **验证范围有限**：仅考察三个问题族、五台求解器，且 VRP 无法与 trans2feat 直接对比（无公开特征）；结论向更大规模实例、更多求解器组合与更多问题类型的推广尚缺乏证据。
- **失败运行的乐观偏差**：实验中对 AutoSK 超时或退化为常数模型的运行做了排除，虽然透明披露，但被排除运行多为困难配置，保留后 LLM2feat 的优势幅度可能收窄。
- **可解释性的天花板**：虽然生成代码是"灰盒"，但特征名称和计算逻辑由 LLM 自由发挥，个别维度可能出现语义重复、数值尺度不稳定或对数据模式过拟合的现象，仍需要人工事后校验。
- **一次合成、一次使用的固定成本假设**：若问题族内实例分布发生漂移，当前设计没有在线更新或再校准机制，特征提取器可能随数据演化而失效。

## 9. 总结与展望

本文以"自动化特征工程"为切入点，证明了 LLM 智能体能够在受控的检查–修复–验证循环中，以约 0.27 美元/个的极低代价合成出可执行、可解释、可审计的 Python 特征提取器；该提取器在三个组合优化问题族上全面超越专家手工特征（mzn2feat）与神经嵌入特征（trans2feat），在准确率、特征利用率、特征多样性三个维度上均取得一致增益，并将求解时间收益向 VBS 上限推进约 30%。

展望方面，论文为后续研究留下了若干自然延伸方向：

- **跨问题泛化**：将合成协议扩展到更多 MiniZinc Challenge 问题族、随机规划与多目标优化，检验方法的规模敏感性；
- **交互式特征精炼**：将特征重要度分析与相关性诊断反馈给 LLM，形成"合成→评估→反馈→重合成"的闭环，替代当前一次性合成；
- **混合特征空间**：将 LLM 生成的可解释特征与神经嵌入特征拼接，探索灰盒与黑盒特征的互补增益；
- **开源模型适配**：通过更强的开源模型或知识蒸馏，降低对商用 API 的依赖，提升方法普惠性；
- **在线自适应**：为特征提取器引入实例分布漂移检测与增量再合成机制，增强长期部署中的鲁棒性。

总体而言，LLM2feat 的工作具有清晰的定位与扎实的实验支撑，其核心贡献不在于提出一种全新的选择器算法，而在于为算法选择管线中最昂贵、最依赖人工的一环——特征提取器设计——提供了一条自动化、低成本、可验证的替代路径，有望成为从"手工 AS 管线"走向"全自动 AS 管线"的关键垫脚石。
