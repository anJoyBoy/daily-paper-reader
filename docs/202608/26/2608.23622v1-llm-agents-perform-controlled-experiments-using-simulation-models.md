## 摘要
大型语言模型（LLMs）在推理、规划和工具使用方面表现出强大的能力，但许多科学和工程任务需要的不仅仅是合理的文本和代码生成。它们还需要理解系统对干预的响应，而这在实践中依赖于受控实验。在这项工作中，我们提出了一个多代理框架，使LLM代理能够使用科学仿真模型进行受控实验，以用于制药工艺设计。给定用户查询和基线配置，系统构建结构化的任务表示，设计实验，执行比较仿真，解释结果，并为工艺参数优化综合基于证据的建议。通过将语言模型与高保真仿真模型在交互式代理框架中耦合，所提出的系统支持通过干预、比较和观察进行推理。因此，它比仅依赖语言推理产生更具体和可操作的输出。在工业应用环境中，这一优势体现在更高的输出特异性以及用户评分的正确性和有用性提高上。消融研究和可视化案例分析进一步证明了仿真集成实验推理的有效性和实际实用性。

## Abstract
Large language models (LLMs) have shown strong capabilities in reasoning, planning, and tool use, but many scientific and engineering tasks require more than plausible text and code generation. They require understanding how a system responds to intervention, which in practice depends on controlled experimentation. In this work, we propose a multi-agent framework that enables LLM agents to conduct controlled experiments with scientific simulation models for pharmaceutical process design. Given a user query and a baseline configuration, the system constructs a structured task representation, designs experiments, executes comparative simulation, interprets the resulting outcomes, and synthesizes evidence-based recommendations for process parameter optimization. By coupling language models with high-fidelity simulation models in an interactive agent framework, the proposed system supports reasoning through intervention, comparison, and observation. As a result, it produces more specific and actionable outputs than language-only reasoning. In an industrial application setting, this advantage is reflected in higher output specificity as well as improved user-rated correctness and helpfulness. Ablation studies and visualized case analyses further demonstrate the effectiveness and practical utility of simulation-integrated experimental reasoning.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：大规模语言模型（LLM）虽然在多步推理、规划和工具使用方面表现出色，但许多科学与工程任务需要的不仅是"生成合理文本"，而是**理解系统对干预的响应**——这在实践中依赖受控实验（controlled experimentation），而非单纯的语言生成。
- **现有方法的缺陷**：当前基于 LLM 的系统即使配备外部工具，也往往只用于信息检索或孤立函数执行，而非开展结构化的"变量干预—对照比较"实验。其输出常常是"建议性"（suggestive）而非"证据性"（evidential），缺乏可验证性。
- **关键动机**：在制药过程设计等工业场景中，大量知识蕴含于能刻画系统动态的高保真仿真模型中。作者主张将仿真视为**可检验假设的实验环境**而非被动辅助工具，让 LLM 通过"假设→干预→观察→分析→报告"的科学探究逻辑进行推理。
- **整体含义**：该工作探索了"语言模型+仿真模型"的耦合范式，使 LLM 的推理能够基于受控实验证据，从而产生更具体、更可操作、更具决策支持价值的输出。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 核心思想
将科学探究逻辑嵌入 LLM 代理架构，以仿真模型为中心，自动完成"任务分析→实验设计→比较仿真→结果解读→证据化建议生成"的完整闭环。

### 多代理框架（共 6 个代理，其中 5 个为 LLM 驱动，1 个为规则驱动）

| 代理 | 职责 |
|---|---|
| **Requirement Analyzer（需求分析器）** | 解析用户意图，生成任务阐释（task articulation）与结构化需求列表，形成任务描述 |
| **Planner（规划器）** | 基于任务描述和仿真功能规格（Simulation Specs），生成抽象计划，不涉及具体执行细节 |
| **Interactive Operator（交互操作器）** | 将抽象计划具体化；涉及仿真的步骤时生成带完整参数的 Python 代码并委派执行 |
| **Interactive Executor（交互执行器）** | 规则化软件组件，在受控 Python 解释器中执行仿真函数，返回文本与图形结果，具备错误反馈与重试机制 |
| **Interpreter（解释器）** | 使用具视觉能力的 LLM 对仿真生成的图像进行语义解读，产出文本洞察 |
| **Reporter（报告器）** | 汇总全过程文本输出，生成面向用户的最终响应 |

### 受控实验的数学形式化
给定用户查询 q、优化目标 g（如最大化产率）、基线参数向量 **x** = (x⁽¹⁾, x⁽²⁾, …, x⁽ⁿ⁾)：
1. **识别**与目标 g 相关的基线参数元素；
2. 对每个被选元素 x⁽ⁱ⁾ 施加受控扰动：**x⁽ⁱ⁾′ = x⁽ⁱ⁾ + δ⁽ⁱ⁾**，保持其他参数不变，得到 **x′** = (x⁽¹⁾, …, x⁽ⁱ⁾′, …, x⁽ⁿ⁾)；
3. 用仿真函数 f(·) 比较基线结果 **f(x)** 与扰动结果 **f(x′)**；
4. 汇总受控比较的发现，推荐改进参数向量 **x\***，使 f(x\*) 更接近目标 g。

### 交互协议与容错
- **Operator–Executor–Interpreter 三方交互**：操作器生成函数调用代码 → 执行器运行并返回文本结果 → 操作器继续推理；可视化输出并行传给解释器提取语义。
- **容错机制**：函数调用失败时，确定性的执行器返回错误信息，操作器可修正调用并重试，直至成功或达到预设重试上限。

### 结构化图可视化
- 推理轨迹被表示为**有向图**：节点为离散产物（任务描述、需求、规划步骤、仿真调用、输出等），边表示逻辑/程序性依赖，边类型包括 *derives、motivates、yields、summarized*。
- 该设计提供了清晰的**可观测性与可诊断性**，便于工业实际使用中的过程审查。

## 3. 实验设计

### 应用场景与数据集
- **场景**：制药结晶（crystallization）过程设计，共 5 个任务场景（Task Sample 1–5），例如：
  - 将晶体中位粒径从 32 μm 提升至 50 μm；
  - 加速结晶并提高产率；
  - 稳定目标多晶型；
  - 提高过饱和度以加速结晶；
  - 缩短结晶时间。
- **仿真模型**：阿斯利康的**专有工业资产**，基于第一性原理方程结合半经验公式（经拟合参数校准），由微分代数方程组成，能再现传质、相变、随时间演化的粒径分布等关键动力学。通过软件接口以可调用函数形式暴露给 LLM 代理。
- **基准（Benchmark）**：非公开标准数据集，而是基于 5 个工业任务场景 + 用户专家评估。

### 对比的系统变体（均为 GPT-4o 驱动）
1. **Full System（完整系统）**：完整流水线（代理 + 仿真集成 + 需求分析）；
2. **No simulation（无仿真）**：禁用仿真函数；
3. **No requirements（无需求分析）**：禁用需求分析器；
4. **LLM only（纯 LLM）**：直接用 GPT-4o 提示用户任务。

### 评估指标
- **推理特异性**：模糊词频（每 1000 词中模糊表达数）、LUCI 分数（0–1 语言不确定性归一化指标）；
- **正确性与有用性**：由两位资深领域专家按 1–5 分评分（正确性：结果与中间推理是否与经验知识一致；帮助性：输出对实际生产环境用户是否有用）；明确弃用 LLM-as-Judge，因其缺乏该领域的具体知识；
- **仿真调用行为**：仿真调用精度/召回率（Sim. P/R）、仿真确认率（Sim. Conf.，即假设被仿真结果验证的比例）。

## 6. 主要结论与发现

- **仿真集成显著提升推理质量**：完整系统的模糊词频最低（13.7/千词），LUCI 不确定性分数最低（0.13），输出更具体、更精确；而无仿真和纯 LLM 变体的 LUCI 分别高达 0.33 和 0.36，输出含糊、不可验证，专家评分为 <3.0（被认为"不可用"）。
- **用户评分领先**：完整系统正确性 4.1、帮助性 4.2，均优于无需求消融（3.4/3.8）和无仿真/纯 LLM（<3.0）。
- **仿真调用表现**：完整系统仿真调用精度达 **94%**，假设确认率 **76%**；表明系统能完成"假设→实验执行→验证"的闭环。
- **需求分析器的价值**：去除需求分析器后，仿真召回率虽从 64% 升至 69%，但精度骤降至 65%——系统倾向过度使用仿真函数，调用目标性变差；正确性、帮助性与语言确定性均下降。这与 ReAct、Plan-and-Act 等工作中"中间推理步骤有价值"的发现一致。
- **定性对比清晰**：面对同一用户问题，纯 LLM 给出"降低冷却速率至 3 °C/h"的模糊启发式建议；完整系统则基于仿真证据给出"将冷却速率增至 7.0 °C/h 可获得更大 d50、更窄 PSD、更稳定过饱和度"的精确可操作建议。
- **统一原理——近似保真度（approximation fidelity）**：仿真模型的物理保真度与语言模型的假设正确性共同决定系统质量；低保真仿真会向 LLM 注入噪声而非知识，差 LLM 则无法有效与仿真交互。系统定位为**决策支持助手**，而非取代用户判断。

## 7. 优点与亮点

1. **科学推理结构化**：将推理组织为"假设→干预→观察→分析→报告"的科学探究范式，任务被分解为子目标、需求、受控实验与综合结论，系统性强且可验证。
2. **高保真仿真集成**：不同于已有工作中简化的沙盒/游戏环境，该系统与再现真实物理化学动态的高保真工业仿真模型交互，实现了"仿真模型知识与语言模型知识互补"。
3. **工业实用性导向**：在真实应用约束下开发；有向图形式的推理轨迹可视化提供清晰的**可观测性和可诊断性**，便于工程审查。
4. **容错工具调用机制**：Operator–Executor 两代理对话环支持失败重试，增强系统的鲁棒性和自适应性。
5. **严谨的评估设计**：拒绝 LLM-as-Judge 的便捷路径，采用领域专家人工评估；结合词汇模糊性定量指标（模糊词频、LUCI）与行为指标（仿真调用精度/召回率、假设确认率），多维度刻画系统表现。
6. **定性案例极具说服力**：同一任务下仿真集成与纯语言输出的对比鲜明，直观展示"从模糊启发式到证据化精确建议"的转变。

## 8. 不足与局限

- **实验覆盖有限**：仅 5 个任务场景、单一工业领域（制药结晶），且未报告多次运行的统计稳定性；方差较大暗示结论可能对任务选择敏感。
- **不可复现性**：仿真模型为专有资产，未公开；数据收集与推理轨迹虽详细呈现，但第三方难以复现核心实验设置。
- **评估主观性风险**：仅 2 位领域专家评分，未披露评分者间一致性；<3.0 的截断式报告方式损失了区分度信息。
- **仿真确认率未饱和**：假设确认率仅 76%，仿真召回率仅 64%，说明系统仍会遗漏必要的仿真调用或产生未被验证的假设；无需求消融的召回率反而更高（69%）也提示完整系统在"探索充分性"上可能偏保守。
- **LLM 幻觉与仿真保真度的叠加风险**：如讨论部分所述，低保真仿真或弱 LLM 都会使系统失去科学准确性；论文未系统评估仿真模型误差对最终建议的影响。
- **算力与成本信息缺失**：未报告 API 调用次数、推理成本、仿真耗时等实际部署资源需求，限制了工程落地的成本评估。
- **未与其他多代理/工具集成基线对比**：仅与自身的消融变体及纯 LLM 对比，未与 ReAct、AutoGen、ChemCrow 等现有方法在同一任务上横向比较，无法定位其在更广泛方法空间中的相对位置。
