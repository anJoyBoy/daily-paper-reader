## 摘要
许多以表格为中心的NLP任务（如NL2SQL）首先使用关键词搜索从大型集合中检索相关表格。近期工作利用LLM生成自然语言表格描述以改进检索，但通常针对流畅性而非检索效果进行优化。我们提出Polaris，一个直接根据检索反馈训练LLM生成表格描述的系统。我们的关键洞见是，现有的表格检索基准已包含此任务所需的监督信息：给定查询-表格相关性判断，我们为每个表格生成多个候选描述，根据其BM25检索效果进行排序，并使用由此产生的偏好对通过直接偏好优化（DPO）微调LLM。Polaris还在生成前扩展缩写的表格名和列名，以减少词汇不匹配。大量实验表明，Polaris优于最先进的AutoDDG方案，且往往有显著优势。更广泛地说，我们的结果证明，检索基准可以重新用作监督信息，以训练LLM生成面向检索的元数据。

## Abstract
Many table-centric NLP tasks such as NL2SQL first retrieve relevant tables from large collections using keyword search. Recent work uses LLMs to generate natural-language table descriptions to improve retrieval, but they are typically optimized for fluency rather than retrieval effectiveness. We present Polaris, a system that trains an LLM to generate table descriptions directly from retrieval feedback. Our key insight is that existing table retrieval benchmarks already contain the supervision needed for this task: given query-table relevance judgments, we generate multiple candidate descriptions for each table, rank them by their BM25 retrieval effectiveness, and use the resulting preference pairs to fine-tune the LLM with Direct Preference Optimization (DPO). Polaris further expands abbreviated table and column names before generation to reduce vocabulary mismatch. Extensive experiments show that Polaris outperforms the state-of-the-art AutoDDG solution, often by a significant margin. More broadly, our results demonstrate that retrieval benchmarks can be repurposed as supervision for training LLMs to generate retrieval-oriented metadata.

## 1. 论文的核心问题与整体含义（研究动机和背景）

表格数据在企业、科学、政府等领域广泛存在，许多以表格为中心的 NLP 任务（如 NL2SQL、表格问答）都需要先从一个大型表格集合中**检索出相关表格**，再进行下游推理。然而，现实中的表名和列名往往晦涩、简短、充满缩写（如 "DTPh" 表示 "daytime phone"），这严重阻碍了关键词搜索（KWS）的效果。

近年来，研究者尝试用 LLM 生成自然语言的表格描述来改善检索。然而，现有方法（如最先进的 AutoDDG）存在以下关键问题：

- **面向流畅性而非检索效果**：生成的描述虽然语言通顺，但未必包含与查询匹配的关键词汇；
- **流水线复杂、信息有损**：AutoDDG 需要多次调用 LLM 分步生成统计信息、主题、列摘要等，再合成最终描述，中间步骤可能丢失信息；
- **不做名称扩展**：LLM 在晦涩的缩写名称上难以生成有信息量的描述；
- **不微调模型**：直接使用通用 LLM，无法针对检索任务优化；
- **只用描述单一字段检索**：忽略了表/列名扩展、上下文等其他元数据的价值。

本文的核心洞见是：**现有的表格检索基准中已经包含了训练所需的监督信号**——查询-表格相关性判断。利用这些标注数据，可以直接根据检索效果（BM25 分数）对候选描述进行排序，形成偏好对，从而用 DPO 微调 LLM，使其生成"检索友好"的表格描述。这一思路具有更广泛的含义：**检索基准可以被重新用作训练元数据生成器的监督来源**。

## 2. 论文提出的方法论

Polaris 的核心思想是"从检索反馈中学习生成表格描述"，分为**两个阶段**（见下图）：

![Polaris总体架构](assets/figures/arxiv/2608.17171v1/fig-002.webp)

### 2.1 阶段一：微调 LLM（训练流程）

1. **表/列名扩展**：使用 Columbo（Cai et al., 2025）方案，将晦涩的缩写表名/列名（如 "eSal" → "employee salary"）扩展为完整英文短语，为 LLM 提供更丰富的输入信息。
2. **初始描述生成**：对每个"金标准表"（至少对一个查询有正相关性分数），用未经微调的 LLM 在非零温度下采样生成 K=3 个候选描述。对其他表各生成 1 条描述。此处的关键词是：**只需单次 LLM 调用**（对比 AutoDDG 至少四次），使用包含名称扩展和表上下文的提示词，输出六字段 JSON 格式的描述。
3. **基于检索效果的描述排序**：对每张金标准表构建一个"统一语料库"（包含该表的 K 个候选描述副本 + 其余各表一个随机描述），用 BM25 计算各候选描述在相关查询上的平均分数，将其从高到低排序。
4. **构造偏好对**：取排名最高和排名最低的描述（如 dπ1 ≻ dπ3），构建偏好对 (prompt(T), d_win, d_lose)。
5. **DPO 微调**：用直接偏好优化（DPO）微调基础 LLM（Llama 3.1 8B Instruct）。DPO 无需单独训练奖励模型，直接在偏好对上优化：
   - 4-bit 量化 + LoRA（rank=64，α=64），167M 可训练参数（占 2.05%）；
   - β=0.1，学习率 5×10⁻⁶，1 epoch，有效批大小 8，AdamW 8-bit 优化器；
   - 采用 leave-one-out 交叉验证：留出一个数据集作为验证集，用其余五个数据集的偏好对训练。

### 2.2 阶段二：为新表格生成描述

对新的表格语料库，先扩展表/列名，再将扩展后的名称+上下文输入训练好的 LLM，用与训练时相同的提示词生成一条描述，最后用 BM25 对这些描述进行关键词检索。

### 2.3 多字段检索增强

Polaris 还提出一种多字段 BM25 分数融合方式：将"描述"、"表/列名扩展"和"表上下文"三个字段结合，分数取最大匹配字段的 BM25 分数加上 0.1 倍其余字段分数之和作为 tiebreaker，让最强信号主导同时兼顾多字段匹配。

### 2.4 关键技巧总结

- **名称扩展**：解决缩写导致词汇不匹配问题；
- **偏好对构造**：用 BM25 检索效果而非人工判断来打分，克服了人无法判断哪条描述对 KWS 更优的问题；
- **DPO 训练**：直接优化 LLM 使"胜出"描述概率相对上升；
- **单次调用简洁流水线**：证明比 AutoDDG 复杂的多步流水线更有效；
- **多字段检索**：描述并非完美，融合其他元数据可进一步提升准确率。

1. **Polaris 全面优于 AutoDDG**：在 6 个数据集中 5 个上显著领先，例如 LTER 上 NDCG@100 提升 44.6%（0.356→0.515），AW 上 NDCG@5 提升 31.7%（0.555→0.731）。WikiTables 上两者基本持平。

## 7. 局限性与未来工作

- **仅验证了词法检索**：所有实验均基于 BM25，Polaris 生成的描述尚未在密集检索（dense retrieval）或混合检索（hybrid search）场景下验证，其对语义匹配的增益未知。
- **名称扩展依赖外部工具**：表/列名扩展依赖 Columbo 或 Llama 4（AWS Bedrock）等外部组件，引入额外 API 调用成本，且在模型不可用或处理大规模语料时可能成为性能瓶颈。
- **DPO 偏好对的区分度问题**：偏好对完全由 BM25 分数排序决定，在高相关性密度、低区分度的数据集（如 ECIR）上，“胜出”与“失败”描述的检索分数差异过小，导致 DPO 信号噪声增加，甚至在部分指标上表现为负面效果。
- **超参数未做充分调优**：候选描述数 K 与 DPO 的 β 均采用固定值（K=3，β=0.1），不同数据集上的最优配置可能存在差异，论文未提供自适应的超参数选择策略。
- **未来研究方向**：将方法推广到行级摘要、SQL 查询生成等更广泛的元数据生成任务；结合跨编码器（cross-encoder）重排序或学习型检索器进一步提升效果；引入真实用户查询日志代替人工标注，扩展监督信号的规模与多样性。
