## 摘要
大型语言模型的最新进展催生了一类新型的代理式数据科学系统，使用户能够通过自然语言完成复杂的数据科学工作流程。尽管这些系统可以显著减少人工操作，但当出现故障或意外输出时，仍然难以诊断其行为并引导推理过程。我们提出了MUSE，一个交互式元代理，通过以下方式增强用户对代理式数据科学系统的理解和控制：(1) 将低级执行轨迹动态重构为多个语义层级，支持从高层概览到低级实现细节的导航；(2) 使用户能够在上下文中引用特定的工作流步骤，提出有根据的问题、提供反馈并修正有问题的步骤，而无需手动定位相关的执行历史；(3) 通过呈现可疑步骤以供检查、构建修复过程，并将用户的修复意图转化为底层代理的情境化指令，支持混合主动性引导。在一项受试者间研究（n = 15）中，MUSE提高了任务效率，并增强了用户理解和引导代理式数据科学工作流的信心。

## Abstract
Recent advances in large language models have enabled a new class of agentic data science systems that allow users to complete complex data science workflows through natural language. Although these systems can significantly reduce manual effort, it remains difficult to diagnose their behavior and steer the reasoning process when failures or unexpected outputs occur. We present MUSE, an interactive meta-agent that enhances user understanding and control of agentic data science systems by (1) dynamically restructuring low-level execution traces into multiple semantic levels that support navigation from high-level overviews to low-level implementation details; (2) enabling users to reference specific workflow steps in context to ask grounded questions, provide feedback, and revise problematic steps without manually locating relevant execution history; and (3) supporting mixed-initiative steering by surfacing suspicious steps for inspection, scaffolding the repair process, and translating user repair intent into contextualized instructions for the underlying agent. In a between-subjects study (n = 15), MUSE improved task efficiency and increased users' confidence in understanding and steering agentic data science workflows.

## 2. 论文提出的方法论

### 核心思想
MUSE是一个元代理（meta-agent），不直接执行数据科学任务，而是在底层DS Agent之上增加一层交互和翻译机制，将底层Agent的无结构行为转化为用户可以理解、操作的结构化语义视图，并支持混合主动性（mixed-initiative）的检查、验证与修复。

### 系统架构：四大层级

1. **Summarization Layer（摘要层）**
   - 对Agent运行时进行插桩，捕获五类执行日志：推理轨迹、工具调用、代码、信号/状态、中间产物；
   - 利用Agent发出的步骤完成标记（STEP_COMPLETE）将日志流切分为**语义块（Semantic Chunk）**，避免依赖LLM推断边界；
   - 将每个语义块通过LLM转化为**L1–L5五级语义表示**：
     - L1：阶段标题；
     - L2：自然语言摘要；
     - L3：有序子步骤列表；
     - L4：展开的详细操作（文件、命令、参数）；
     - L5：底层代码、命令和工具输出。
   - 用户可通过语义滑块在概览与细节之间自由导航，遵循“先概览、再缩放过滤、按需看细节”的信息检索设计原则。

2. **Monitoring Layer（监控层）**
   - 基于预定义启发式规则（表11，涵盖数据级与Agent级共20种警告类型），对每个语义块进行实时检测；
   - 识别可疑行为后，在对应步骤卡片上显示局部警告徽章；
   - 用户可点击“Why this warning?”查看基于证据的警告解释，并可一键进入修复流程。

3. **Verification Layer（验证层）**
   - 支持**上下文引用**：用户可将工作流步骤拖入（drag-and-drop）聊天框，MUSE自动解析该步骤对应的日志、文件、脚本和产物作为上下文证据，回答用户问题；
   - 支持**脚手架式验证（Scaffolded Verification）**：用户高亮某个输出（如指标）后，MUSE基于所选内容生成3–5个具体验证计划供用户选择，随后自动生成验证脚本在沙箱中执行，无需用户手动编写检查代码。

4. **Steering Layer（引导层）**
   - 支持**脚手架式修复**：基于警告解释和修复建议，MUSE提供可选的修复方案；
   - 用户选择修复方案后，MUSE自动将修复意图、受影响的步骤和警告上下文编译为上下文化的指令，传递给底层DS Agent执行；
   - 修复以用户选中的步骤为重启点，并级联更新下游产物。

### 关键实现细节
- 底层DS Agent使用Claude Agent SDK实现，控制循环由 `ds-pipeline`、`step-complete`、`ds-progress-checker` 三个技能组成，阶段工作委托给 `ds-cleaning`、`ds-eda`、`ds-feature-engineering`、`ds-modeling` 等技能；
- MUSE作为一个独立的只读Agent运行，读取沙箱产物回答用户问题，需要修改或继续执行时再把控制权交还给 `ds-pipeline`；
- L1–L5语义翻译使用Google Gemini API生成，所有LLM调用温度设为0以保证可复现性。

## 3. 实验设计

### 实验形式
- **形成性研究**：7名有AI工具使用经验的数据科学家，通过任务式研究和半结构化访谈，提炼出4项用户需求（理解系统行为、快速定位可疑步骤、精确上下文指定修复、混合主动性控制）。
- **组间用户研究**：15名来自不同学术背景的参与者（商业分析、计算机科学、金融、建筑、物理、机械工程等），随机分配到三种条件。

### 实验场景与基准
- **任务数据**：从Kaggle选取6个代表不同难度和领域的DS任务：
  - 易：送餐时间预测（T1）、需求预测（T2）；
  - 中：电信客户流失预测（T3）、客户终身价值预测（T4）；
  - 难：MovieLens 100k评分预测（T5）、在线新闻热度预测（T6）。
- **对比条件**：
  - **条件A（Raw Logs）**：直接显示底层Agent原始执行输出，用户可查看日志并通过聊天界面反馈（类似现有Agent界面）；
  - **条件B（DiLLS）**：基于DiLLS的改进基线，提供三层摘要（活动→动作→操作），使用相同警告检测方法但警告不可原位操作，用户需跳到外部编辑器检查/修改；
  - **条件C（MUSE）**：论文提出的系统。
- **模型**：使用弱模型（Claude Haiku 4.5）和强模型（Claude Opus 4.6）以覆盖不同错误特征，条件和模型分配做了平衡设计。
- **成功标准**：30分钟内产生可运行的DS流水线，并通过人工检查确认预处理、特征工程、模型选择和训练评估均正确。

### 评价指标
- 任务完成时间、成功率、重试次数；
- 用户自信度（7点Likert量表）；
- NASA TLX认知负荷问卷；
- 用户对5个对比陈述（理解、错误定位、验证、信任、控制）的评分；
- 交互行为日志（滚动、滑块调节、警告检查、提问、修订、验证等）。

## 6. 论文的主要结论与发现

- **效率提升**：MUSE组平均17分钟/任务，比原始日志条件缩短35%（统计显著，p=.035），比DiLLS条件缩短9%（不显著）；MUSE组任务成功率达90%，远高于原始日志条件的50%。
- **自信度提升**：MUSE组用户对最终结果的自信心评分最高（均值5.80 vs 条件A 2.60 vs 条件B 4.20），差异统计显著（p=.0265）。
- **认知负荷降低**：在“匆忙感”“努力程度”“挫败感”三个维度上，MUSE组显著低于对比条件（p<.05）。
- **警告解决率高**：在相似警告总数下（39 vs 36），MUSE组平均解决2.8个警告，DiLLS组仅0.8个（p=.0118）。
- **行为模式转变**：MUSE将用户的监控行为从“线性滚动搜索”（条件A为147次滚动/任务）转变为“局部定向检查”（MUSE组61次滚动/任务），语义滑块调整是最频繁的交互（162次）。
- **用户类型差异**：观察到三类用户行为模式——AI委派者（Delegators）、AI协作者（Collaborators）、AI审计者（Auditors），提示不同用户需要不同层级的验证支持。
- **Agent错误特征**：在DS任务中，Agent即使使用弱模型也很少出现语法错误或崩溃，而是产生大量“静默错误”（如未经验证的Schema假设占56%、缺失数据未检查16%、单次分割评估12%），这类错误更难被用户察觉。
- **技术背景影响**：专家与非专家在完成时间和尝试次数上无显著差异，说明MUSE有助于弥合用户间的技术差距。

## 7. 优点

- **创新的元代理架构**：将底层Agent执行日志转化为面向数据科学语义而非Agent行为的结构化表示，大幅降低用户的认知负担，是对信息检索“先概览后细节”原则的有效应用。
- **多级语义抽象（L1–L5）**：设计合理且实用，用户可以在不丢失细节的前提下灵活调节理解粒度。
- **上下文感知的交互设计**：拖放步骤入聊天框、高亮输出触发验证、原位警告修复等设计，极大减少了用户在日志、编辑器、聊天框之间切换所需的上下文重建成本。
- **混合主动性机制**：系统主动监控和提示（信息气味），而非被动等待用户发现问题，有效支持运行期的实时干预。
- **脚手架式验证与修复**：不仅帮助用户发现“哪里有问题”，还通过生成验证计划和修复选项，降低非AI专家指定修复意图的提示负担。
- **实验设计整体严谨**：形成性研究驱动设计，正式实验包含多条件对照、多任务、多模型、混合方法，并对交互行为进行了细粒度的时间线分析。

## 8. 不足与局限

- **实验覆盖有限**：6个Kaggle任务反映的是竞赛型、有明确标签的预测场景，缺少真实开放式的探索性分析、多表关联、非结构化数据等复杂情形。
- **样本人群偏向非专家**：作者明确指出研究结论主要反映MUSE对经验较少用户的帮助，对专家级DS从业者的有效性尚不明确。
- **警告检测依赖预定义启发式**：目前只能捕捉到预设的20类问题模式，对超出此范围或其他领域的错误（如领域特定错误）可能漏报。
- **与DiLLS对比不显著**：在任务完成时间上，MUSE与条件B的差异未达统计显著，MUSE的某些效能优势可能主要来自比原始日志更结构化，而非某种特定机制。
- **LLM生成的不确定性**：MUSE自身的语义翻译和警告检测依赖商业LLM API，存在潜在的错误传播风险；虽然温度设为0，但不同模型的判断稳定性未被系统评估。
- **生态依赖性**：底层Agent是定制化的技能式流水线（固定7阶段），MUSE的通用性（适配任意Agent框架）尚未验证。
- **缺少长期部署验证**：实验为单次受控会话，未考察用户在真实工作中长时间使用MUSE的效果、学习成本和工具采纳意愿。
