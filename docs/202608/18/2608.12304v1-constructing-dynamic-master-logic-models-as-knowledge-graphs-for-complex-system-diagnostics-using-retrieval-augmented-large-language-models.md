## 摘要
动态主逻辑（DML）提供了一种分层框架，通过将功能目标与底层结构元素相连接来表示系统行为。然而，DML的构建通常依赖于专家对技术文档的解释，这限制了其在复杂系统中的可扩展性。本研究提出了一种框架，用于从系统描述中自动构建DML模型，并将其表示为知识图谱（KG-DML），使用检索增强生成和大型语言模型作为使能工具。在先前小规模系统工作的基础上，该框架将自动KG-DML构建和评估扩展到规模更大、复杂度更高的系统。模型构建通过有针对性的检索在DML层次结构上进行，同时保留功能依赖关系和显式逻辑关系。生成的KG-DML支持诊断推理、安全评估、向上故障传播和向下依赖追踪。一种多级验证方法评估了各层的精确率和召回率、逻辑门一致性以及整体结构完整性。将该方法应用于一座退役沸水反应堆的低压冷却剂注入系统，展示了多次重复运行中的一致重建。结果表明，自动KG-DML构建可以将技术文档转换为可执行的功能模型，用于诊断和可靠性分析。

## Abstract
Dynamic Master Logic (DML) provides a hierarchical framework for representing system behavior by linking functional objectives to underlying structural elements. However, DML construction typically relies on expert interpretation of technical documentation, limiting scalability for complex systems. This study presents a framework for automated construction of DML models from system descriptions and their representation as Knowledge Graphs (KG-DML), using Retrieval-Augmented Generation and Large Language Models as enabling tools. Building on prior work with small-scale systems, the framework extends automated KG-DML construction and evaluation to substantially larger and more complex systems. Model construction proceeds across the DML hierarchy using targeted retrieval while preserving functional dependencies and explicit logical relationships. The resulting KG-DML supports diagnostic reasoning, safety assessment, upward failure propagation, and downward dependency tracing. A multi-level validation methodology evaluates layer-specific precision and recall, logical gate consistency, and overall structural integrity. Application to the Low-Pressure Coolant Injection system of a decommissioned Boiling Water Reactor demonstrates consistent reconstruction across repeated runs. The results show that automated KG-DML construction can transform technical documentation into executable functional models for diagnostic and reliability analysis.

## 2. 论文提出的方法论

- **总体架构**：框架由三个阶段组成——文档处理与嵌入、逐层 DML 模型构建、知识图谱合成与导出；另有评估框架和交互模块。
- **阶段一：文档预处理与嵌入**
  - 对系统文档进行标准化：统一组件标识符、扩展缩写、补充描述性上下文、消除代词歧义。
  - 按段落切分为 1500 字符块，重叠 150 字符，用 text-embedding-3-small 模型嵌入并存储于向量数据库。
- **阶段二：逐层模型构建**
  - 按 DML 层次顺序构建：Goals → Functions → Subfunctions → Components → Success Conditions。
  - 每一层构造检索查询（由层的语义定义和上一阶段确定的父节点组成），通过余弦相似度（式 1）从向量库中检索 Top-K（K=10）相关文档块。
  - 将检索证据、父节点和层特定指令交给 LLM（GPT-4o，温度=0），模型以预定义的 JSON Schema 输出候选节点及其逻辑关系（AND/OR 门）。
  - 输出经结构正确性、标识符有效性和层约束验证后，追加到“主 JSON”中间表示中。
  - 父节点可分批处理（batch size = 1、5、10、15），批次大小影响模型质量与计算效率。
- **阶段三：知识图谱合成与导出**
  - 利用算法 1（Cypher 生成算法）将主 JSON 转换为 Neo4j 图数据库的 Cypher 语句。

- **评估框架**
  - 节点级评估：逐层计算精确率、召回率和 F2 分数（F2 更重视召回，因漏项比多余项危害更大），区分正确、缺失、幻觉三类节点。

  - 整体完整性评分（式 2）：由各层 F2 加权均值乘以指数结构惩罚项（惩罚与缺失节点、缺失关系、门不匹配、孤立节点相关），反映结构重建质量和端到端推理的适用性；算法 2 给出完整计算流程。
- **交互模块**
  - LLM 代理作为协调层，解释用户查询并调用预定义图遍历工具，而非直接自主推理。
  - 向上传播：从组件/成功条件层的状态与条件概率出发，通过嵌套布尔门递归聚合，计算系统级目标成功概率，支持多故障场景。
  - 向下传播：从查询节点出发枚举最小成功路径集，遵循布尔逻辑（AND 组合、OR 分列）；对冗余相同组件附加共因失效（CCF）定性提示。

## 7. 优点

- **约束化 LLM 应用**：通过预定义 DML Schema、有界系统范围、结构化 JSON 输出和温度=0，有效限制了 LLM 的自由度，大幅降低了“幻觉”和结构漂移风险。
- **分层构建+父节点条件化**：逐层构造模型，每层只检索与当前父节点相关的文档内容，既管理了提示/上下文长度，又保持了整体层次的一致性；这是一种对大规模文档场景很自然的扩展策略。
- **嵌套布尔门的图表示**：在知识图谱中用中间门节点递归表达嵌套 AND/OR 逻辑，不做扁平化处理，保证了从目标到成功条件的完整功能路径可追踪。
- **多维度评估体系**：结合逐层精确率/召回率/F2、链接级指标、门精度和整体完整性评分（含结构惩罚的指数形式），比单一指标更能反映端到端诊断推理的适用性。
- **交互设计可解释性**：LLM 仅充当查询协调者，确定性图遍历与布尔传播由工具完成，推理路径完全可溯源，降低了无依据推理的风险。
- **对工程实践的定位诚实**：明确声明构建结果是 LLM 辅助的，需领域专家验证，不以替代专家为目标。

## 8. 不足与局限

- **模型偏差**：依赖单一 LLM（GPT-4o），未评估不同架构/能力水平下的性能鲁棒性；批次、提示、检索配置等默认参数（如 chunk 大小、Top-K、温度）在实验中被固定，其对结果的敏感性未充分刻画。
- **评估覆盖有限**：仅单一系统验证，未涉及多文档、多格式、更多层嵌套或更高组件密度的场景；缺乏多源异构文档的鲁棒性测试。
- **检索是必要前提**：由于系统文档体积远超上下文窗口，检索成为结构性依赖，因此无法评估“无检索/全上下文”基线；嵌入质量和 chunk 策略对最终模型质量的影响未经消融验证。
- **结构≠功能**：评估基于节点/链接/门级结构一致性，未验证模型的逻辑行为等价性（如最小割集/成功路径集的一致性），结构性匹配不一定意味着相同诊断推理结果。
- **静态快照**：框架基于静态文档提取，生成的是系统结构快照，不支持时间依赖、延迟门或上下文相关的动态行为建模。

- **文档质量前提**：虽然做了预处理，但未系统评估噪声、遗漏、高度不一致或不完整文档下的表现，实际工程文档中这些都是常见挑战。
