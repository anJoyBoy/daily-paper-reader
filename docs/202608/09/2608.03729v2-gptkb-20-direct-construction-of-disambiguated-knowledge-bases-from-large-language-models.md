## 摘要
自动化知识库构建（AKBC）是一项核心的自然语言处理任务，近期工作提出直接从大型语言模型（LLM）生成知识库，将模型本身视为知识来源。然而，LLM 天生不具备实体的表示，导致重复条目和概念混淆。我们提出 GPTKB 2.0，一种直接从 LLM 构建消歧知识库的方法。GPTKB 2.0 融入了对实体、关系和类别的即时消歧，并经过精心设计以满足可扩展性和消歧准确性。我们分析了核心设计决策，并刻画了准确性、规模和成本之间的权衡。我们大规模执行 GPTKB 2.0，获得了一个包含超过 100 万消歧实体和 3840 万条三元组的物化知识库。这是首个具有显式内部规范化（实体、关系和类别）的百万级 LLM 原生知识库，与此前以维基媒体为中心的工作形成显著区别。GPTKB 2.0 可在 https://gptkb.org/ 获取。

## Abstract
Automated Knowledge Base Construction (AKBC) is a core NLP task, and recent work proposes generating knowledge bases directly from large language models (LLMs), treating the model itself as the knowledge source. However, LLMs natively possess no representation of entities, leading to duplicate entries as well as conflations. We propose GPTKB 2.0, a methodology for constructing disambiguated KBs directly from LLMs. GPTKB 2.0 incorporates on-the-fly disambiguation of entities, relations and classes, and is meticulously designed to satisfy both scalability and disambiguation accuracy. We analyze the central design decisions and characterize the trade-offs between accuracy, scale, and cost. We execute GPTKB 2.0 at scale, obtaining a materialized KB containing over 1M disambiguated entities and 38.4M triples. This represents the first million-scale LLM-native KB with explicit internal canonicalization of entities, relations, and classes, a significant departure from prior Wikimedia-centric works. GPTKB 2.0 is available at https://gptkb.org/.

# GPTKB 2.0 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：自动化知识库构建（AKBC）是 NLP 的核心任务。传统方法依赖 Wikipedia/Wikidata 等人工维护资源来获得实体身份，或从文本语料中抽取事实。近期，利用 LLM 直接"物化"其参数化知识来构建知识库（LLM-native KB）成为新兴方向。
- **核心问题**：LLM 是基于字符串训练的，**没有原生的实体表示**，因此在生成知识时会产生两类互补的失败模式：
  - **同形异义（Homonymy）**：表面标签相同但指称不同的实体被错误合并，例如城市 *Munich* 与电影 *Munich*。
  - **同义异形（Synonymy）**：指称相同但标签不同的实体未能合并，例如 *Île-de-France* 与 *Île-de-France region*。
- **研究问题**：给定一个或多个种子实体，如何在不使用外部标识符（如 Wikidata ID）的前提下，直接从 LLM 中可扩展地构建一个经过规范化（canonicalized）的开放域知识库？
- **整体意义**：该工作是**首次在 Wikimedia 体系之外**构建出百万规模的、显式内部规范化（实体、关系、类别均消歧）的 LLM 原生知识库，突破了 15 多年来依赖维基媒体资源进行实体规范的范式。

## 2. 方法论：核心思想与关键技术细节

### 2.1 数据模型
- 知识库定义为四元组 (T, E, R, C)：
  - **三元组**：每个三元组是六元组，包含主语 ID、关系 ID、宾语 ID（实体/类/字面量）及三者的标签。
  - **实体/关系/类别**：每个元素包含 ID、标签、描述和别名集合。
- 元素**用唯一 ID 而非标签标识**：同一标签可对应多个不同实体（容纳同形异义）；同一元素可挂多个别名（容纳同义异形）。任意两个元素必须在标签或描述上有所区别。

### 2.2 构建流水线（三阶段核心操作）
流水线从种子实体出发，沿"主语–宾语"前沿迭代执行"抽取 → 消歧 → 扩展"：

1. **知识抽取（Elicitation）**：提示词中除实体标签外还附带**实体描述**作为上下文，确保抽取的事实指向目标实体而非同名实体。同时要求至少生成一条 `instanceOf` 三元组以捕获实体类型。
2. **命名实体识别（NER）**：将宾语的上下文（来源三元组）一并提供给 LLM，以判断宾语是字面量（如邮编 01099）还是命名实体（如乐队 01099）。
3. **消歧（Disambiguation）**，分为两轮 NED：
   - **第一轮：三元组上下文 NED**——按标签嵌入相似度检索 top-5 候选实体，将目标标签、来源三元组和候选实体的标签/描述一起交给 LLM，决定匹配、新建（None of above）或不确定（Unsure）。
   - **描述生成**：被标记为"新建"的实体，由 LLM 结合标签和来源三元组生成一句话描述，此描述成为后续所有消歧决策的上下文。
   - **第二轮：描述上下文 NED**——针对高密度同形异义标签（如 *Faculty of Law* 出现 300+ 次），候选集限定为同标签实体，按描述嵌入相似度检索，再用生成的描述作为上下文进行消歧。

### 2.3 守卫式并行化（Guarded Parallelization）
- 顺序消歧代价过高，但朴素并行化会导致重复实体（两个同名实体同时被处理，彼此无法作为候选）。
- 策略：按标签嵌入对 NED 请求聚类；从每个簇中选择最早被抽取的标签；若该标签已完成的 NED 次数超过阈值（50），则并行处理该簇；否则只处理最早的一个，其余推迟至后续批次，届时首个实体已入库可作为候选。

### 2.4 关系与类别的消歧
- 关系与类别仍存在同义异形问题（如 `isLocatedIn` vs `locatedIn`、`Film` vs `Movie`），但同形异义罕见且候选空间小，故简化为**单轮三元组上下文 NED + 描述生成**，省略 Unsure 选项。

### 2.5 缓存机制
- **实体缓存**：若某来源三元组的 (关系标签, 宾语标签) 组合出现超过 λ=50 次且历史消歧结果一致指向同一实体 ID，则直接复用该 ID，跳过 NER 和 NED（在 NER 前和 NED 前各检查一次，因并发可能改变缓存状态）。
- **关系/类别缓存**：采用简单的存在性策略，标签已入库后后续出现直接链接到现有元素。

## 3. 实验设计

### 3.1 基准与数据集
- 该任务**没有现成的标准 benchmark**，作者使用**自建评估集 + 人工标注**：
  - **模型选择评估**：从 100 个随机实体上评估抽取质量；100 个 NER 请求；100 个 NED 请求（50 个 Split + 50 个 Merge），均以人工标注为 ground truth。
  - **NED 性能评估**：n=400（同形异义合并、同义异形合并、同形异义拆分、同义异形拆分各 100 例）人工验证。
  - **三元组事实性**：人工 n=200，LLM 裁判 n=1,000（基于 Brave Search API 的智能体式网页检索验证）。
  - **实体事实性**：人工 n=200，LLM 裁判 n=1,000；另对 1,000 个 Wikidata 新颖实体验证。
  - **消融实验**：去掉第二轮描述上下文 NED 的管道变体，构建 2.3M 三元组的消融 KB，各取 100 个 split/merge 样本人工评估。
  - **基线对比**：① 基于表面字符串身份（String-based Identity）的基线；② 在 Ancient Babylon 领域将基线与 GPTKB 2.0 各扩展到 2,700 实体做聚焦对比。

### 3.2 对比方法
- 主要对比对象是**字符串作为实体标识的基线**（非消歧的朴素方法）；此外在消融中对比了"仅第一轮 NED"的变体；在模型选择上对比了 GPT-5.1、GPT-5-mini、GPT-5-nano 三个商业模型。

### 3.3 关键配置
- 种子实体：Vannevar Bush（任意选择，作者论证种子无关性）。
- 抽取和描述生成用 GPT-5.1，NER 和 NED 用 GPT-5-mini；嵌入模型用 Qwen3-Embedding-4B；每轮 NED 检索 top-5 候选；并行化和缓存阈值均为 50。

## 4. 资源与算力

- **未提及任何 GPU 型号、数量或训练时长**——该方法不进行模型训练，而是通过调用商业 LLM API 完成构建。
- 全文使用 **47.7M 次 API 调用**，构建耗时 **70 天**，总花费 **$6,992**。
- token 消耗分布：Elicitation 占 59.5% 成本（1M 次调用，2.657 亿输入 + 7.988 亿输出 token）；实体相关操作（NER + 两轮 NED + 描述生成）占 38.8%；类别与关系规范化合计不到 2%。
- 每实体平均成本随 KB 规模增大从 $0.015 降至约 $0.008，体现缓存和合并的边际效益。

## 5. 实验数量与充分性

- **实验数量**：涵盖模型选择（3 个模型 × 3 项任务）、嵌入模型选择（3 个变体）、消融（完整管道 vs 单轮 NED）、领域对比（Babylon）、大规模运行 + 多维度质量评估（人工 n=400/200，LLM n=1000）以及超参数验证（缓存/并行化阈值各 100 例人工核验），总体实验较充分。
- **客观性**：人工评估采用双人标注抽样（100 例中 90 例一致）；LLM 裁判对比了三种模型（Llama-4-Scout、Opus 4.7、Gemini 2.5 Pro）并报告了差异。同义异形拆分评估作者承认只能覆盖"标签嵌入相似"的重复，真实拆分准确率可能略低。
- **公平性**：基线对比中巴比伦领域实验显示非消歧管道效率更低且已出现同形异义混淆（如 Paris、Philadelphia 指称不同实体），对比较有说服力。
- **局限性**：多数评估基于抽样（100–1000 样本），对于 3840 万三元组只能提供估计；人工评估由作者本人参与，存在一定主观偏差风险。

## 6. 主要结论与发现

- 成功构建 **GPTKB 2.0**：包含 **1,592,185 个消歧实体、38,450,135 条三元组、207,633 个关系、66,523 个类别**。
- 消歧效果显著：将 **2,316,275 个表面标签合并为 1,592,185 个规范实体**，正确区分了 **131,990 个共享 41,275 个表面标签的同形异义实体**。
- **36.8% 的实体在 Wikidata 中不存在**（1,000 样本验证），且这些新颖实体大多位于长尾区域（89% 出现少于 5 次），表明 LLM 原生 KB 能有效补充人工策展资源覆盖不足的长尾知识。
- 质量评估：NED 同形异义合并准确率 98%、同义异形合并 91%、同形异义拆分 100%、同义异形拆分 95%；三元组事实性 >94%（人工）/>92%（LLM），实体可验证性 96%/92.3%。
- 消融证实第二轮描述上下文 NED 对抑制重复实体积累至关重要（去掉后误合并率显著上升，重复实体率高达 22%）。
- 基线对比显示字符串身份方案产生大量重复且无法处理同形异义；GPTKB 2.0 的消歧使知识图谱更稠密（如 Eurozone memberOf 实体从 365 降至 30）。

## 7. 优点

- **方法创新**：首次系统性地在 LLM 原生 KB 构建中同时解决同形异义和同义异形两个方向的问题，而传统聚类方法只能处理同义异形。
- **"上下文引导"设计精巧**：抽取时的实体描述、NER 时的来源三元组、NED 时的候选描述均作为消歧上下文，使 LLM 能在无外部标识符的情况下做出准确判断。
- **守卫式并行化**：巧妙解决了"并行消歧导致重复新建"的全局耦合难题，兼顾了规模与精度。
- **两轮 NED 分工合理**：第一轮解决大多数常规消歧，第二轮针对高密度同形异义做聚焦处理，消融实验证明了其必要性。
- **成本和缓存的精细分析**：提供了详尽的 token/cost 分布和边际成本递减证据，对后续工作者有实用参考价值。
- **开源可查**：提供在线浏览和 SPARQL 端点（https://gptkb.org/），支持细粒度消歧决策可视化与聚合查询。
- **评估较严谨**：同时使用人工与 LLM 双轨评估，并设置"无描述"的严苛裁判条件作为下限估计。

## 8. 不足与局限

- **缺乏溯源**：三元组未附带参考文献或出处，无法提供信任依据；事后补引用在大规模上依然困难。
- **规模仍远小于 Wikidata**：虽然成本可控（$6,992），但覆盖仍有限；作者也指出这一定程度上有失公平（Wikidata 含大量模板化记录且投入达百万美元量级）。
- **时间静态性**：KB 反映模型训练时的知识，包含截止日期、过时观点和错误；更新需重跑管道或设计专门的刷新机制。
- **信息建模局限**：LLM 将 n 元关系编码为参数化二元谓词（如 `distanceToDresden`、`adjacentTimeZoneWest`），产生大量细粒度关系，存在一定程度的欠规范化。
- **同义异形拆分评估偏差**：只能检测"嵌入相似"的重复，表面形式差异很大的重复可能漏检，真实重复率可能略高于报告值。
- **实体的 Wikidata 新颖性仅基于 1,000 样本验证**，存在统计波动；新颖实体子集的可验证性（90.5%）低于 KB 整体（92.3%），提示长尾区域幻觉风险略高。
- **潜在偏见与毒性**：KB 内容完全来自 LLM 参数化知识，可能继承训练数据中的社会偏见、地域偏差（如 86k 美国实体 vs 1k 中国实体）甚至毒性信息。
- **商业 API 依赖**：方法依赖特定商业模型（GPT-5.1/mini），可复现性和模型更新带来的波动性未充分讨论。
