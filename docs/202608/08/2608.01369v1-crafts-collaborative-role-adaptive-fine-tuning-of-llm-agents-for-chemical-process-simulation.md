## 摘要
构建可执行的化工过程模型仍然需要大量人工操作。化学工程师将未明确指定的请求转化为关于单元操作、热力学、物流、规格、自由度（DoF）、初始化、求解器修复和优化的耦合决策；一个错误就可能导致模型失效。CRAFTS通过将模拟构建分解为分配给七个有界角色的有界子任务，并在阶段之间设置确定性的IDAES/Pyomo门控，来模拟化学工程师的分阶段工作流程。给定自然语言请求、工艺流程图（PFD）证据和精选的化学工程知识，输入理解与意图模块恢复需求、约束和过程语义；视觉、拓扑和规格专家将其转化为类型化的模拟器契约；调试与优化模块支持有界修复和符合条件的优化。对三个模式关键的角色（视觉、拓扑和规格）进行微调，而其余角色使用未微调的Qwen。由此产生的VisualGraphIR、TopologyIR、SpecIR、BuildPlan和SolveReport揭示了单元、端口、热力学、数值和执行决策。兼容的构造函数、物性包和运行器仅在语义工件通过工程门控后才被附加。我们引入了OpenIDAES-450，一个包含450个案例的IDAES过程模拟数据集，并在其冻结的82案例留出分割上评估完整的七角色LangChain/LangGraph工作流的求解和符合条件的优化。CRAFTS完成了91.5%案例的规定验证和执行契约，并实现了单元、物流和有向连接F1分数分别为0.815、0.791和0.782。这些结果证明了角色专业化、类型化中间表示和确定性工程门控对于可靠自动化过程模型构建的有效性。

## Abstract
Constructing an executable chemical-process model remains manually intensive. Chemical engineers translate underspecified requests into coupled decisions about unit operations, thermodynamics, streams, specifications, degrees of freedom (DoF), initialization, solver repair, and optimization; one error can invalidate the model. CRAFTS mirrors the staged workflow of chemical engineers by decomposing simulation building into bounded subtasks assigned to seven bounded roles, with deterministic IDAES/Pyomo gates between stages. Given a natural-language request, process flowsheet diagram (PFD) evidence, and curated chemical-engineering knowledge, Input Understanding and Intent recover requirements, constraints, and process semantics; visual, topology, and specification specialists translate them into typed simulator contracts; and Debug and Optimization support bounded repair and eligible optimization. Fine-tuning is applied to the three schema-critical visual, topology, and specification roles, while the remaining roles use untuned Qwen. The resulting VisualGraphIR, TopologyIR, SpecIR, BuildPlan, and SolveReport expose unit, port, thermodynamic, numerical, and execution decisions. Compatible constructors, property packages, and runners are attached only after semantic artifacts pass engineering gates. We introduce OpenIDAES-450, a 450-case IDAES process- simulation dataset, and evaluate the complete seven-role LangChain/LangGraph workflow through solve and eligible optimization on its frozen 82-case held-out split. CRAFTS completes the prescribed validation and execution contract for for 91.5% of cases and achieves unit, stream, and directed-connection F1 scores of 0.815, 0.791, and 0.782. These results demonstrate the effectiveness of role specialization, typed intermediate representations, and deterministic engineering gates for reliable automated process-model construction.

## 1. 论文的核心问题与整体含义

- **研究背景**：化学过程模拟（如 Aspen Plus/HYSYS）是化工设计与优化的重要工具，但构建一个**可执行的化工过程模型**至今仍高度依赖人工。化学工程师必须把模糊的、不完整的自然语言请求转化为一系列**强耦合的工程决策**，包括：单元操作选择、物流拓扑、热力学模型与物性包、操作规格、自由度（DoF）闭合、初始化策略、求解器诊断与修复、优化设置等。其中任何一个环节出错都可能导致整个模型失效。
- **核心痛点**：
  - 现有商业模拟器（如 Aspen Plus/HYSYS）是**黑盒**的，不暴露方程、变量、约束和求解状态，难以自动诊断与修复；
  - 现有 LLM 智能体方法大多依赖商业闭源模型和商业模拟器，部署受限、透明度低、可复现性差；
  - 现有方法缺乏**结构化的中间表示**和**工程知识约束**，生成的流程图往往在拓扑、热力学、规格、求解器契约上不一致。
- **论文含义**：文章提出 **CRAFTS**（Collaborative Role-Adaptive Fine-Tuning of LLM Agents），将化学工程师的分阶段工作流程镜像到多智能体系统中：将建模任务分解为七个有界角色，并用**确定性工程门控**衔接各阶段，从而在不替代工程师判断的前提下，实现**可靠、可审计、可复现的自动化过程建模**。

## 2. 论文提出的方法论

### 2.1 总体架构
- CRAFTS 将模型构建分解为**受限子任务**，每个子任务由专门的 LLM 角色负责，各阶段之间通过**确定性 IDAES/Pyomo 门控**衔接。
- 输入：自然语言请求 `ri` + 可选 PFD 图像证据 `pi` + 精选化工知识 `K` + 已验证的模拟器能力 `C`。
- 输出：一组类型化中间工件 `Ai = {Gi, Vi, Ti, Si, Bi, Ei, Oi}`，包括需求解释、VisualGraphIR、TopologyIR、SpecIR、BuildPlan、SolveReport 及可选的优化工件。

### 2.2 七个角色
| 角色 | 功能 | 是否微调 |
|---|---|---|
| Input Understanding | 恢复需求、约束、过程语义与歧义 | 否（Qwen） |
| Intent Router | 将需求映射到化工概念与过程族 | 否（Qwen） |
| Visual Descriptor | 将 PFD 图像转换为 VisualGraphIR | **是（Qwen3-VL-8B + LoRA）** |
| Topology Agent | 生成 TopologyIR（单元、端口、物流、物性包） | **是（Qwen2.5-Coder-7B + LoRA）** |
| Specification Agent | 生成 SpecIR（操作目标与 DoF 闭合） | **是（Qwen2.5-Coder-7B + LoRA）** |
| Debug Agent | 读取失败诊断、定位责任层、执行有界修复 | 否（Qwen） |
| Optimization Agent | 提出优化目标、决策变量与约束 | 否（Qwen） |

### 2.3 关键机制
- **确定性格子**：
  - 表示层门控：验证工件 schema、实体一致性、必要关系；
  - 编译层门控：验证单元可用性、端口兼容性、物性包支持、图连通性、规格目标；
  - 运行时门控：验证模型构建、DoF 闭合、初始化、求解器终止、物理一致性、优化可行性。
- **有界修复**：失败时定位到具体工件阶段而非重新生成整个模型；保留已验证的中间状态，用白名单修复策略进行局部修复；超出修复预算则 fail-closed。
- **类型化中间表示**：VisualGraphIR、TopologyIR、SpecIR 等是显式的、可检查的工程状态，而非自由文本；确定性编译器将验证通过的结构工件编译为可执行的 IDAES/Pyomo 模型。
- **公式**：
  - 工件生成：`Ai = f(xi, K, C) = {Gi, Vi, Ti, Si, Bi, Ei, Oi}`；
  - 编译：`Bi = compile(Ti, Si, C)`；
  - 结构指标：宏 F1（单元 UC、物流 SC、有向连接 CC）；
  - 工作流成功：`Wi = Π zi,s`，`WS = 100/N Σ Wi`。

### 2.4 核心设计思想
> 将**灵活的 LLM 推理**与**确定性的工程执行**分离：LLM 负责阶段性的工程推理，类型化工件作为共享的、可检查的状态，使确定性门控能够在信息传播下游之前验证结构、物性和数值一致性。

## 6. 论文的主要结论与发现

- **角色专业化 + 类型化中间表示 + 确定性门控**的组合是可靠的自动化过程建模的有效途径：CRAFTS 在 82 例冻结测试集上达到 91.5% 的工作流成功率，UC/SC/CC 宏 F1 分别为 0.815/0.791/0.782，在所有对比中取得最佳结果。
- **关键挑战不在单元识别，而在关系结构保持**：SC 和 CC 的提升幅度（分别 +0.427 和 +0.308）远大于 UC（+0.244），说明保持物流身份、有向端口连接、物性域一致性和数值规格闭合才是可执行模型的关键。
- **局部微调优于统一商业后端**：在相同角色图和评估协议下，本地角色自适应 Qwen 配置的 WS 超过 GPT-5 mini 36.6 个百分点、超过 Claude Sonnet 4.6 46.4 个百分点、超过 Gemini 3.5 Flash 63.5 个百分点。
- **每个组件都不可或缺**：消融表明，去掉任意一个组件（微调、知识、视觉、阶段分离或调试）都会导致 WS 大幅下降（从 91.5% 降至 0–36.6%）。
- **调试是内在需求**：75/82 例至少需要一次调试交互，说明迭代式诊断是化工过程建模的本质特征，而非可选的附加功能。
- **开放白盒基底是可行路径**：IDAES/Pyomo 的可检查性使局部化验证与修复成为可能，这是商业黑盒模拟器难以实现的。

## 7. 优点

- **问题分解符合领域实践**：将化工建模分解为解释、拓扑、规格、编译、求解、调试和优化等阶段，镜像了化学工程师的真实工作流，而非通用的 LLM 编排模式。
- **类型化中间表示**：VisualGraphIR / TopologyIR / SpecIR 等工件将工程决策显式化，使确定性门控可验证、可审计、可修复，避免黑盒生成的不可控性。
- **确定性门控 + 有界修复**：灵活推理与确定性执行分离，失败时只在责任层修复，保留已验证中间状态，极大减少级联错误。
- **本地可部署**：使用本地 Qwen 系列模型 + LoRA 微调，不依赖商业 API，适合工业场景的私有化部署，也避免数据出域风险。
- **开放基准**：贡献 OpenIDAES-450 数据集（450 例 + 冻结的 82 例测试集 + 完整工件和执行痕迹），为后续研究提供了可复现的比较基准。
- **公平的评估协议**：所有方法在相同的 82 例冻结测试集、相同的分母、相同的角色接口和工件事务下比较，降低了评估偏差。
- **多模态支持**：Visual Descriptor 处理 PFD 光栅输入，涵盖符号识别、方向、分支与循环线索，并显式记录不确定度。

## 8. 不足与局限

- **测试规模有限**：82 例冻结测试集相对较小，且全部来自 IDAES 已验证的能力面；扩展到更大规模工业流程、更多样化物性模型和更复杂的优化场景仍需验证。
- **结果统计强度不足**：报告了点估计和单个 Wilson 区间，但未提供多次运行的标准差、显著性检验或多种子稳定性分析，可能影响结论的稳健性。
- **基线重实现偏倚**：架构/编排框架控制的“风格”重实现可能无法完全还原原系统的能力，既可能低估也可能高估基线；统一模型控制未披露 API 解码参数细节。
- **消融效果极端**：移除 ChE 知识后 WS 降为 0%，这一极端结果可能反映测试集对该知识的高敏感性，也可能暗示模型对显式知识的依赖过强、泛化能力有限。
- **未能覆盖完整工业场景**：当前聚焦于流向图构建与稳态求解，未涉及动态模拟、大规模非线性优化、多目标优化、不确定性量化等更复杂的工程场景。
- **算力细节不透明**：未报告 GPU 数量、总训练时长、推理延迟、API 调用成本等，不利于他人复现成本估算。
- **局限性声明**：作者也承认 CRAFTS 的评估局限于 OpenIDAES-450 所代表的已验证 IDAES 能力面，更广泛的过程族、物性模型和优化设置有待未来探索。
