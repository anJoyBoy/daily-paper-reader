## 摘要
PyOMES是一个基于Python的开源建模环境，用于（生物）化学过程模拟，旨在简化动态（包括稳态）过程的建模。这是以通用化、模块化的方式完成的，以便在单一建模框架下对广泛的生物、化学和生物化学系统进行建模。PyOMES旨在让广泛的用户都能使用——从建模经验较少的用户（如实验人员和学生）到经验丰富的专业用户。本文介绍了PyOMES软件，包括其设计、架构和愿景的概要。随后提供了用例，以展示PyOMES在多种（生物）化学过程建模场景中的适用性。将预测结果与现有基准软件（如PHREEQC）进行比较，证明了该软件包的稳健性。最后，总结了PyOMES软件包的未来发展方向——强调其作为统一建模框架的建立，以及未来在社区驱动改进方面的潜力。

## Abstract
PyOMES is a Python-based, Open-source Modelling Environment for (bio)chemical process Simulation that aims to simplify the modelling of dynamic (including steady state) processes. This is done in a generalied, modular way to facilitate modelling a broad range of biological, chemical, and biochemical systems under a single modelling framework. PyOMES has been built to be accessible to a broad range of users - ranging from those with little modelling experience, such as experimentalists and students, through to more experienced power-users. Here, an introduction is provided to the PyOMES software including a summary of the design, architecture and vision. Use cases are then provided to demonstrate applicability of PyOMES to a number of (bio)chemical process modelling scenarios. Comparisons of predictions against existing benchmark software (i.e. PHREEQC) demonstrate the robustness of the package. Finally, a summary is provided of future directions for the PyOMES package - highlighting its establishment as a unified modelling framework and its potential for community-driven improvement as future developments.

## 1. 核心问题与整体含义（研究动机与背景）

（生物）化学过程的计算建模长期面临**结构性挑战**：建模所需知识横跨热力学、反应动力学、传质、控制理论等多个学科，但缺乏能够将这些学科整合到同一框架中的软件基础设施。这使得广大实验人员、学生等非建模专业人员难以使用计算模拟来辅助研究，限制了建模方法在实验设计、过程控制和数字孪生等场景中的推广。

论文指出，现有工具（如 Excel 和脚本实现）在模型复杂度增加时难以维护、调试和复用；与此同时，像 pH、气体传质等变量在许多生物/化学过程中至关重要，却因现有建模软件的限制而被实验人员所忽视。为解决这一问题，论文提出了 **PyOMES**（Python-based, Open-source Modelling Environment for (bio)chemical process Simulation）——一个基于 Python 的开源建模环境，旨在以通用、模块化的方式，在单一框架下支持广泛的生物、化学和生化系统的动态（含稳态）过程模拟。

## 2. 方法论

### 2.1 核心设计思想

PyOMES 采用**面向对象编程**方法，将（生物）化学过程划分为以下核心对象：

- **Simulation**：负责运行整体模拟，采用控制体积（Control Volume）方法。
- **ControlVolume**：物理空间的独立单元，是所有材料特性和状态的基础模块，可自动进行质量、电荷和元素守恒检查。
- **Phase**：提供给定控制体积内的热力学和状态核算的“事实源”。
- **Species**：描述模型中的化学物质种类，确保质量平衡和反应计量正确。
- **Reaction**：描述控制体积内的瞬态现象，包括化学反应和传质现象。

### 2.2 模块化设计原则

- **概念模块化**：通过 Python 的 `Protocol` 机制实现，定义各建模领域之间交互、传递信息的标准化架构骨架，使供默认实现保持精简的同时允许高级用户自定义扩展。
- **空间模块化**：以控制体积范式为核心，将物理空间分解为多个具有预定义特征（如分子状态、物化性质、相态）的独立单元，通过传输链接可组合成多隔室系统（如消化器串联、色谱柱、分层发酵罐）。

### 2.3 热力学框架

通过独立的 `ThermoFramework` 对象表示模型的热力学假设，统一计算活度、活度系数和平衡关系。该对象同样遵循 Protocol 扩展机制，使热力学模型作为一个可替换的独立选择。

### 2.4 质量传输现象——三维分解

- **物理化学维度**：区分物理传质（空间移动，无化学变化）与化学传质（化学键的生成与断裂）。
- **空间维度**：区分控制体积内部（intra-CV）与控制体积间（inter-CV）的传质。
- **时间维度**：区分为动态传输（用 ODE 求解）与瞬时传输（用代数方程描述，称为“瞬时传质平衡”）。

### 2.5 微分方程求解——双轴求解器架构

- **StepSolver 协议**（控制体积内部）：允许为单个 `ControlVolume` 分配特定的 ODE 求解算法。
- **SystemSolver 协议**（控制体积间）：处理多控制体积系统中跨隔室流动的求解策略，特别针对涉及快速平衡反应和慢速动力学反应同时存在的**微分代数方程（DAE）**问题。

### 2.6 关键数学表述

- **瞬时平衡**按 log K 形式并结合质量平衡和电荷平衡方程，用 Newton-Raphson 数值求根法求解。
- **活度系数**采用 Davies 模型：

  \( \log_{10} \gamma_i = -A z_i^2 \left( \frac{\sqrt{I}}{1+\sqrt{I}} - 0.3I \right) \)

- **气液传质动力学**采用一阶速率过程（kLa 为体积传质系数）：

  \( \frac{dn_{L,i}}{dt} \frac{1}{V_L} = k_L a (C^\*_{L,i} - C_{L,i}) \)

- **发酵动力学**采用 Monod 型动力学（双底物限制）：

  \( \mu = \mu_{\max,S} \left( \frac{S}{K_S + S} \right) \left( \frac{O_2}{K_{O_2} + O_2} \right) \)

## 3. 实验设计

论文设计了**三个递进复杂度**的用例来验证 PyOMES 的功能：

### 用例 1：水溶液 pH 预测
- **场景**：对 KH₂PO₄ 和 NH₄Cl 的混合水溶液（0–100 mmol/L，25°C），预测平衡 pH。
- **假设**：盐完全溶解解离，考虑水自电离、铵解离和磷酸逐级质子化等瞬时平衡反应。
- **基准**：以 **PHREEQC** 软件为基准，对相同体系进行对比。

### 用例 2：气液平衡（CO₂ 吸收）
- **场景**：初始纯水与大气（含 400 ppm CO₂）接触，模拟 pH 随时间的动态变化。
- **假设**：大气体积相对无限大，气相消耗可忽略；气相到液相的传质按 kLa 的一阶过程进行；水中碳酸平衡按集总模型处理。
- **参数设置**：基准 kLa = 96 h⁻¹，另对 kLa 在 0.1–1000 h⁻¹ 范围内进行变参数模拟。

### 用例 3：好氧发酵 CSTR
- **场景**：大肠杆菌在以醋酸为碳源的 2 L 连续搅拌反应器（CSTR）中的稳态好氧生长。
- **关键模型**：包括不可逆反应计量（按质量守恒确定系数）、Monod 双底物限制动力学（醋酸和溶解氧）、气液传质和水相平衡。
- **参数扫描**：稀释率 D 从 0.00 到 0.295 h⁻¹ 变化，各运行至稳态后比较稳态生物量、底物浓度和体积生产力。

### Benchmark 与对比方法
- 与 **PHREEQC**（通过其 Python 封装 PhreeqPython，使用基于 WATEQ Debye-Hückel 活度校正的 `vitens.dat` 数据库）进行 pH 预测对比。

## 6. 主要结论与发现

- **功能验证成功**：PyOMES 正确预测了水溶液 pH 随组分浓度的变化趋势（包括溶液非理想性导致的非线性曲率），并能捕捉 CO₂ 溶解导致的 pH 随时间下降的动态过程，最终收敛到理论平衡值。
- **与基准软件高度一致**：PyOMES 与 PHREEQC 的 pH 预测最大偏差 <0.001，验证了数值实现的可可靠性。
- **性能具有竞争力**：PyOMES 在 pH 计算上比 PHREEQC 快约 50%，可支持大规模蒙特卡洛等计算密集型应用。
- **参数影响可量化**：kLa 从 0.1 到 100 h⁻¹ 的变化可使气液平衡特征时间跨越约 4 个数量级（从分钟到天），展示了该工具在设计实验和评估方案（如储藏稳定性）方面的决策支持价值。
- **CSTR 行为符合预期**：在稀释率接近临界值（洗出条件）时，生物量浓度下降、底物浓度上升，生产力出现最大值，与经典生物反应器理论一致。
- **性能瓶颈可预期**：CSTR 模拟的耗时在稀释率接近洗出条件时急剧增长，反映了系统动态时间尺度变慢这一已知过程特性。

## 7. 优点

- **面向广泛用户的三级设计**：专业用户可深度定制，普通用户可借助快捷函数快速建模，初学者可低门槛上手。
- **真正的模块化架构**：通过 Protocol 机制实现概念模块化，通过 ControlVolume 实现空间模块化，使复杂模型可由简单模块组合而成，提升了可读性和可复用性。
- **热力学假设统一且可交换**：ThermoFramework 将热力学模型封装为单一可替换模块，保持全模型一致性。
- **守恒检查内置**：每个 ControlVolume 自动进行质量、电荷和元素守恒验证，有利于模型纠错。
- **与成熟基准软件进行了定量对比**：验证了数值可靠性，且运行性能优异（快速且可扩展）。
- **开源许可（AGPLv3）托管于 GitHub**：支持社区驱动的发展模式，具有明确的可持续演进路线。
- **支持从简单到复杂的递进式学习**：三用例从平衡计算到动态传质再到生物反应器的组织方式对新手友好。

## 8. 不足与局限

- **基准验证覆盖有限**：仅 pH 预测与 PHREEQC 进行了定量对比；气液传质和发酵模拟缺乏独立的基准数据或实验数据验证。
- **活度模型不一致**：PyOMES 采用 Davies 模型，而 PHREEQC 采用 WATEQ Debye-Hückel 模型，两者对比虽结果一致但并非严格同模型对比，存在一定的基准偏差风险。
- **实验覆盖场景有限**：未展示多隔室模型、控制回路集成、更复杂的传质模型等论文宣称支持的高级功能。
- **CSTR 运行时间统计不足**：稀释率扫描的耗时数据仅 n=1，代表性有限。
- **缺乏不确定性分析**：未对模型参数（如 kLa、Monod 参数、热力学常数）的不确定性进行传播分析。
- **文档和生态成熟度**：作为新发布的软件，教程、API 文档、社区案例库相对有限；依赖 SciPy 等外部库的版本兼容性未见明确说明。
- **适用范围**：主要面向理想或较简单混合的反应器系统，对于非理想流动、复杂几何结构或固相/多相系统的描述能力尚未得到验证。
