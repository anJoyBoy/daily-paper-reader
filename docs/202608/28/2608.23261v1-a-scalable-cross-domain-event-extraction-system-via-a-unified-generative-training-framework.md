## 摘要
事件抽取是信息抽取的基础。以往的方法通常将事件检测和论元抽取分开，或依赖于特定数据集的设计，限制了可扩展性和跨领域泛化能力。我们提出了一种统一的生成式序列到序列框架，该框架联合执行事件抽取子任务，并支持管道式和端到端两种配置。我们在多个不同领域的事件数据集上对预训练语言模型进行微调，使单一模型能够保留领域特定语义，同时在大规模和不断演化的标签空间上进行泛化。我们通过一个面向研究人员和实践者的基于Web的应用来展示这些能力。该平台支持文档上传、模式感知的事件抽取、触发词和论元的可视化，以及跨领域不同抽取配置的比较。

## Abstract
Event extraction is fundamental to information extraction. Prior approaches often separate event detection and argument extraction or depend on dataset-specific designs, limiting scalability and cross-domain generalization. We propose a unified generative sequence-to-sequence framework that performs event extraction subtasks jointly and supports both pipeline and end-to-end configurations. We fine-tune pretrained language models on multiple event datasets across diverse domains, enabling a single model to retain domain-specific semantics while generalizing over large and evolving label spaces. We demonstrate these capabilities through a web-based application tailored for researchers and practitioners. The platform supports document upload, schema-aware event extraction, visualization of triggers and arguments, and comparison of different extraction configurations across domains.

# 论文深度总结：基于统一生成式训练框架的可扩展跨领域事件抽取系统

## 1. 核心问题与研究动机

事件抽取（Event Extraction, EE）是信息抽取领域的基石任务，旨在将非结构化文本转化为结构化事件表示，为知识库构建等下游应用提供支撑。传统事件抽取通常被拆分为两个子任务：

- **事件检测（ED）**：识别触发词（trigger）并分类事件类型。
- **事件论元抽取（EAE）**：抽取论元并标注其语义角色（如参与者、地点、时间等）。

**现有方法的痛点**：

- 多采用流水线式架构，为每个子任务设计专属模型，缺乏统一性；
- 高度依赖特定数据集的标注模式和事件定义，跨领域泛化能力弱；
- 面对大型或不断演化的事件类型标签空间时，伸缩性严重不足；
- 基于大型语言模型的统一抽取框架虽有探索，但通常依赖复杂提示词编码完整事件模式，且计算开销高，难以扩展到大规模事件本体。

**核心研究问题**：如何构建一个统一的、可扩展的跨领域事件抽取系统，使其能够在多数据集、多领域中无需大量重新工程设计即可稳健运行？

## 2. 方法论：统一生成式训练框架

### 2.1 核心思想

本文提出将事件抽取完全建模为一个**统一的序列到序列（sequence-to-sequence）生成任务**，基于 T5 架构，使单一模型能够同时（或按需分别）处理事件检测与论元抽取子任务，兼容流水线（pipeline）与端到端（E2E）两种推理模式。

### 2.2 关键技术细节

**（1）统一任务格式化**

- 所有事件抽取子任务（触发词识别、事件类型分类、论元抽取）被统一转换为 text-to-text 形式；
- 每个数据集映射到特定的任务提示词（task prompt）和对应的输出模式（output pattern），从而标准化异构数据集的输入输出格式。

**（2）领域/数据集标识条件化**

- 在输入序列开头拼接 **数据集名称 + 任务前缀 + 输入文本**，格式为 `{dataset name} + {task prefix} + {text}`；
- 数据集名称同时充当领域指示符和模式（schema）引导；
- 这一设计使模型可同时在多个数据集上联合训练，保留领域专门语义的同时实现跨域泛化。

**（3）双模式推理**

- **流水线模式**：先识别触发词 → 再分类事件类型 → 最后抽取论元（按事件类型对应的论元角色）。该模式提供对每个阶段的显式控制，利于可解释性和分阶段评估。
- **端到端模式**：联合执行触发词识别和事件类型分类，简化推理、减少错误传播；完全端到端（含论元抽取）也可行，但输出空间复杂度更高，更具挑战性。
- 两种模式共用同一训练好的模型，仅通过不同的输入/目标模板切换。

### 2.3 框架创新点

- 任务条件化（task-only conditioning）被扩展为"任务+领域"双重条件化；
- 无需为每个数据集重新设计架构，仅需指定领域名称即可让模型预测到对应领域的事件类型；
- 单模型联合训练支持**大规模演化标签空间**，兼顾跨域共享表示与领域专属语义。

## 6. 主要结论与发现

1. **统一生成式框架可行**：将事件检测与论元抽取统一为序列到序列任务，单一 T5 模型即可处理多个领域的事件抽取，无需子任务专属模型。
2. **领域标识条件化有效**：通过在输入中拼接数据集名称，模型能够同时学习跨域共享表示和领域专属语义，适应大规模演化标签空间。
3. **双模式设计灵活实用**：流水线模式便于阶段级控制和解释，E2E 模式简化推理减少错误传播，两模式可在同一模型上切换，互为补充。
4. **Web 应用提升可用性**：该系统为研究人员提供了从文档上传到结构化事件输出的完整工作流，支持模式感知标注、可视化对比与多模式混合使用（如 Stage 1 可分别运行流水线和 E2E 模式并合并结果）。
5. **跨域模型的实际价值**：在低资源领域，跨域训练的模型比单领域模型具有更好的泛化能力，有助于缓解流水线抽取中的错误传播。

## 7. 优点与亮点

### 方法论层面

- **真正统一的建模框架**：将 ED 与 EAE 统一为 text-to-text 格式，消除子任务模型碎片化；
- **领域感知的条件化输入设计**：`数据集名+任务前缀+文本`简单有效，以极小的工程代价解决跨域适配问题；
- **灵活的双模式推理**：流水线与 E2E 互补，兼顾可解释性与效率，且无需重新训练；
- **可扩展性突出**：面对新增数据集/领域，只需定义新的提示词与输出模板，无需重新设计架构；
- **基于 T5-base 的轻量级方案**：相对于依赖大模型的方法，计算需求显著降低，更便于实际部署。

### 系统层面

- **两阶段抽取界面设计合理**：允许用户灵活组合流水线/E2E 输出，关注错误传播问题；
- **可视化对比功能突出**：精确偏移、对齐高亮、事件卡片等设计支持细粒度结果审查；
- **多模式标注能力**：同一文档可反复用不同事件模式标注，生成可复用的分层 JSON 产物，便于下游分析。
