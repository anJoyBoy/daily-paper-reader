## 摘要
大型语言模型的最新进展催生了一类新的智能体数据科学系统，使用户能够通过自然语言完成复杂的数据科学工作流。尽管这些系统可以显著减少人工投入，但当出现故障或意外输出时，诊断其行为并引导推理过程仍然困难。我们提出了MUSE，一个交互式元智能体，通过以下方式增强用户对智能体数据科学系统的理解和控制：（1）动态地将低层执行轨迹重构为多个语义层级，支持从高层概览到低层实现细节的导航；（2）使用户能够在上下文中引用特定工作流步骤，提出基于上下文的问题、提供反馈并修改有问题的步骤，而无需手动定位相关执行历史；（3）通过呈现可疑步骤供检查、为修复过程提供支架、以及将用户的修复意图转化为对底层智能体的情境化指令，来支持混合主动引导。在一项受试者间研究（n=15）中，MUSE提高了任务效率，并增强了用户理解和引导智能体数据科学工作流的信心。

## Abstract
Recent advances in large language models have enabled a new class of agentic data science systems that allow users to complete complex data science workflows through natural language. Although these systems can significantly reduce manual effort, it remains difficult to diagnose their behavior and steer the reasoning process when failures or unexpected outputs occur. We present MUSE, an interactive meta-agent that enhances user understanding and control of agentic data science systems by (1) dynamically restructuring low-level execution traces into multiple semantic levels that support navigation from high-level overviews to low-level implementation details; (2) enabling users to reference specific workflow steps in context to ask grounded questions, provide feedback, and revise problematic steps without manually locating relevant execution history; and (3) supporting mixed-initiative steering by surfacing suspicious steps for inspection, scaffolding the repair process, and translating user repair intent into contextualized instructions for the underlying agent. In a between-subjects study (n = 15), MUSE improved task efficiency and increased users' confidence in understanding and steering agentic data science workflows.

  - 现有工具（如 LangSmith、Phoenix、DevUI）主要面向专业智能体开发者，暴露的是低层消息、内部状态、工具调用等细粒度信息，对非专家用户而言信息过载；

## 2. 方法论：MUSE 的核心思想与关键技术

MUSE 是一个运行于底层数据科学智能体之上的**元智能体**，由四个核心层组成：

### 2.1 摘要层（Summarization Layer）
- **执行轨迹捕获**：对智能体运行时进行插桩，捕获五类日志——推理轨迹、工具调用、代码执行、信号/状态、中间产物。
- **语义分块**：利用底层智能体在完成每个阶段时发出的 `[STEP_COMPLETE]` 完成标记，将原始日志流动态切分为语义块（semantic chunk），无需 LLM 推断边界。
- **五级语义表示**（L1–L5）：
  - L1：阶段标题；
  - L2：自然语言摘要；
  - L3：有序子步骤列表；
  - L4：包含文件、命令、参数等细节的动作列表；
  - L5：底层原始轨迹（代码、命令、工具输出）。
- 使用 Gemini API 配合 JSON schema 约束实时生成，所有 LLM 调用 temperature=0 以保证可重复性。

### 2.2 监控层（Monitoring Layer）
- **警告检测**：基于预定义的启发式规则（从 MLE-Bench 的 20 个任务中总结而来），检测两类异常：
  - 数据级警告（如过度删除数据、覆盖原始数据、未验证的 schema 假设、缺失数据未检查等 13 类）；
  - 智能体级警告（如推理–行动不匹配、任务偏离、过早终止等 7 类）。
- **本地化警告**：警告直接标记在对应的步骤卡片上，悬停查看解释，支持"为何警告"追问和后续修复操作。

### 2.3 验证层（Verification Layer）
- **上下文引用**：用户可将工作流步骤拖拽到聊天框中提问，MUSE 自动解析该锚点并检索相关脚本、报告、产物作为提示证据，无需用户手动拼装上下文。
- **脚手架式验证**：用户高亮输出内容并选择"Help me verify"，MUSE 结合所选输出、关联文件和会话上下文，生成 3–5 个具体可选的验证方案，用户选择后 MUSE 在沙箱内自动生成并执行验证脚本（不修改正式流水线产物），返回验证通过/失败/不确定的结论及证据文件。

### 2.4 引导层（Steering Layer）
- **脚手架式修复**：当步骤被标记警告时，MUSE 提供警告解释、可点击的文件引用和修复建议选项，用户选择合适的修复方案后，MUSE 自动将修复请求、受影响步骤和警告上下文合并为情境化指令，传递给底层 DS 智能体执行。
- 底层智能体为基于 Claude Agent SDK 的 ds-pipeline 技能编排系统，包含七个固定阶段（目标理解→数据问题检测→清洗→EDA→特征工程→基线建模→最终报告），MUSE 为只读辅助智能体，需要执行修改时再交还控制权。

## 3. 实验设计

### 3.1 预研究（Formative Study）
- 7 名数据科学家参与，使用 MLE-STAR 和 Cursor 完成两个 Kaggle 任务（California Housing、Optiver），通过出声思考和半结构化访谈提炼出 4 项用户需求（N1–N4）。

### 3.2 正式用户研究
- **被试**：15 名参与者，来自商业分析、计算机科学、金融、建筑、物理等 11 个不同学科背景，分为三组，每组 5 人。
- **实验条件**（组间设计）：
  - **条件 A（Raw Logs）**：直接暴露底层智能体的原始执行输出（代码、推理痕迹、工具调用等），类似现有智能体执行界面；
  - **条件 B（DiLLS）**：模拟现有 DiLLS 系统的三层摘要界面，同样显示警告但警告不可就地操作，用户需切换到外部编辑器手动修复；
  - **条件 C（MUSE）**：完整版的 MUSE 系统。
- **任务**：6 个 Kaggle 任务（食物配送时间预测、需求预测、电信客户流失、客户终身价值、MovieLens 推荐、新闻流行度预测），覆盖回归、分类、时序、推荐等场景，分为易、中、难三档。
- **模型**：弱模型 Claude Haiku 4.5 与强模型 Claude Opus 4.6 混合使用，条件和任务分配做反平衡，参与者不知道使用哪个模型。
- **测量指标**：任务完成时间、成功率、重启次数、NASA TLX 负荷、信心评分、五项主观对比评分（S1–S5）、交互行为日志。
- **统计方法**：ANOVA + Tukey HSD 事后检验；定性数据采用归纳主题分析。

## 6. 主要结论与发现

1. **任务效率**：条件 C 平均完成时间 17 分钟，比条件 A 减少 35%（p = .035），比条件 B 减少 9%（不显著）；条件 A 成功率仅 50%，条件 B 和 C 均为 90%。
2. **用户信心**：条件 C 用户对最终结果信心最高（5.80 vs. 2.60 vs. 4.20，p = .0265）。
3. **认知负荷**：条件 C 在匆忙感、费力程度和挫败感上显著低于其他条件。
4. **警告解决率**：条件 C 参与者平均解决 2.8 个警告，条件 B 仅 0.8 个（p = .0118）。
5. **交互模式转变**：MUSE 将监控行为从"线性搜索"转变为"局部检查"（滚动量从 147 次/任务降至 61 次/任务）；警告触发、步骤完成和修复前检查是语义级别滑块调整的主要诱因。
6. **错误类型的分布**：智能体最常见的错误是未验证的 schema 假设（56%）、缺失数据未检查（16%）、单次划分评估（12%）；弱模型比强模型多触发 27% 的警告。
7. **用户行为模式**：存在三类用户——AI 委托者（Delegators）、协作者（Collaborators）、审计者（Auditors），需要不同粒度的验证支持。
8. **专家与新手**：先前编程或智能体开发经验对任务绩效无显著影响。

## 7. 优点

1. **多级语义抽象设计**：从 L1 概览到 L5 执行迹的五层表示，兼顾了不同能力层级用户的需求，呼应"概览优先、按需缩放"的信息搜寻经典范式。
2. **混合主动式监控与干预**：MUSE 不依赖用户自行发现错误，而是主动检测警告、附上解释和修复建议，将修复过程"脚手架化"，降低非 AI 专家的参与障碍。
3. **上下文锚定交互**：拖拽步骤入聊天框的设计使提问、反馈和修复都能锚定到具体工作流节点，MUSE 自动补充相关上下文，避免用户在大量日志中手动寻找证据。
4. **行动导向的验证支持**：不只解释系统行为，还生成具体的验证方案和验证脚本，支持用户在沙箱内独立验证结果，且不污染正式管道产物。
5. **实时的并行监控架构**：MUSE 与底层智能体并行运行，用户在长耗时步骤执行期间即可提问和干预，无需等待整个流水线结束。
6. **应用价值**：实验证明其有效性和可用性，且任务设计贴近现实场景（而非经典记忆化任务如 Titanic），增强了结论的生态效度。

## 8. 不足与局限

1. **受控实验环境**：6 个 Kaggle 任务无法充分代表真实数据科学工作的复杂性和多样性；30 分钟时限也限制了任务的深度。
2. **样本代表性**：参与者多为非专业开发者，结论主要反映 MUSE 对经验较少用户的帮助效果，对专业数据科学从业者的适用性尚不确定。
3. **样本量偏小**：每组仅 5 人，组间设计下统计检验功效有限；条件 B 与 C 的部分差异（如完成时间 9% 缩减）未达统计显著，可能受样本量制约。
4. **监控层覆盖有限**：警告检测依赖预定义的启发式规则，可能无法捕捉实践中出现的更广泛的错误类型。
5. **基线对比的公平性**：条件 B 为简化的 DiLLS 模拟，可能未充分还原该工具的实际能力；条件 A 也未能完全反映真实系统中可能存在的辅助功能。
6. **任务分配与随机性**：各条件的任务和模型分配虽然反平衡，但 LLM 推理本身的随机性导致各条件警告总数略有差异（B 为 39 个，C 为 36 个）。
7. **未做组内消融**：没有分别验证摘要层、监控层、验证层和引导层各自的独立贡献，无法确定哪些功能对效率提升最关键。
8. **工程规模依赖**：MUSE 依赖底层智能体显式发出 `[STEP_COMPLETE]` 标记来切分语义块，这一设计假设在不同框架的智能体系统中可能不成立或需要额外适配。
