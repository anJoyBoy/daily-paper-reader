## 摘要
自动化机器学习（AutoML）系统在预先指定的预处理算子、学习器和超参数空间内搜索流水线：它们可以选择和调整已知组件，但无法在该空间之外生成结构。我们提出LACE，一个AutoML框架，它转而搜索完整的可执行流水线程序：进化循环维护一个由scikit-learn兼容Python类组成的种群，而大型语言模型充当变异算子。据我们所知，LACE是首个以这种方式构建通用表格流水线AutoML的框架，并在标准化OpenML任务上、在泄漏受控协议下进行评估，该协议不向生成器透露数据集身份。由于每个候选都是普通Python代码，返回的流水线及其生成过程可直接检查和编辑，而不仅仅是通过框架的模型对象。在68个OpenML分类任务上，LACE与GPT-5.4-mini组合显著优于auto-sklearn、H2O和固定XGBoost基线，与所评估的最强基于搜索的系统AutoGluon相比无显著差异，同时覆盖完整基准。较新的表格基础模型在其支持的任务子集上更准确，但应用固定的预训练预测器，而非返回可编辑的任务特定程序。因此，LACE的贡献并非原始精度，而是由代码定义的搜索空间：完整覆盖、从业者可直接复用的流水线，以及通过编辑提示词而非框架来扩展的组件集。

## Abstract
Automated machine learning (AutoML) systems search for pipelines within a space of preprocessing operators, learners, and hyper-parameters specified in advance: they can select and tune known components, but cannot produce structure outside that space. We present LACE, an AutoML framework that instead searches over complete executable pipeline programs: an evolutionary loop maintains a population of scikit-learn-compatible Python classes, and a large language model acts as the variation operator. To our knowledge, LACE is the first to formulate general tabular pipeline AutoML this way, evaluated on standardized OpenML tasks under a leakage-controlled protocol that withholds dataset identity from the generator. Because every candidate is ordinary Python, the returned pipeline and the search that produced it can be inspected and edited directly, rather than only through a framework's model objects. On 68 OpenML classification tasks, LACE with GPT-5.4-mini significantly outperforms auto-sklearn, H2O, and a fixed XGBoost baseline, with no detectable difference against AutoGluon, the strongest search-based system evaluated, while covering the full benchmark. Newer tabular foundation models are more accurate on the subset of tasks they support, but apply a fixed pretrained predictor rather than returning an editable task-specific program. LACE's contribution is therefore not raw accuracy but a search space defined by code: complete coverage, pipelines practitioners can reuse directly, and a component set extended by editing the prompt rather than the framework.

### 1. 核心问题与研究背景

- **问题：传统 AutoML 的搜索空间由预定义组件决定。** AutoGluon、auto-sklearn、H2O 等经典系统只能在预先指定的预处理算子、学习器和超参数范围内进行选择与调优，无法生成该空间之外的全新结构；TPOT 等进化系统也受限于固定算子库；TabPFN、TabICL 等表格基础模型则应用固定的预训练预测器，不返回可编辑的任务特定程序。
- **核心矛盾：** AutoML 需要兼顾"搜索能力"（能否发现空间外的结构）与"输出可用性"（结果能否被直接理解、检查和复用）。
- **LACE 的答案：** 用大语言模型（LLM）作为进化算法中的变异算子，直接在**完整可执行的 Python 流水线程序**上做种群进化搜索——搜索空间由代码定义，而非固定语法；每个候选程序本身就是可读、可改、可复用的任务特定产物。

  - `__call__(self, X)`：返回预测。
- 同时附带一句自然语言描述和可调超参数空间（默认值由生成器给出，研究中不做外部调参）。
- 约束（在提示词中要求，而非执行时强制）：仅用 scikit-learn/NumPy/SciPy/pandas；单估计器或至多 3 个学习器的集成；单一共享预处理；禁止内部交叉验证、超参数搜索或嵌套 AutoML。

#### 2.2 泄漏控制与评估协议
- 生成器只收到**粗粒度任务摘要**（任务类型、约化样本数、布尔/整数/实值特征数），**不包含**数据集名、任务 ID、特征名、目标语义、类别分布和评测指标。
- 评估器持有完整任务访问权：将每个官方训练折再分为内部训练/验证（验证比例 0.2），候选在内部验证集上打分；官方测试集**仅在最终评估时使用一次**。
- 失败候选获得最差适应度并附首个错误信息作为反馈。

#### 2.3 进化算法
- 采用 **(μ+λ) 进化策略**（μ=4 父代，λ=12 后代），LLM 为唯一变异算子，精英截断保留最优 μ 个个体。
- 运行预算 B=100 个候选（4 个初始 + 8 代×12 个后代），包含无效与超时候选。
- 后代由：均匀随机选父 + 父代码 + 其评估反馈 + 种群摘要 + 随机变异指令（共 3 条指令）生成。

### 3. 实验设计

#### 3.1 数据集与基准
- **68 个 OpenML 分类任务**（amlb-classification-all 套件），覆盖 100 到 4,898,431 个样本、4 到 10,000 个特征。
- 评估指标：67 个任务用 accuracy，1 个任务（360114）用 ROC-AUC。
- 协议：OpenML 预定义 10 折官方划分；每任务 5 次重复（种子 0–4），共 102,000 个计划候选评估。

#### 3.2 对比方法
| 类别 | 方法 |
|---|---|
| LACE 变体 | LACE(GPT-5.4-mini)、LACE(DeepSeek-V4-Flash)、LACE(Qwen3-Coder-Next 4-bit) |
| 经典搜索式 AutoML | AutoGluon-Tabular、auto-sklearn、H2O AutoML |
| 非调参基线 | 固定 XGBoost（500 棵、depth 6） |
| 表格基础模型 | TabPFN v2.5、TabPFN v3、TabICL |

- 所有方法使用相同官方划分和指标；**每个基线获得与对应 LACE 运行相同的总墙钟时间预算**（time-matched）。

#### 3.3 消融与辅助分析
- 配置消融：crossover 率、后代数、父选择机制、变异指令集（3 任务开发集）。
- 骨干模型筛选：7 个 LLM 中选出 3 个（3 任务预筛）。
- 基础模型消融：5 任务，3 条件（默认 / 安装不减提及 / 显式宣布 TabPFN 可用）。
- 审计：1,020 个最终程序的静态约束合规检查。
- 动态分析：搜索进步、序列结构多样性、祖先谱系、个体改进率。

### 4. 资源与算力

- **论文未明确提供 GPU 型号、数量或总 GPU 小时数**，仅说明：使用共享异构计算集群；每个候选评估有墙钟超时上限——重任务（≥40 万样本 / ≥1000 特征 / 样本-特征积 ≥10⁷）4 小时，其余 1 小时；整体计算成本以任务墙钟时间报告。
- 单次 100 候选运行的平均墙钟时间：最小任务约 0.7 小时，最大任务超过 240 小时（LACE 端到端，非硬件归一化）。
- 由于集群异构且未做计算平价校准，作者将其定位为"共享基础设施下的比较"，而非严格计算平价基准。

### 5. 实验数量与充分性

- **规模可观**：68 任务 × 5 重复 × 3 骨干 = 1,020 次完整运行，约 70,998 个有效候选（69.6% 有效）；4 个外部 AutoML/baseline + 2 个基础模型 + 3 个基础模型对比。
- **多角度交叉验证充分**：共同任务视图、考虑覆盖率的全基准视图、按任务规模分解、配对显著性检验（Holm 校正）、零样本 vs 进化后对比（含留出重放）、审计敏感性分析。
- **存在可指出的公平性局限**：时间匹配是"上限"而非实际使用量；集群异构；LACE 与 AutoML 基线均限制为经典非神经模型，而基础模型单独评估，组件集不同，非同一搜索空间内的等位对比；TabPFN 未完成的任务直接记为失败而非截断调整。

---

### 6. 主要结论与发现

1. **性能：** LACE(GPT-5.4-mini) 在 45 个共同任务上平均排名 4.71，显著优于 auto-sklearn、H2O 和 XGBoost，与 AutoGluon 无显著差异（68 任务共享，胜 33 负 35，p=0.66）；所有 LACE 变体完整覆盖 68 个任务。
2. **覆盖率价值：** 考虑失败惩罚后，TabPFN v2.5（仅覆盖 45 任务）排名从共同任务的第 3 跌至第 7，而 LACE(GPT) 排名略升至 4.50，与 AutoGluon（4.59）基本持平——"覆盖完整基准"是 LACE 的实质性优势。
3. **基础模型限制：** TabPFN v3 与 TabICL 在支持的任务上显著优于 LACE，但只在各自覆盖的子集上有效；TabICL 虽在 67/68 任务上覆盖，但在小数据任务上存在不可回归的失败。
4. **进化确实起作用：** 第一候选有效性为 37.6%（Qwen3）至 79.7%（GPT），最终 100% 有效；在留出官方测试数据上，193 个骨干-任务单元中 190 个改进，中位增益 2.99 个百分点（GPT 下 4.53）；该增益非 best-of-four 效应（对比初始种群最优成员仍增益 1.58）。
5. **程序多样性：** 70,998 个候选中有 65,298 个（92%）独特结构签名；73.3% 的最终程序包含多学习器集成；8.7% 直接手写 NumPy 预测组合逻辑（如 SVC 与随机森林概率加权 0.60/0.40）。
6. **搜索空间由"提示词"，而非"包可用性"决定：** 5 任务消融显示，安装但不提及 TabPFN 时生成器从未使用它；显式宣布后有 74.5%（DeepSeek）和 42.0%（GPT）的候选采用，通常作为集成组件。
7. **审计：** 约束以提示词而非强制方式施加，1,020 个终局中确认 22 个违规（GPT 骨干仅 2 个），剔除后所有统计结论不变。

---

### 7. 优点与亮点

- **以代码为搜索空间：** 摆脱固定算子语法，搜索空间由 LLM 在提示词与包约束下可生成的所有程序隐式定义，扩展组件只需修改提示词。
- **泄漏控制严谨：** 生成器只获得粗粒度摘要，官方测试集在搜索期间完全隔离，显著降低基准污染风险。
- **输出可直接使用：** 返回的是普通 Python 类，中位暴露 12 个超参数，可直接修改、复用，无需通过框架 API 反查模型对象。
- **作为"搜索方法"而非"精度尖峰"的定位清晰：** 明确承认基础模型在支持任务上更准，其贡献是覆盖率 + 可编辑程序 + 搜索空间自由度。
- **评估协议细致：** 时间匹配预算、统一官方划分、重任务更长超时的分级处理、Held-out 重放分析、违反约束的静态审计及其敏感性分析，均提高可信度。
- **进化动态分析做得深入：** 按代数报告有效性、改进速度、祖先深度、代表性运行谱系，揭示搜索持续到最后一代（中位最终改进在第 7 代）且存在早期停止空间。

---

### 8. 不足与局限

- **基准覆盖单一：** 仅表格二分类/多分类（一套 OpenML 套件），无回归、无时间序列、无图像/文本，也未与非表格的 LLM 代理（如 MLE-bench、MLAgentBench）做比较——作者将后者归为不同研究对象，但通用性仍受限。
- **无严格计算平价：** 共享异构集群、时间匹配为"上限"而非实际使用量；基础模型训练（如 TabPFN v3 的预训练成本）未计入比较，LACE 生成 100 个候选的累积评估成本可能远超 AutoGluon 等单次搜索系统的实际开销。
- **统计效能有限：** 5 次重复、单套任务划分，配对检验在部分对比上（如 vs AutoGluon）无法拒绝等价假设——作者也承认"不显著"不等于"无差异"。
- **约束执行靠提示而非强制：** 22 个已确认违规（含 5 个自制 out-of-fold、13 个四学习器集成、4 个预测时重拟）说明生成器并非完全遵守规则，且审计为定向静态分析，不能排除遗漏。
- **无外部调参：** 全部分数来自生成器默认超参数，未测量"生成结构 + 数值调优"的联合效应，可能低估 LACE 的潜力。
- **数据污染风险不能完全排除：** 粗摘要降低了 LLM 识别数据集的可能性，但公开基准出现在预训练语料中的风险只能缓解，无法消除。
- **首个候选在部分骨干上有效率低：** Qwen3 的 62.4% 初始程序无效，虽能在预算内恢复，但反映骨干质量对系统的强依赖，以及由此带来的实际计算浪费。
