## 摘要
代码性能优化是现代软件开发的一个重要方面，因为它能实现更快的响应时间和更少的资源占用。这些优化需要对底层硬件细节和并行处理的复杂性有深入理解，即使对经验丰富的开发者来说也颇具挑战。随着大语言模型（LLMs）的出现，它们生成和理解代码的能力日益增强，人们越来越有兴趣将这些模型纳入自动化代码优化流程。传统上，这种自动化涉及将源代码转换为特定领域的表示形式，可以使用网格搜索或机器学习算法进行自动调优，同时遵循严格的规则和有限的可行变换集以确保可验证性。LLMs 融入了高层代码语义，因此能够执行超越可验证自动化优化的变换。本文研究了自动化代码优化中使用的传统抽象是否能够提高并行HPC应用的LLM引导优化的性能和正确性。我们使用PolyBench基准套件对此进行了评估，并证明在我们评估的设置中，与使用既定框架创建计算流水线和优化调度相比，提供特定优化目标的LLM在生成C代码时能获得更好的实测性能和有效性比率，这表明未来的开发应探索可验证的LLM引导代码优化的替代方法。

## Abstract
Code performance optimization is a vital aspect of modern software development, as it enables faster response times and reduced resource usage. These optimizations require a deep understanding of low-level hardware details and the intricacies of parallel processing, making them challenging even for experienced developers. With the advent of Large Language Models (LLMs), which are increasingly capable of generating and understanding code, there is growing interest in incorporating these models into automated code optimization processes. Traditionally, this automation involves transcribing the source code into a domain-specific representation that can be auto-tuned using grid search or machine learning algorithms, while adhering to strict rules and a limited set of feasible transformations to ensure verifiability. LLMs incorporate high-level code semantics and can thus perform transformations that go beyond verifiable automated optimizations. This paper investigates whether the traditional abstractions used in automated code optimization improve the performance and correctness of LLM-guided optimizations of parallel HPC applications. We evaluate this using the PolyBench benchmark suite and demonstrate that, in our evaluated setting, LLMs provided with specific optimization goals achieve better measured performance and validity rates when generating C code compared to creating computation pipelines and optimization schedules with established frameworks, suggesting that future development should explore alternative approaches for verifiable LLM-guided code optimization.

## 1. 核心问题与整体含义

- **研究背景**：高性能计算（HPC）中的代码性能优化非常依赖对底层硬件、内存层次、并行机制和算法特性的深入理解，传统上依赖编译器、多面体模型（polyhedral model）、自动调优框架以及人类专家。即便对经验丰富的开发者而言，这类优化也容易出错且成本高昂。
- **研究动机**：大语言模型（LLM）已经具备理解和生成高质量代码的能力，有潜力自动完成或辅助 HPC 代码优化。但传统自动化优化通常需要将代码转换为领域特定表示（DSL / 框架），并依赖严格的规则与有限变换集合来保证可验证性；LLM 则可以直接理解高层语义，可能做出更灵活、更激进的变换。
- **核心问题**：传统代码优化抽象（如 Halide、Exo、Noarr 等 DSL/框架）是否能提升 LLM 引导优化的**性能**与**正确性**？还是说，直接让 LLM 生成优化后的 C 代码反而更有效？
- **整体含义**：论文通过系统性实验表明，在当前评估设置中，**直接生成 C 代码 + 具体优化提示**优于借助传统抽象框架的流程；这提示未来应重新思考如何设计可验证且适合 LLM 能力的优化抽象。

## 2. 方法论

- **总体思路**：采用非迭代、非反馈闭环的 LLM 优化流程，避免迭代式自调试或编译反馈引入额外变量，聚焦研究“抽象”和“提示策略”两个因素本身的效果。
- **两种主线流程**：
  1. **框架翻译 + 优化**：先让 LLM 将 C 基准代码翻译为 Halide、Exo、Noarr 三种框架/DSL 表示；再对选出的翻译结果进行 LLM 引导优化。
  2. **直接 C 优化**：直接让 LLM 优化原始 C 代码，不经过中间抽象。
- **翻译阶段的候选选择**：
  - 对每个 benchmark–框架组合独立请求 5 次翻译。
  - 优先验证正确性，然后在验证通过的候选中选取在 SMALL/MEDIUM/LARGE 输入规模下性能最接近原始 C 实现的翻译，作为后续优化输入。
- **直接优化策略（提示策略）**：
  - **Naïve**：仅要求 LLM 优化代码并保持语义。
  - **All-hints**：提供四类具体优化提示：缓存局部性（tiling、数据布局）、结构（临时 buffer）、算术（代数化简、累加器）、并行化（OpenMP 或 DSL 内并行原语）。
  - **Choose-hints**：提供同样的提示集合，但要求 LLM 自行选择最合适的提示再应用。
- **抽象优化计划方法（From-plan）**：
  - 两阶段提示：第一阶段让 LLM 在不改代码的情况下生成多个抽象的优化计划（描述维度、数据结构、计算步骤、可用的变换指令，如 tiling、unrolling、vectorization、parallelization）；第二阶段要求 LLM 从这些计划中选一个并应用到当前代码。
  - 目的是强制 LLM 外化推理过程，类似 chain-of-thought 的显式规划。
- **验证方法**：将生成代码与原始 C 代码的输出对比，设置绝对容差 \(10^{-2}\) 和相对容差 \(2\times10^{-7}\)，覆盖多个 PolyBench 输入规模；编译失败、运行失败、超时（8 分钟）或数值不一致均视为无效。
- **提示设计**：针对每个框架提供编程指南、翻译示例和框架特定规则；为避免偏差，所有提示经统一风格化处理并在保留的 4 个基准上预调优。

## 6. 主要结论与发现

- **RQ1：框架是否帮助？** 在本文设置中，Halide、Exo、Noarr 等框架对比直接 C 生成**没有带来明确的性能或正确性优势**；直接 C 的验证率最高，而框架反而可能限制 LLM 的优化空间。
- **RQ2：具体提示是否帮助？** **有帮助**。All-hints 和 Choose-hints 优于 Naïve，尤其 All-hints 在多数框架下获得最好性能；更具体的优化目标能显著提升结果。
- **RQ3：抽象计划是否帮助？** **没有明显帮助**。From-plan 并不优于直接 All-hints，甚至有时性能更低；说明强制 LLM 外化计划可能抑制其灵活推理能力。
- **RQ4：不同方法总体对比**：
  - 最佳组合为 **All-hints + 直接 C**；
  - Exo 在 5 次尝试预算下验证率接近 C，但性能仍不如 C；
  - Noarr 在所有框架中表现相对较差；
  - 增加独立尝试次数普遍能提升最佳加速比，Noarr 除外。
- **RQ5：LLM 是否受既有框架限制？** **是**。LLM 能可靠地生成不易用现有 DSL 指令表达的优化，甚至在一些基准上取得极高加速比，说明当前框架的抽象模板可能成为约束而非助力。
- **与先前工作对比**：非迭代、仅 5 次请求的 All-hints + C 已在多个 PolyBench 基准（如 3MM、correlation、covariance、doitgen、symm）上达到数十到百倍加速，与迭代式 agentic 方法处于同一数量级，同时获得更高的有效性比率。
- **总体结论**：提示策略的具体性比是否使用 DSL/框架更重要；未来研究应关注**更贴合 LLM 能力的新抽象与验证机制**。
