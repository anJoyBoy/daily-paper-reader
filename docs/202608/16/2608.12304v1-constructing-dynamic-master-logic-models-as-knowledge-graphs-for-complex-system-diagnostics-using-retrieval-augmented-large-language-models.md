## 摘要
动态主逻辑（DML）提供了一种分层框架，通过将功能目标与底层结构元素相关联来表示系统行为。然而，DML的构建通常依赖于专家对技术文档的解读，这限制了其在复杂系统中的可扩展性。本研究提出了一种框架，用于从系统描述中自动构建DML模型，并将其表示为知识图谱（KG-DML），利用检索增强生成和大型语言模型作为支撑工具。在先前针对小规模系统的工作基础上，该框架将自动化的KG-DML构建与评估扩展到规模更大、复杂度更高的系统。模型构建过程基于针对性检索，在DML层级结构中逐步推进，同时保留功能依赖关系和显式逻辑关系。生成的KG-DML支持诊断推理、安全评估、向上故障传播分析以及向下依赖追溯。多层级验证方法评估了各层的精确率与召回率、逻辑门一致性以及整体结构完整性。将该方法应用于一座已退役沸水反应堆的低压冷却剂注入系统，展示了多次运行下的一致重建效果。结果表明，自动化的KG-DML构建能够将技术文档转化为可用于诊断和可靠性分析的可执行功能模型。

## Abstract
Dynamic Master Logic (DML) provides a hierarchical framework for representing system behavior by linking functional objectives to underlying structural elements. However, DML construction typically relies on expert interpretation of technical documentation, limiting scalability for complex systems. This study presents a framework for automated construction of DML models from system descriptions and their representation as Knowledge Graphs (KG-DML), using Retrieval-Augmented Generation and Large Language Models as enabling tools. Building on prior work with small-scale systems, the framework extends automated KG-DML construction and evaluation to substantially larger and more complex systems. Model construction proceeds across the DML hierarchy using targeted retrieval while preserving functional dependencies and explicit logical relationships. The resulting KG-DML supports diagnostic reasoning, safety assessment, upward failure propagation, and downward dependency tracing. A multi-level validation methodology evaluates layer-specific precision and recall, logical gate consistency, and overall structural integrity. Application to the Low-Pressure Coolant Injection system of a decommissioned Boiling Water Reactor demonstrates consistent reconstruction across repeated runs. The results show that automated KG-DML construction can transform technical documentation into executable functional models for diagnostic and reliability analysis.

### 1. 论文的核心问题与整体含义

- **背景动机**：现代工程系统由大量互连组件构成，传统的事件驱动诊断模型（如故障树分析 FTA、事件树分析 ETA）依赖于枚举故障事件，在面临未预见的故障序列时内在不完备，且随着系统复杂度增长难以追踪故障传播路径。功能建模（Functional Modeling）提供了替代方案，其中**动态主逻辑（DML）**是一种将系统目标、功能、子功能、组件及成功条件组织为严格手段-目的层级的功能建模框架，支持诊断推理、可靠性分析与安全评估。
- **核心问题**：DML 模型的手工构建依赖领域专家对技术文档的解读，耗时长（传统上可能需要数月），难以扩展到大型复杂系统。LLM 虽具备语义理解能力，但存在幻觉、缺乏持久结构、推理不一致等局限。
- **研究意义**：本工作提出一个自动化框架，利用**检索增强生成（RAG）+ 大语言模型（LLM）**从工程文档中自动构建 DML 模型并表示为知识图谱（KG-DML），将非结构化技术文档转化为可存储、可查询、可推理的可执行功能模型，从而显著降低人工建模成本，支持大规模复杂系统的诊断推理与可靠性分析。

### 2. 方法论

#### 核心思想
采用**"分而治之"的分层构建策略**：不试图一次性从文档中推断整个 DML 模型，而是按照 DML 的层级结构（目标 → 功能 → 子功能 → 组件 → 成功条件）逐层构建。每一层通过检索文档中与当前层级语义和父节点相关的语料，由 LLM 生成候选元素及逻辑关系，经过验证后逐步累积到主 JSON 模型中。最终将 JSON 转换为 Neo4j 图数据库的 Cypher 查询语句，形成可遍历的 KG-DML。

#### 关键流程（三阶段）

1. **Stage 1：文档预处理与嵌入**
   - 对系统文档进行标准化处理：统一组件标识符格式、扩展缩写、补充描述性上下文、消解代词。
   - 采用基于段落的切分策略（块大小 1,500 字符，相邻块重叠 150 字符）。
   - 使用 `text-embedding-3-small` 模型将文本块嵌入向量数据库，支持基于余弦相似度的检索。

2. **Stage 2：逐层模型构建**
   - 每一层构建时，从主 JSON 中提取父节点，结合当前层的语义定义构造检索查询。
   - 通过余弦相似度计算（`cos(q, dᵢ) = (q·dᵢ) / (‖q‖‖dᵢ‖)`）从向量库中检索 Top-K 个文档块（K=10）作为证据。
   - 将检索证据、父节点信息和层级指令提供给 LLM（GPT-4o，temperature=0），生成符合预定义 JSON Schema 的候选元素和逻辑关系。
   - 对 LLM 输出进行结构正确性、标识符有效性和层级约束的自动校验，有效元素加入主 JSON。
   - 父节点可按不同批量大小（batch size 1/5/10/15）处理，以权衡质量和效率。

3. **Stage 3：知识图谱合成与导出**
   - (Algorithm 1) 将主 JSON 转换为 Cypher 语句，在 Neo4j 中创建节点、关系。
   - 对包含布尔逻辑（AND/OR）的依赖关系创建中间门节点；嵌套门结构递归处理以保留多层级逻辑结构，不打平。

#### 评估框架
- **归一化与节点级评估（Algorithm 2）**：将预测模型和参考（gold）模型归一化后，通过语义匹配对齐节点，逐层计算精确率、召回率和 F2 分数（F2 更强调召回，反映"漏建比多建更严重"这一考量）。
- **关系与逻辑门一致性**：逐层比较父-子链接，分类为缺失/错误/多余链接；对共有父节点比较 AND/OR 门操作符是否一致。
- **完整性分数**：
  - 公式：`IntegrityScore = 100 × (Σ wₗ·Fₗ / Σ wₗ) × exp(-E_structural / ((N_nodes + N_links)·S))`
  - 第一项为各层 F2 的加权平均（高层权重更大）；第二项基于结构重建误差（缺失节点、缺失关系、门不匹配、孤悬节点）的指数惩罚，使用指数衰减形式反映累积结构错误的非线性影响。

#### 交互模块
- **向上传播**：从组件/成功条件层的状态概率出发，沿层级通过嵌套 AND/OR 门结构递归聚合，量化组件失效对系统目标的影响。
- **向下传播**：从查询节点向下遍历生成最小成功路径集；对含冗余相同组件的备选路径，附加共因失效（CCF）的定性提示。
- **解释性查询**：LLM 根据 KG-DML 的预定义模式生成 Cypher 查询，由图数据库执行结构检索，LLM 负责格式化自然语言回答。

### 7. 优点

- **明确的问题定位**：精准指出 DML 手工构建瓶颈，目标清晰——不是用 LLM 替代专家，而是减少专家提取和整理结构的工作量。
- **架构设计合理**：为降低 LLM 不可靠性，采用多重约束设计——预定义 Schema、有界系统范围、结构化 JSON 输出、独立校验模块，将 LLM 从开放式生成转变为受控的结构化解释，这一设计理念值得借鉴。
- **分层检索策略**：每层使用父节点信息约束检索范围，既解决长文档的上下文窗口限制，又保持层级依赖的连贯性。
- **嵌套布尔门支持**：相较于先前工作，支持任意层级的嵌套 AND/OR 子门结构，增强了模型表达复杂逻辑的能力。
- **系统的评估框架**：同时考察节点、链接、逻辑门三个层面的准确性和完整性，并设计了综合完整性分数，将结构错误与元素级精度结合为单个可解释指标；指数惩罚形式合理反映了累积结构错误的非线性影响。
- **交互/推理分离架构**：LLM 只负责理解用户意图并调用图遍历工具，概率计算和逻辑推理由确定的图算法执行，保证了推理的可追溯性和可控性。
- **代码开源承诺**：论文声明代码将在录用后公开，有利于复现。

### 8. 不足与局限

- **单一案例验证**：评估仅基于 LPCI 一个系统，虽然该系统具有代表性，但对更大规模、多文档、更高组件密度或更复杂嵌套逻辑系统的泛化性尚未验证。
- **缺乏消融实验**：未评估无检索基线、不同检索配置（如混合检索、自适应分块）、不同提示策略或不同 LLM 模型对框架性能的贡献，作者承认这一点并指出开放域 KG 构建的标准消融设计并不直接适用于这种 Schema 约束的分层任务，需要专门的方法论。
- **结构一致 ≠ 功能等价**：节点/链接/门层面的结构对齐无法保证行为等价（如同样的向上/向下传播结果）。未来应引入最小割集/成功路径集比较，并且即使这些集合等价，功能层的专家验证仍不可替代。
- **CCF 建模不完整**：共因失效只在下行传播时以定性提示方式提醒，未在 KG-DML 逻辑结构中显式建模共享失效机制或依赖强度，限制了定量 CCF 分析的可行性。
- **静态快照**：基于静态文档提取，不捕获随时间变化的系统行为或上下文依赖行为；未建模传感器数据、实时状态更新等动态输入。
- **对预处理和检索配置敏感**：组件标识符标准化等预处理步骤是手动设计的，对噪声、不一致或不完整文档的鲁棒性未系统评估；变异的分块、检索排序或相似度阈值均可能改变模型输出。
- **人工成本未量化**：自动化减少专家工作量的声明基于有限实践经验，未通过受控的人机对比实验系统测量。
- **模型成本问题**：依赖高能力 LLM（GPT-4o）通过外部 API 访问，在成本敏感或数据保密的工业场景中可能不实用；未来需要探索轻量模型与大型模型混合、本地化部署等方案。
