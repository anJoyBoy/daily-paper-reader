## 摘要
生成结构有效的合成表格数据仍然困难：具有高统计保真度和下游效用的输出仍可能违反语义上有意义的领域约束。我们研究了三种互补的列间约束族——方程、线性不等式和逻辑依赖——的发现与执行。我们统一的、基于工具的工作流将这三者表示为机器可执行的假设，并应用一个通用接口进行全表验证、确定性诊断和反例引导的修订。一个与生成器无关的后处理器协调对不变表格生成器输出的族特定修复。通过精心策划的行为审计和端到端评估，完整的工作流在一次性直接提示上提高了保留违规检测的能力，而后处理对每个保留的、适用的约束产生了零测量的违规，提高了大多数数据集上的下游效用，并在很大程度上保留了单变量边际分布。

## Abstract
Generating structurally valid synthetic tabular data remains difficult: outputs with high statistical fidelity and downstream utility can still violate semantically meaningful domain constraints. We study the discovery and enforcement of three complementary inter-column constraint families---equations, linear inequalities, and logical dependencies. Our unified tool-grounded workflow represents all three as machine-executable hypotheses and applies a common interface for full-table validation, deterministic diagnosis, and counterexample-guided revision. A generator-agnostic postprocessor coordinates family-specific repairs on outputs from unchanged tabular generators. Across curated behavioral audits and end-to-end evaluations, the complete workflow improves held-out violation detection over one-shot direct prompting, while postprocessing yields zero measured violations for every retained, applicable constraint, improves downstream utility on most datasets, and largely preserves univariate marginals.

- 合成表格生成（synthetic tabular data generation）在真实数据稀缺或受限场景中广泛应用，例如模型开发、系统测试与分析。

- 典型问题：电商订单的交付时间早于订单时间、小计金额与单价×数量不匹配、配送方式与商品类型不兼容等。这些违反通常源于列间（inter-column）语义约束。
- 已有约束感知生成方法存在两方面不足：
  - 约束获取常局限于单一约束族或特定生成管线，缺乏跨族统一的表示、验证与修订机制；
  - 约束执行常依赖生成器内部的训练目标或拒绝采样，无法直接作用于已训练好的“黑盒”生成器输出，并且处理共享列时缺乏协调，可能产生修复相互破坏的问题。
- 论文的核心目标是：**提出一个端到端框架**，用 LLM 智能体自动发现三类列间约束（方程、线性不等式、逻辑依赖），以统一的机器可执行形式表达，进行全表验证、确定性诊断和反例引导修订，并对任意生成器输出进行协调的后处理修复，从而在不改变生成器的情况下实现结构有效的合成数据生成。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 总体架构
- 框架分为两部分：
  1. **LLM 引导的约束发现（constraint discovery）**
  2. **生成器无关的约束执行（constraint enforcement）**，即后处理阶段。

### 2.2 约束发现流程
- **数据集画像（profiling）**：为每个数值列生成范围、分位数、均值、标准差、众数等统计；为每个类别列生成高频值及其频率；并包含列语义描述和数据描述。
- **可执行假设生成（executable hypothesis generation）**：
  - LLM 智能体接收数据集描述、列画像和少量上下文行（nctx = 100）后，输出候选结构：
    - 唯一 ID
    - 自然语言描述
    - 参与列
    - 族特定的机器可执行表示（仅此字段用于验证）
  - 三类约束的表示：
    - **方程**：用 Python `check(df)` 函数，逐行返回布尔序列，支持任意算术表达式和容差。
    - **线性不等式**：JSON DSL，形如 `∑ a_j x_j ≤/≥ b`，存储列、系数、比较符号和右端常数。
    - **逻辑依赖（LD）**：JSON DSL，由若干决定列、一个依赖列和值表组成；值表指定“决定列取值集合 → 依赖列允许值集合”的映射；支持功能依赖、部分规则和多值映射。
- **工具化验证与修订**：
  - 每个假设用确定性校验工具在全表上评估：
    - `validate_equational`：执行 check 函数并统计 False 数量。
    - `validate_linear`：评估半空间约束。
    - `validate_LD`：统计适用行中依赖值不在允许集合中的比例。
  - 保留条件：违规率 `VR(h) ≤ τ_vio`，且 LD 还需满足支持度 `Supp(h) ≥ τ_sup`（两者均设为 0.005）。
  - 验证失败时，校验器返回聚合诊断和最多 ncex = 20 个反例行，交给 LLM 智能体修订。每个候选最多 Rrev = 3 次修订尝试，最终仍失败则拒绝。
  - 发现过程进行 Rdisc = 3 轮，后续轮次智能体会收到已接受/已拒绝假设的摘要，被要求探索新的关系。
- **合并与去重（consolidation）**：
  - 线性不等式：标准化系数向量，去除重复和“同系数但更大右端”的弱约束。
  - 方程：为每个列集合保留一个首选候选，再用二进制优化选择不共享列的方程集合。
  - LD：构建无环依赖图、规范化值表、去除重复或严格被包含的映射、合并兼容映射。

### 2.3 约束执行（后处理）
- 后处理顺序：**逻辑依赖 → 方程 → 线性投影**。
  - 逻辑依赖只改类别列，顺序相对独立。
  - 方程修复必须在线性投影之前，且投影时**固定方程参与列**，避免投影破坏已修复的方程。
- **逻辑依赖修复**：保持决定列不变，将依赖列替换为允许集合中的值；若集合为多值，则按参考条件分布抽样。
- **方程修复**：
  - LLM 为每个方程和可选目标列生成 `fix(df)` 重构函数，并在全参考表上验证（VR ≤ τ_vio）。
  - 对于共享列的方程，使用 **KS-complement 引导的启发式算法**选择修复目标和顺序：
    - 先最大化最差修复对边际分布（KS complement）的预测变化，避免严重损害任何单列；
    - 再在满足最优最小值的前提下，最大化总预测变化。
    - 修复后列被冻结，后续修复不得覆盖。
- **线性不等式修复**：
  - 对每个违规行，求解联合凸投影问题：

    \[
    \mathbf{bx}_{i, S_{num}} \in \arg\min_{z \in \mathbb{R}^{|S_{num}|}} \sum_{j \in U} \left( \frac{z_j - \tilde{x}_{ij}}{s_j} \right)^2
    \quad \text{s.t.} \quad A z \le b,\; z_j = \tilde{x}_{ij} \; \forall j \in P
    \]

  其中 `P` 是方程参与列和零方差列，`U` 是可变列，`s_j` 是参考标准差。该投影是顺序无关的全局最优，且保证方程约束不被破坏。
- 最终，用所有族校验器重新检查后处理表，确保零违规。

### 3.2 端到端约束感知生成
- 7 个公开数据集：FLIGHTS、HELOC、NBA、NEWS、STEEL、TAXI、URL（ANXIETY 仅用于发现，因无目标列且为纯类别）。
- 4 类生成器范式：
  - **Gaussian Copula**（统计）
  - **CTGAN**（对抗式）
  - **TVAE**（变分自编码）
  - **TabDDPM**（扩散模型）
- 设置：3 个独立 70/30 划分；每个生成器每划分训练一次并产生 3 张合成表；每划分用 GPT-5.6 独立发现约束并应用后处理，共 252 组（raw–postprocessed）配对评估。
- 约束指标：
  - CVR（行级违规率，越低越好）

## 6. 论文的主要结论与发现

- **发现阶段**：完整的“可执行验证+修订”工作流在全部 18 个 family–backbone–metric 对比中均优于一次性直接提示。最大增益出现在逻辑依赖：GPT-5.6 下精确率/召回率从 .442 提升至 .974；Claude-5 下提升至 .963。线性不等式也有大幅提升（如 Claude-5 准确率 .815→.959，召回率 .633→.919）。方程在接近上界的基线上仍达到接近 1.000。
- **执行阶段**：后处理在所有保留且适用的约束上达到**零测量违规**（CVR = 0、sCVC = 0、LFD = 0、方程 R² = 1），且没有将违规在约束族间转移。
- **效用与保真**：TSTR 在 7 个数据集中的 4 个上提升（如 STEEL 0.486→0.976），其余 3 个最多下降 0.042；Column Shapes 变化范围仅 −0.009 到 +0.019，说明单变量边际基本保留。
- **生成器差异**：不同生成器在不同约束族上表现各异（如 TabDDPM 逻辑依赖最好但线性最差，TVAE 线性最好但方程一般，CTGAN 方程最差），因此选择生成器不足以保证结构有效性，需要族感知的后处理。
- **修复顺序**：方程修复必须在线性投影之前（E→L），否则线性违规会再次出现（NBA 中 L→E 在 66.7% 设置中留下线性违规）。
- **发现消融**：默认超参数（3 轮、100 行上下文、20 反例）是观察到的成本–产量最佳折衷；反例对产量影响最大，移除后保留约束产量从 46.33 降至 19.33。

## 7. 优点

- **统一可执行接口**：将三种异构约束族统一为“可执行假设”，支持共同的验证、诊断和修订流程，使 LLM 输出不再是“文本建议”而是可测试的机器对象。
- **生成器无关**：后处理不访问、不修改生成器，可应用于黑盒模型或已生成的表，规避了重训练和拒绝采样的缺陷。
- **协调修复**：通过冻结已修复列、保护方程参与列、联合凸投影等机制，避免修复之间相互破坏；KS 引导的选择策略在保持约束满足的同时减少边际分布损伤。
- **发现与验证闭环**：用反例引导的迭代修订显著提高约束发现的产量与质量，优于一次性提示。
- **实验质量较高**：包含行为审计、端到端评估、消融研究，覆盖 4 类生成器、多数据集和多指标，且报告了方差与细节（阈值、提示、超参数等），可复现性好。
- **诚实处理伦理与限制**：论文明确说明数据隐私风险、约束可能编码历史偏见、生成代码需沙箱等，并对方法边界给予清晰描述。

## 8. 不足与局限

- **约束类型范围有限**：仅限记录内行级约束；不支持跨行约束（如唯一性）、单元格级格式（如正则表达式）、跨表键约束等。
- **语义可靠性有限**：全表验证只保证经验一致性，不保证语义正确性；“零违规”仅针对保留且适用的校验器，可能存在未发现的约束或未覆盖的配置。
- **依赖高质量元数据**：所有实验都提供了丰富的数据集/列描述；在元数据缺失、模糊或噪声大的真实场景下，发现准确性可能显著下降。该问题未做鲁棒性实验。
- **发现基准覆盖面窄**：每约束族仅一个数据集（NBA 方程、URL 不等式、ANXIETY 逻辑依赖），可能无法代表该族的多样性；消融主要在 NEWS 和 NBA 上，结论的外推性有限。
- **无显著性检验**：结果多为均值 ± 标准差，未进行统计显著性测试；论文也承认消融结果不是“通用最优”。
- **LLM 与算力**：实验使用指定的 GPT-5.6/Claude-5（2026 年版本），提示词或模型版本变化可能影响结果；硬件总时长约 18 小时，但未报告详细能耗或 LLM API 成本。
- **公平性风险**：发现约束可能编码历史偏差或刻板模式，若直接用于合成数据可能放大不公平；论文只提醒需领域审查。
