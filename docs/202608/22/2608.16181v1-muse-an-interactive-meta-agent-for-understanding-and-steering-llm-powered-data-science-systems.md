## 摘要
大规模语言模型的最新进展催生了一类新的智能体数据科学系统，允许用户通过自然语言完成复杂的数据科学工作流。尽管这些系统能显著减少人工工作量，但当失败或意外输出发生时，诊断其行为并引导推理过程仍然困难。我们提出了MUSE，一个交互式元智能体，它通过以下方式增强用户对智能体数据科学系统的理解和控制：（1）动态地将底层执行轨迹重构为多个语义层级，支持从高层概览到底层实现细节的导航；（2）使用户能够在上下文中引用特定的工作流步骤，以提出有依据的问题、提供反馈并修订有问题的步骤，而无需手动定位相关执行历史；（3）通过展示可疑步骤以供检查、搭建修复过程框架，并将用户修复意图转化为针对底层智能体的情境化指令，来支持混合主动引导。在一项受试者间研究（n=15）中，MUSE提高了任务效率，并增强了用户理解和引导智能体数据科学工作流的信心。

## Abstract
Recent advances in large language models have enabled a new class of agentic data science systems that allow users to complete complex data science workflows through natural language. Although these systems can significantly reduce manual effort, it remains difficult to diagnose their behavior and steer the reasoning process when failures or unexpected outputs occur. We present MUSE, an interactive meta-agent that enhances user understanding and control of agentic data science systems by (1) dynamically restructuring low-level execution traces into multiple semantic levels that support navigation from high-level overviews to low-level implementation details; (2) enabling users to reference specific workflow steps in context to ask grounded questions, provide feedback, and revise problematic steps without manually locating relevant execution history; and (3) supporting mixed-initiative steering by surfacing suspicious steps for inspection, scaffolding the repair process, and translating user repair intent into contextualized instructions for the underlying agent. In a between-subjects study (n = 15), MUSE improved task efficiency and increased users' confidence in understanding and steering agentic data science workflows.

- **核心问题**：
  - 现有系统输出大量低层执行日志，缺乏结构化语义，用户难以判断整体流程是否合理；

  - 修复错误步骤需要手动定位历史日志并编写自由文本指令，对非AI专家用户存在较高的提示工程门槛。
- **总体含义**：需要通过交互式元智能体的设计，弥合用户与LLM驱动数据科学系统之间的“评估鸿沟”（gulf of evaluation）和“协调障碍”（coordination barrier），使用户能够理解和控制agent的行为。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想

MUSE作为一个**元智能体**，在底层数据科学agent与用户之间充当中介，将原始的、无结构的执行日志转化为多级语义表示，并支持用户对工作流的上下文内理解、验证、修复和引导。

### 2.2 四层系统架构

MUSE由四个层次组成：

| 层次 | 功能 |
|------|------|
| **总结层（Summarization Layer）** | 将原始日志转化为结构化的多级语义表示 |
| **监控层（Monitoring Layer）** | 检测可疑行为并突出显示潜在问题步骤 |
| **验证层（Verification Layer）** | 支持对中间结果进行就地验证，提供脚手架式验证计划和脚本 |
| **引导层（Steering Layer）** | 使用户能够提供反馈、修订有问题的步骤并引导系统行为 |

### 2.3 关键流程

- **执行轨迹捕获**：MUSE在agent运行时记录五类执行事件——推理轨迹、工具调用、代码、信号（警告/错误/完成标记）和人工产物（中间输出）。
- **语义块分割**：利用agent发出的步骤完成标记将原始日志流分割为语义块，每个块对应一个工作流阶段。
- **五级语义表示（L1–L5）**：
  - **L1**：数据科学阶段标题
  - **L2**：自然语言摘要
  - **L3**：有序子步骤列表
  - **L4**：详细操作（如生成的文件、执行的命令、选择的参数）
  - **L5**：底层痕迹（代码、命令、工具输出）
- **警告检测**：使用从MLE-Bench任务和已有agent错误分类学中总结的启发式规则，识别数据级和agent级可疑行为。检测启发式包括：攻击性数据删除、覆盖原始数据、硬编码阈值、可疑连接/合并、丢失分类语义、缺失/误导性评估、单次分割评估、未经验证的schema假设、未检查缺失数据等（共14类）。
- **上下文引用**：用户可以将工作流步骤拖放到聊天框，MUSE将选中的步骤解析到相关证据（代码片段、日志、文件），并自动丰富请求上下文。
- **脚手架式验证**：用户高亮输出后触发“Help me verify”，MUSE生成3–5个验证选项供用户选择，然后生成验证脚本在沙箱中执行，不修改管线输出。
- **脚手架式修复**：用户点击“Revise”后，MUSE基于警告诊断提供修复选项，并自动将修复请求与受影响的步骤和警告上下文整合为上下文化指令传递给底层agent。

## 6. 主要结论与发现

1. **效率提升**：MUSE显著减少了任务完成时间（比Raw Logs条件减少35%，比DiLLS条件减少9%），同时保持了高成功率（90%）。
2. **用户信心增强**：MUSE用户对最终DS结果信心最高，差异显著。
3. **认知负荷降低**：MUSE在NASA TLX的Hurry、Effort、Frustration三个维度上显著优于条件A和B。
4. **错误处理能力显著提升**：在识别到警告时，条件C用户平均解决了2.8个警告，而条件B仅解决了0.8个（p=.0118），表明就地修复功能有效帮助用户处理行为偏差。
5. **监控方式转变**：MUSE将监控从“线性搜索”转变为“本地化检查”——条件A中用户平均每次任务滚动147次，条件C仅滚动61次；语义级别滑块是条件C中最频繁的交互，共162次调整。
6. **用户类型分类**：研究中观察到三类用户行为模式——AI委托者（AI Delegators，2人）、AI协作者（AI Collaborators，8人）、AI审计者（AI Auditors，4人），说明不同用户需要不同级别的验证支持。
7. **错误类型分布**：agent最常见的错误类型包括Unverified Schema Assumptions（56%）、Missing Data Not Inspected（16%）和Single-Split Evaluation（12%）；较弱模型Haiku触发警告比Opus多27%。
8. **专家与新手差异不显著**：有技术背景的专家（N=6）与新手（N=9）在完成时间和尝试次数上无显著差异。

## 7. 方法或实验设计上的亮点

- **多级语义表示**：受信息寻找咒语（overview first, zoom and filter, details on demand）启发，设计L1–L5五级抽象层次，动态将无结构执行日志转化为结构化DS工作流语义，而非agent行为语义。
- **语义块分割机制**：利用agent自身发出的步骤完成标记（step-completion marker）作为块边界，不依赖LLM推断日志中的分界，提高分割的可靠性和实时性。
- **混合主动控制**：MUSE在agent执行期间并行监控，用户可以随时提问、验证、修订，无需等待整个流程结束，支持长时间运行步骤中的干预。
- **上下文拖拽引用**：用户可以直接拖拽工作流步骤到聊天框，MUSE自动解析相关证据并丰富上下文，降低提示工程门槛。
- **脚手架式验证与修复**：通过生成验证计划和修复选项来引导用户，而不是要求用户自由发挥诊断和指令，对非AI专家用户尤为友好。
- **基于信息气味理论**：设计警告本地化提示，引导用户快速定位最可能需要关注的问题区域。
- **与强基线对比**：条件B（DiLLS风格）作为强基线，且使用了与条件C相同的警告检测方法，使对比更公平。
