## 摘要
大型语言模型在将自然语言翻译为SQL方面展现了显著能力，但现有方法在处理需要多步骤、数据感知推理的复杂查询时仍显不足。我们提出DecoSearch，一种无需训练的框架，通过将每个查询路由到适当级别的推理努力来解决这一问题。轻量级模式选择器首先将完整数据库模式修剪为相关的表和列。然后，一个LLM评判器决定问题是否需要分解：简单问题直接生成，复杂问题则升级为原子子问题的有向无环图，每个子问题通过针对性的SQL生成步骤解决。RAG组件通过语义相似的训练示例支持分解器，当执行失败表明是分解缺陷而非可修复的SQL错误时，拓扑精炼器会重构推理计划。DecoSearch在BIRD上达到70.53%的执行准确率，在Spider上以DeepSeek为骨干达到88.31%，超越了所有无训练基线，同时消耗的令牌数量比竞争方法少一个数量级。它还可作为模型无关的封装器，在不修改流水线的情况下一致地改进微调后的SQL生成骨干。

## Abstract
Large Language Models (LLMs) have demonstrated remarkable capabilities in translating natural language to SQL, yet existing methods still falter on complex queries requiring multi-step, data-aware reasoning. We introduce DecoSearch, a training-free framework that addresses this by routing each query to the appropriate level of reasoning effort. A lightweight Schema Selector first prunes the full database schema to the relevant tables and columns. An LLM Judger then decides whether the question requires decomposition: straightforward questions follow a direct generation path and complex ones are escalated to a Directed Acyclic Graph (DAG) of atomic sub-questions, each solved by a targeted SQL generation step. A RAG component grounds the decomposer with semantically similar training examples, and a Topology Refiner restructures the reasoning plan when execution failures signal a flawed decomposition rather than a fixable SQL error. DecoSearch achieves 70.53% execution accuracy on BIRD and 88.31% on Spider with a DeepSeek backbone, surpassing all training-free baselines while consuming an order of magnitude fewer tokens than competing methods. It also functions as a model-agnostic wrapper, consistently improving fine-tuned SQL generation backbones without any modification to the pipeline.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有大型语言模型（LLM）在Text-to-SQL任务中，对于需要多步推理、数据感知的复杂查询（如嵌套查询、多表连接、多步逻辑推理）表现不佳。单次自回归生成无法处理组合空间，早期错误无法恢复。
- **现有方法的不足**：现有方法如分解、自修正、多候选生成等通常只处理单一层级的错误（如语法错误），但忽略了**策略级错误**（SQL结构选择不当）和**计划级错误**（高层次推理计划本身有缺陷）。没有框架能系统诊断失败层级并路由到合适的修复机制。
- **核心目标**：提出一个无需训练的、自适应推理框架，将简单查询直接生成，复杂查询分解为有向无环图（DAG）子问题，并引入计划级修复机制。

## 2. 方法论
### 核心思想
- **复杂度感知路由**：通过一个LLM评判器（Judger）判断查询是否需要分解，将简单查询导向直接生成路径（成本低），复杂查询升级到DAG分解路径（高成本但高正确率）。
- **层次化失败处理**：失败分为实现级（SQL错误）、策略级（结构不当）、计划级（分解错误）。DecoSearch能识别计划级失败并通过拓扑精炼器重构DAG。

### 关键技术细节
1. **模式选择器（Schema Selector）**：分两阶段：
   - 关键字提取：从自然语言问题和证据中提取相关关键字。
   - 表/列选择：基于关键字调用LLM选择相关表和列，压缩模式，减少噪声和令牌消耗。
2. **评判器（Judger）**：单个零样本LLM调用，输出JSON决定是否需要分解。偏向直接路径，仅在需要多步推理、极端连接复杂度、证据驱动公式等情况下才分解。
3. **直接路径（Direct Path）**：对于简单查询，单次零温度LLM生成SQL并执行；成功则返回，失败则回退到分解路径。
4. **DAG分解（Decomposition）**：
   - 分解器将复杂问题拆分为原子子问题的DAG，节点表示子问题，边表示数据依赖。
   - 使用RAG（检索增强生成）从训练集中检索语义相似的分解示例，辅助分解器生成更合理的图。
   - 子问题求解：按拓扑序执行每个节点，通过`@[n]`占位符传递上游结果。小结果集（≤100行）内联为SQL值列表，大结果集（>100行）物化为临时表。
5. **拓扑精炼器（Topology Refiner）**：当某节点SQL执行失败且不能通过重新生成修复时，视为计划级错误。LLM根据当前DAG、失败节点和执行错误，自动重构DAG（如重新划分依赖、插入中间节点），并保留已成功节点的结果。重试次数受预算B=3限制，如耗尽则接受最佳结果并继续下游。

### 算法流程（文字说明）
- 输入：自然语言问题Q、数据库D、模式S。
- 步骤1：Schema Selector修剪模式得到S_pruned。
- 步骤2：Judger判断是否直接路径？是则生成SQL并执行，成功返回，失败则进入分解。
- 步骤3：Decomposer将Q分解为DAG G，按拓扑序排序。
- 步骤4：循环处理每个节点：替换依赖占位符 → 调用SQL Generator生成SQL → 执行 → 如果失败且未超预算则调用Topology Refiner重构DAG并重新排序；否则将结果物化，继续下一个节点。
- 返回最终节点结果。

## 6. 主要结论与发现
- DecoSearch在BIRD上达到70.53% EX，Spider上达到88.31% EX，**超越所有无训练基线**，并在Spider上优于多个微调模型。
