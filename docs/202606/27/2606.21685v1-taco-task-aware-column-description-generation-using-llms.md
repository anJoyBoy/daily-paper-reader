## 摘要
生成准确且信息丰富的列描述（例如，针对列名“cust_mem”生成“客户会员状态”）对于表格数据上的广泛下游NLP任务（包括NL2SQL、表格问答和实体链接）至关重要。该问题出现在企业、领域科学、政府数据门户等场景中。尽管其重要性，大多数真实世界的数据集由于列名缩写或领域特定术语而缺乏文档或文档难以理解。现有方法主要依赖单提示大语言模型，但面临三个关键问题：(i) 对缩写的处理不一致或错误，(ii) 产生幻觉或不完整的描述，以及(iii) 冗余或模糊性阻碍下游性能。我们提出了TACO，一种使用大语言模型进行自动列描述生成的任务感知框架。TACO引入了一个三步流水线：(1) 缩写扩展，标准化列名；(2) 描述生成，生成初始语义描述并丰富同义词和面向搜索的关键词；(3) 描述修订，通过模拟下游任务来优化这些输出。此外，我们还研究了人在回路扩展，并发布了用于实体链接和模式增强的新评估数据集。在公共和专有数据集上的大量实验表明，TACO始终优于现有方法，将下游任务性能提升高达32%。

## Abstract
Generating accurate and informative column descriptions (e.g. "membership status of customers" for the column name "cust_mem") is essential for a wide range of downstream NLP tasks on tabular data, including NL2SQL, table question answering, and entity linking. This problem arises in enterprises, domain sciences, government data portals, and so on. Despite its importance, most real-world datasets suffer from missing or cryptic documentation, often due to abbreviated column names or domain-specific jargon. Existing approaches largely rely on single-prompt large language models (LLMs), which struggle with three key issues: (i) inconsistent or incorrect handling of abbreviations, (ii) hallucinated or incomplete descriptions, and (iii) redundancy or vagueness that hinders downstream performance. We present TACO, a task-aware framework for automatic column description generation using LLMs. TACO introduces a three-step pipeline: (1) abbreviation expansion, which standardizes column names; (2) description generation, which produces initial semantic descriptions enriched with synonyms and search-oriented keywords; and (3) description revision, which refines these outputs using simulated downstream tasks. In addition, we investigate human-in-the-loop extensions and release new evaluation datasets for entity linking and schema enrichment. Extensive experiments across public and proprietary datasets show that TACO consistently outperforms existing methods, improving downstream task performance by up to 32%.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：结构化数据广泛存在，下游任务（NL2SQL、表格问答、实体链接等）需要准确理解列语义。但现实数据集的列名往往缩写（如“esal”表示“employee salary”）或缺乏描述，导致大语言模型（LLM）难以正确识别列、产生幻觉或冗余输出，阻碍下游推理。
- **研究动机**：现有方法（如Wretblad et al. 2024）采用单提示（single-prompt）让LLM直接生成列描述，存在三个主要缺陷：①缩写处理不一致（同一缩写在不同列中解释不同）；②描述包含幻觉或无关细节；③描述过于通用或冗余，缺失关键语义线索。
- **整体意义**：提出TACO框架，系统性地解决列描述生成中的缩写规范化、语义丰富化和任务感知优化问题，提升下游任务（尤其是语义检索）的性能，为自动表格注释提供新范式。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：将列描述生成分解为三个阶段，通过模块化流水线逐步提升描述质量，并引入模拟下游任务来驱动描述修订，使描述“任务感知”。
- **关键技术细节**：
  - **阶段1：缩写扩展（Abbreviation Expansion）**
    - 列名扩展：使用COLUMBO方法（Cai et al. 2025），基于表内和表间上下文、token级思维链扩展，并在数据集级别强制执行一致性（同一缩写整个数据集中统一扩展）。
    - 表名扩展：利用扩展后的列名作为上下文，生成简洁表名。
  - **阶段2：描述生成（Description Generation）**
    - 以扩展后的表名和列名作为输入，对每个表分组（K列）使用提示（prompt）生成结构化描述，包含四部分：一句话概述、同义词列表、关键词列表、代理查询（proxy queries），以支持语义检索。
    - 提示约束要求：区分相似列、不虚构字段、优先使用领域无关措辞。
  - **阶段3：描述修订（Description Revision）**
    - 模拟下游语义检索：对每个列生成M个（默认3）候选用户查询，嵌入后与所有列描述计算余弦相似度。若目标列未排第一，则收集竞争列的描述，提示LLM修订目标列的描述，使其更独特、与查询更对齐。
    - 仅当修订后的平均余弦相似度高于原描述时才更新；否则保留原描述。
  - **人类在环扩展（Human-in-the-Loop）**：
    - 利用LLM作为裁判对扩展结果打分（0-5），自动标记低置信度扩展供人工验证。
    - 人工修正后，通过检索同一表中或同名列中的已验证扩展，引导LLM重新生成其他列的扩展。

## 7. 优点：方法或实验设计上的亮点

- **模块化设计**：将列描述生成分解为三个独立阶段，每个阶段可独立优化或替换，易于扩展（如加入表描述模块）。
- **任务感知修订**：通过模拟下游语义检索的失败案例，针对性地优化描述，使描述更独特、更利于检索，这是与现有方法的关键区别。

- **人类在环集成**：自动识别低置信度扩展并允许人工修正后传播，适应现实标注需求。
- **提供新评估数据集**：基于SNAILS构建的黄金查询-列对，以及专有数据集，为社区提供可复现的基准。
