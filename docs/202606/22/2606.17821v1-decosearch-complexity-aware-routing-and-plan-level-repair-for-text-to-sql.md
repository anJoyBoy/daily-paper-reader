## 摘要
大型语言模型（LLMs）在自然语言转SQL方面展现了卓越能力，但现有方法在处理需要多步骤、数据感知推理的复杂查询时仍存在不足。我们提出DecoSearch，一种无需训练的框架，通过将每个查询路由到适当的推理复杂度级别来解决这一问题。轻量级模式选择器首先将完整数据库模式剪枝到相关的表和列。然后，语言模型评判器判断问题是否需要分解：简单问题采用直接生成路径，复杂问题则升级为原子子问题的有向无环图（DAG），每个子问题通过目标SQL生成步骤解决。检索增强生成组件利用语义相似的训练示例对分解器进行强化，而拓扑优化器在执行失败标志着分解缺陷而非可修复的SQL错误时，重构推理计划。DecoSearch在BIRD上达到70.53%的执行准确率，在Spider上达到88.31%，采用DeepSeek骨干模型，超越了所有无需训练的基线方法，同时消耗的令牌数比竞争方法少一个数量级。它还可以作为模型无关的封装器，在不修改流水线的情况下，持续改进微调的SQL生成骨干模型。

## Abstract
Large Language Models (LLMs) have demonstrated remarkable capabilities in translating natural language to SQL, yet existing methods still falter on complex queries requiring multi-step, data-aware reasoning. We introduce DecoSearch, a training-free framework that addresses this by routing each query to the appropriate level of reasoning effort. A lightweight Schema Selector first prunes the full database schema to the relevant tables and columns. An LLM Judger then decides whether the question requires decomposition: straightforward questions follow a direct generation path and complex ones are escalated to a Directed Acyclic Graph (DAG) of atomic sub-questions, each solved by a targeted SQL generation step. A RAG component grounds the decomposer with semantically similar training examples, and a Topology Refiner restructures the reasoning plan when execution failures signal a flawed decomposition rather than a fixable SQL error. DecoSearch achieves 70.53% execution accuracy on BIRD and 88.31% on Spider with a DeepSeek backbone, surpassing all training-free baselines while consuming an order of magnitude fewer tokens than competing methods. It also functions as a model-agnostic wrapper, consistently improving fine-tuned SQL generation backbones without any modification to the pipeline.

## 1. 核心问题与整体含义（研究动机与背景）
- **问题**：现有 LLM-based Text-to-SQL 方法在处理复杂查询（多表连接、嵌套子查询、数据感知推理如值分布与阈值）时准确率显著下降，而简单的单次自回归生成往往不足。
- **动机**：现有方法（分解、自修正、多候选生成）各自只解决单一失败类型（实现层、策略层、计划层），缺乏系统性地识别失败根因并将其路由到对应修复层级的机制。
- **背景**：LLM 在简单查询上已经表现良好，但复杂查询仍需要推理深度；同时大数据库和复杂模式（如 Spider 2.0）使问题更严峻。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：自适应地匹配计算复杂度到查询难度，通过**Judger-led 路由**将简单查询导向直接生成，复杂查询升级为结构化的 DAG 分解，并在执行失败时进行**计划级修复**（拓扑重构），而非仅修复 SQL。
- **技术细节**：
  - **Schema Selector**：两阶段筛选（先关键字提取，再 LLM 驱动选择表/列），剪枝模式以减少噪音和 token 消耗。
  - **Judger**：零样本 LLM 调用，输出 JSON 指示是否需要分解，默认偏向直接路径，仅对含冲突聚合粒度、极多连接、多阶段推理、证据驱动公式等情况触发分解。
  - **Direct Path**：直接生成并执行 SQL，成功则返回，失败则回退到分解路径。
  - **Decomposition Path**：
    - **Decomposer**：将问题分解为 DAG，节点为原子子问题，边表示数据依赖。
    - **RAG 强化**：检索训练集中相似的成功分解示例（k=3）注入 prompt，提高分解质量。
    - **依赖占位符 @[n]**：小结果集（≤100行）内联为 SQL 值列表；大结果集物化为临时表（`temp_ds_node_n`）。
  - **SQL Generator**：针对每个节点零样本生成 SQL，含数据集特定规则（如 BIRD 强制 `LOWER()` 和证据精确遵循）。
  - **Topology Refiner**：当节点执行失败时，LLM 基于当前 DAG、失败节点、错误信息重写 DAG（可重划分、插入中间节点、重连边），最多 B=3 次尝试。若失败则接受当前最佳结果并继续下游。
- **算法流程**（文字说明）：
  1. Schema Selector 剪枝得到子模式。
  2. Judger 判断：若直接路径，生成 SQL 并执行；成功则返回，失败则继续。
  3. 进入分解路径：Decomposer 构建 DAG，RAG 检索示例。
  4. 拓扑排序执行节点：每个节点生成 SQL 并执行。
  5. 若执行失败，调用 Topology Refiner 重写 DAG 并重试（不超过 B 次）。
  6. 最终返回根节点结果。

## 6. 主要结论与发现
- **性能**：DecoSearch 在 BIRD 上达 70.53% EX，Spider 上达 88.31% EX，超越所有训练-free 方法，在 Spider 上甚至超过部分微调模型。

- **路由核心**：Judger 主导的复杂度感知路由是最大贡献者，避免在简单查询上过度使用分解（直接路径成功率高）。
- **计划级修复**：拓扑精炼仅在执行失败标志计划级错误时触发，提供额外增量收益（+0.78pp）。
- **模型无关性**：作为包装器可稳定提升任意微调模型性能，无需修改流水线。

## 7. 优点
- **训练-free**：无需额外数据或微调，仅依赖 LLM 推理，部署成本低。
- **分层故障处理**：首次明确区分实现层、策略层、计划层错误，并针对性地路由到不同修复机制（SQL 级别 vs DAG 级别）。
- **计划级修复**：不同于仅重写 SQL，Topology Refiner 能重构整个推理图，解决更根本的错误。
- **RAG 增强分解**：通过检索历史成功示例提高分解质量，可扩展。
- **高效 token 利用**：通过 Judger 路由和模式剪枝，大幅节省计算资源。
- **消融实验完整**：量化各组件贡献，证明设计合理。

## 8. 不足与局限
- **依赖执行反馈**：要求 SQL 可在目标数据库上执行且错误信息能反映计划级缺陷。若数据库不可执行、或查询语法正确但语义错误（即执行成功但结果错误），则无法触发修复。
- **拓扑精炼次数有限**：B=3，可能不足以修复非常复杂的分解错误；若预算用尽，采取坦然退化（接受最佳结果），可能丢失准确性。
- **知识库依赖**：RAG 需要训练集成功分解对，对于完全零样本或新领域可能不适用。
- **实验范围局限**：仅测试了 BIRD 和 Spider，未在更难的 Spider 2.0 或企业环境评估；骨干仅使用 DeepSeek，未验证其他 LLM 上是否一致有效。
- **开放性风险**：虽提到 LLM 用于润色写作，但方法本身依赖 LLM 能力，不同模型性能方差可能较大。
