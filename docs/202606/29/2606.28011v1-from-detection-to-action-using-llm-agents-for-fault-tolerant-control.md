## 摘要
我们提出了一种主动容错控制（FTC）的智能大型语言模型（LLM）框架，该框架将故障检测输出转化为基于工厂特定知识的约束感知恢复行动。该方法结合了：(i) 一个多代理工作流，将操作员职责分解为监控、规划、行动合成、仿真、验证和重新提示；(ii) 一个数字过程工厂孪生（DPPT），提供工厂数据、模型以及用于执行前测试的仿真服务；(iii) 一个基于CPSMod本体的图检索增强生成（Graph RAG）层，该本体将工厂知识（结构、功能、混合动力学、控制上下文和故障语义）组织成图结构，支持面向关系的多跳检索，供代理使用。纠正行动被生成为最小风险的状态机恢复路径及相应的离散命令或连续设定点调整，然后在任何执行之前，根据互锁、包络线和动态可行性进行确定性验证。如果在有限时间窗口内未找到可接受的计划，则控制权移交给安全后备。该框架在两个代表性基准的仿真中进行了评估：离散批处理混合模块和闭环PID调节下的连续搅拌釜反应器（CSTR）。使用轻量级LLM（GPT-4o-mini和GPT-4.1-mini）的结果表明，语义驱动的代理能够在与各自过程动态兼容的延迟预算内推导出有效的恢复决策，展示了从检测到经过验证的纠正行动在离散和连续FTC任务中的实用路径。

## Abstract
We propose an agentic Large Language Model (LLM) framework for active Fault-Tolerant Control (FTC) that transforms fault detection outputs into constraint-aware recovery actions grounded in plant-specific knowledge. The approach couples (i) a multi-agent workflow that decomposes operator duties into monitoring, planning, action synthesis, simulation, validation, and reprompting; (ii) a Digital Process Plant Twin (DPPT) that exposes plant data, models, and a simulation service for pre-execution testing; and (iii) a Graph Retrieval-Augmented Generation (Graph RAG) layer built on the CPSMod ontology, which organizes plant knowledge (structure, function, hybrid dynamics, control context, and fault semantics) into a graph that supports relation-aware, multi-hop retrieval for the agents. Corrective actions are generated as minimal-risk state-machine recovery paths and corresponding discrete commands or continuous setpoint adaptations, then validated deterministically against interlocks, envelopes, and dynamic feasibility before any actuation. If no acceptable plan is found within a bounded time window, control is handed to a safety fallback. The framework is evaluated in simulation on two representative benchmarks: a discrete batch Mixing Module and a Continuous Stirred-Tank Reactor (CSTR) under closed-loop PID regulation. Results with lightweight LLMs (GPT-4o-mini and GPT-4.1-mini) show that semantically grounded agents can derive valid recovery decisions within latency budgets compatible with the respective process dynamics, demonstrating a practical pathway from detection to validated corrective action across both discrete and continuous FTC tasks.

## 2. 论文提出的方法论

### 核心思想
- 将操作员职责分解为多个专用LLM智能体，每个智能体负责容错控制中的一项子任务（监控、规划、动作合成、仿真、验证、重提示）。所有智能体通过**数字过程工厂孪生（DPPT）** 获取实时数据和仿真服务，并通过**基于CPSMod本体的Graph RAG层**获取结构化的工厂知识（设备、功能、行为、故障语义等）。
- 纠正动作生成过程遵循“检测 → 规划 → 动作合成 → 仿真验证 → 执行/重试”的闭环，只有通过确定性验证的动作才被允许执行；若超时未找到可行方案，则交给安全后备系统。

### 关键技术细节

1. **数字过程工厂孪生（DPPT）**：
   - 包含：传感器/执行器数据流、仿真模型（结构+功能+连续时间动力学+状态机行为）、数据驱动故障检测模型。
   - 提供仿真服务，用于在执行前测试纠正动作是否满足互锁、包络线、动态可行性等约束。

2. **Graph RAG层**：
   - 基于**CPSMod对齐本体**，该本体整合五个标准本体设计模式（ODP）：VDI 2206（结构分解）、VDI 3682（功能与物料/能量/信息流）、UML State Machine（离散行为）、OpenMath（连续行为数学方程）、DIN 17359（状态监控与故障诊断）。
   - 本体通过RDF/OWL表示，包含T-Box（模式）和A-Box（实例数据）。知识图谱存储在图形数据库（如Ontotext GraphDB）中，通过预定义的SPARQL模板（CONSTRUCT等）为LLM提供紧凑子图作为上下文。
   - 查询返回的结构化子图明确包含实体间关系（例如：故障症状关联的过程、该过程对应的状态机片段、与之相连的执行器及其限制），使LLM能进行多跳关系推理。

3. **多智能体工作流**：
   - **监控代理（Monitoring Agent）**：确定性组件，处理传感器、报警、事件信号，通过统计基线或数据驱动模型检测偏差。无故障时保持正常操作；否则触发恢复工作流并将工厂状态设为“故障”。
   - **规划代理（Planning Agent）**：LLM驱动的。接收故障症状，通过SPARQL查询获取受影响的过程实例及关联的状态机子图。LLM被提示遍历状态机，枚举满足守卫条件的路径，选择**最小风险恢复路径**（从当前故障状态到目标操作状态），输出为有序路径集合。
   - **动作代理（Action Agent）**：LLM驱动的。接收规划路径，查询图谱获取结构-功能-执行器子图（将路径上的过程与具体执行器、允许命令和限制关联）。LLM输出具体的离散命令（如“打开V201至30%”）或连续设定点调整（如温度设定点、液位设定点），形成每个可行路径对应的动作集。
   - **仿真代理（Simulation Agent）**：确定性组件。将动作集封装成仿真作业，调用DPPT的仿真服务，执行后返回轨迹、终态及约束违反报告（如违反互锁、包络线、动态可行性失败）。
   - **验证代理（Validation Agent）**：确定性规则引擎。基于仿真输出检查：互锁/许可条件是否始终满足、恢复时间是否在阈值内、闭环性能指标是否达标、执行器速率/行程限制是否合规。输出Approved或Revise（附结构化反馈指出违规点）。
   - **重提示代理（Reprompting Agent）**：当验证失败时，将结构化反馈转换为细化指导文本，回传给规划或动作代理，驱动新一轮迭代。若迭代次数超过预设上限（如5次）仍未找到可行方案，则触发安全后备（Safety System）。
   - 工作流中存在两种反馈循环：规划细化反馈（回Planning Agent）和动作细化反馈（回Action Agent）。

4. **安全后备机制**：如果LLM代理在有限时间窗口内无法生成被验证的安全计划，控制权移交给物理空间的安全系统，执行故障安全策略。

## 6. 论文的主要结论与发现

1. **RQ1（知识表示与检索）**：基于CPSMod本体的Graph RAG层成功为LLM代理提供了所需的植物特定知识。GPT-4.1-mini在所有混合模块故障场景中实现100%计划和行动正确性，表明语义表示足以使代理推导正确决策。本体整合了异构人工制品（P&ID、传感器-执行器映射、控制回路、因果矩阵、行为规范）并保持了关系语义，使规划代理能够识别故障依赖的约束并推理出可行替代路径。

2. **RQ2（恢复计划合成与验证）**：规划代理和动作代理能够合成正确的恢复路径与控制动作，并通过仿真验证确保安全。重提示机制能够纠正瞬态决策错误（恢复率在大多数场景达100%），但无法弥补系统性推理失败（如GPT-4o-mini在sensor_fault和cool_stuck_closed场景中低恢复率说明模型不能正确识别故障局部化）。

3. **RQ3（时效性与有效性）**：轻量级LLM在过程动力学允许的延迟内生成有效恢复决策。混合模块端到端平均时间32-40秒，CSTR为43-52秒，对于批处理/监督控制（秒级到分钟级干预频率）可接受；但硬实时系统（毫秒级响应要求）不适用。

4. **模型对比**：GPT-4.1-mini在几乎所有指标上优于GPT-4o-mini，在混合模块达到100%成功率，CSTR达93.3% vs 76.7%。错误模式分析显示：GPT-4o-mini失败源于**额外非允许的行动**（混合模块pump_degradation中不必要激活主泵）或**错误规划选择**（选择旁路路径而正常路径仍可行），而非遗漏必需动作。说明语义挂载能可靠地引导必要动作，但较弱模型可能注入与正式规范冲突的“常识”推理。

5. **不对称错误模式**：两种模型中，动作召回率始终为100%——从未遗漏所需执行器激活。所有错误都是假阳性（多余动作），从未出现漏动作。这暗示当前语义挂载在约束“做什么”上成功，但在约束“不做什么”上对弱模型效果有限。

## 7. 优点

1. **架构创新性**：多智能体工作流清晰分解容错任务，各代理职责明确，LLM仅用于需要认知推理的部分（规划、动作合成），而监控、仿真、验证保持确定性，兼顾灵活性与可靠性。
2. **语义增强的鲁棒性**：基于本体的Graph RAG超越了纯文本RAG，能够支持关系感知的多跳检索（例如：从故障症状追溯到受影响过程，再关联到执行器及其限制）。这对容错控制中需要遍历分布式关系（设备-故障-互锁-操作模式-控制动作）至关重要。
3. **预执行验证保障安全性**：所有纠正动作在仿真中经过确定性验证（互锁、包络线、动态可行性）后才能执行，避免了执行不安全动作。同时提供可审计的决策追踪（中间理性解释），支持人类监督。
4. **过程类型通用性**：在一个框架内同时处理了离散批处理（基于状态机）和连续过程（基于PID设定点调整），展现了广泛的适用性。
5. **可扩展性设计**：本体T-Box可复用；工厂实例通过映射填充；新增故障、传感器、执行器只需扩充知识图谱节点而无须重新设计控制器；支持通过重提示迭代修正。
6. **轻量级可行性**：使用低成本的mini模型（GPT-4o-mini/GPT-4.1-mini）即能完成有效容错，降低了工业部署的经济与延迟门槛。

## 8. 不足与局限

1. **知识图谱构建成本高**：当前实现依赖结构化输入，而工业数据往往为非结构化或半结构化。虽然论文提到可用LLM进行自动提取，但未实现，限制了实用化。
2. **仅覆盖已建模故障**：数字孪生只能验证针对预先建模的故障条件的动作；真正新故障无法仿真，框架无法处理。
3. **无法纠正系统性推理失败**：当LLM产生系统性错误（如错误归因故障局部化），重提示在有限次数内不能纠正（如GPT-4o-mini在CSTR cool_stuck_closed的0%恢复率）。
4. **延迟局限**：端到端约30-50秒，不适合需要毫秒级响应的硬实时控制系统（如高速零部件加工）。论文也承认这一点并指明未来方向（离线策略合成等）。
5. **无外部对比基线**：实验未与RL、MPC、规则基等经典方法进行对比，无法评估LLM方法在恢复质量、鲁棒性、鲁棒性方面的相对优势。
6. **扩展性未验证**：仅测试了单元设备级案例（~20个执行器/传感器）。在更大工厂（数百个设备）中，知识图谱规模、检索延迟、LLM上下文窗口限制可能会显著影响性能。
7. **无消融实验**：未量化框架各组件（如去掉Graph RAG仅用文本RAG、关闭重提示、使用确定性规划器替代LLM等）的贡献，难以判断哪些组件对最终性能最关键。
8. **LLM选择面窄**：仅测试了OpenAI两种mini模型，未评估更强LLM（如GPT-4、Claude）或本地开源模型（Llama、Mistral）的表现，也未评估微调对性能的影响。
9. **虚假相关风险**：LLM可能因为训练数据中的常见模式而产生错误归纳（如混合模块中泵退化场景下，模型额外激活主泵——可能因为一般常识认为备份泵不能单独工作，但该工厂规范不允许），暴露了对领域外知识的过度依赖风险。
10. **评估偏向“成功率”**：虽然防止

虽然防止了漏动作导致的灾难性后果，但假阳性（多余动作）可能引发非必要的设备损耗、能耗浪费甚至次生风险（如混合模块中错误启动主泵可能使系统压力超限）。论文未评估假阳性动作对过程长期安全性和可靠性的实际影响，也未设定容忍假阳性的量化阈值，这在实际工业部署中可能成为隐患。此外，评估侧重点集中于恢复成功率与动作正确性，对恢复后过程的稳态性能（如控制鲁棒性、超调量、收敛时间）缺乏分析。
