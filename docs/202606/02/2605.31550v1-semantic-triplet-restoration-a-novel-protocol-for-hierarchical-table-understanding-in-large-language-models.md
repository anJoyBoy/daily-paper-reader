## 摘要
表格问答要求模型恢复由二维布局、合并单元格和分层表头隐式编码的语义关系。当前流程通常使用HTML或Markdown作为中间表格表示，但这些面向布局的序列化引入了标记开销，并要求大型语言模型从行和列跨度推断表头-单元格对齐关系。我们提出语义三元组恢复（STR）协议，该协议将每个单元格重写为原子事实<条目路径，特征路径，值>，其中条目路径指定行级实体，特征路径指定分层属性，值包含单元格内容。我们还提出了TripletQL，一种轻量级的查询感知路由器，它利用STR为每个问题选择合适的三元组渲染或过滤子集。在四个中文和英文表格问答基准测试中，STR匹配或改进了基于HTML的基线，同时减少了输入令牌数。对于较小的语言模型和较长的表格上下文，相对收益更大，这表明在受限推理预算下显式语义表示特别有用。代码和数据可在https://github.com/Phoenix-ni/STR.git获取。

## Abstract
Table question answering requires models to recover semantic relations encoded implicitly by two-dimensional layout, merged cells, and hierarchical headers. Current pipelines typically use HTML or Markdown as intermediate table representations, but these layout-oriented serializations introduce markup overhead and require large language models to infer header-cell alignments from row and column spans. We propose Semantic Triplet Restoration (STR), a protocol that rewrites each cell as an atomic fact <item path, feature path, value>, where the item path specifies the row-wise entity, the feature path specifies the hierarchical attribute, and the value contains the cell content. We also present TripletQL, a lightweight query-aware router that uses STR to select an appropriate rendering or filtered subset of triplets for each question. Across four Chinese and English table-QA benchmarks, STR matches or improves upon HTML-based baselines while reducing input tokens. The relative benefit grows for smaller language models and longer table contexts, suggesting that explicit semantic representations are especially useful under constrained inference budgets. Code and data are available at https://github.com/Phoenix-ni/STR.git .

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有表格问答流程普遍使用 HTML 或 Markdown 作为中间表示，但这类面向布局的序列化格式存在两个关键缺陷：
  - **标记冗余**：HTML 标签（如 `<rowspan>`, `<colspan>`）增加了大量无关 token，占用大语言模型（LLM）的上下文窗口。
  - **语义耦合**：布局信息与语义关系耦合，LLM 需从行列跨度中隐式推断表头与单元格的对齐关系，导致数值漂移和推理效率低下。
- **背景**：近年来视觉语言模型（如 PaddleOCR-VL、MinerU）在表格识别方面取得进展，但其输出以 HTML 为主，仅适合结构恢复，不适合下游推理。论文指出，表格问答的核心是**语义关系**而非视觉布局，因此亟需一种解耦布局与语义的新型表示协议。
- **整体含义**：提出**语义三元组恢复（STR）** 协议，将表格重写为显式原子事实，使 LLM 无需从布局中重建 2D 网格，从而在保持或提升准确度的同时显著减少输入 token 数，特别适用于资源受限的推理场景（如小模型、长表格）。

## 2. 提出的方法论
### 2.1 核心思想
- **STR 协议**：将每个单元格表达为原子三元组 `⟨条目路径, 特征路径, 值⟩`，其中：
  - **条目路径**：行级实体的点连接字符串（如 `2023.Q1`），显式编码行层次结构。
  - **特征路径**：列级属性（如 `Revenue`），显式编码分层表头。
  - **值**：单元格内容（如 `100`）。
- **关键设计**：
  - 合并单元格被展平为独立坐标，避免对齐歧义。
  - 视觉布局仅在解析阶段使用，进入 LLM 前已转化为纯语义路径，完全移除 HTML 标签。
  - 提供元数据 `MB`（行/列数、形状），支持无推理的快速回答。

### 2.2 非自回归视觉基础模型（Split-Merge 机制）
- 采用编码器-只读（encoder-only）的非自回归架构，用于从图像中提取单元格边界和层次路径。
- **Split 阶段**：使用 1D 膨胀软标签 + 逆动态加权（IDW）的 Focal Loss，提升行列分割鲁棒性。
- **Merge 阶段**：简化 OTSL 分类为 4 类（C/L/U/X），并引入 `ignore_index` 掩码避免填充区域坐标抖动。
- 该模块不是论文核心创新，仅为 STR 提供稳定输入。

### 2.3 TripletQL 路由器
- 基于查询意图动态选择执行路径，包含三个分支：
  - **路径 A（直接回答）**：当查询与元数据相关（如“多少列”），直接从 `MB` 返回答案，无需访问表格内容。
  - **路径 B（保守过滤）**：当表格较大且可定位特定实体时，通过多步过滤提取相关三元组子集 `Tsub`，再送入 LLM 推理。
  - **路径 C（完整推理）**：当上述条件不满足或需全局视图时，使用完整三元组集 `T`。
- **关键技术细节**：
  - **特征触发路由（πR）**：使用正则规则快速分类，仅在不确定时调用 0.6B 辅助模型（Qwen3-0.6B）确认。
  - **保守过滤（πD）**：包括 LLM 引导的实体召回、词汇补偿、指代扩展、邻居扩展（宽度 w=1）、覆盖率回退（若过滤后实体比例 ≥75% 则回退到路径 C）。
  - **多轮上下文重注入**：强制首轮加载完整 STR 视图，后续每轮重新渲染上下文并仅保留历史文本，缓解“中间丢失”问题。

## 6. 主要结论与发现
- **STR 匹配或超越 HTML 基线，同时显著减少 token 成本**：
  - TableEval-test 上 TripletQL 的 F1 达 88.49（HTML 为 86.06），token 节省 32.1%。
  - WTQ 上 Full Triplet 准确率 46.59%（HTML 为 37.43%），token 节省 22.2%。
  - TQA-Bench 上 STR 在 8k-64k 规模保持准确率，token 节省约 50%。
- **收益随模型规模减小而增大**：
  - Qwen3-0.6B 上增益 +11.0%（F1 从 46.34 提升至 51.44），而 GLM-4.5-Air 仅 +1.80%。

- **视觉解析质量影响但非瓶颈**：
  - 即使使用自家 Split-Merge 输出（而非 GT），STR 仍优于 GT HTML，证明表示本身优于视觉精度。

## 7. 优点
- **方法创新**：将表格表示从布局序列化提升为语义原子事实，彻底解耦布局与语义，避免 LLM 进行隐式网格重建。
- **轻量化设计**：
  - 视觉解析仅 48.6M 参数，推理仅 386ms/图、622MB 显存，适合部署。

- **跨模型与跨语言鲁棒性**：在中英文、多数据集、三档模型规模上均有增益，通用性强。
- **实验严谨**：报告了多次标准差、子任务细粒度分析、消融路由组件、对比不同视觉模型输出，结论可靠。

## 8. 不足与局限
- **视觉解析局限性**：
  - 训练数据主要来自清晰金融文档和 PubTables，对扫描件、低分辨率、旋转或手写表格的鲁棒性未知，可能影响路径提取。
