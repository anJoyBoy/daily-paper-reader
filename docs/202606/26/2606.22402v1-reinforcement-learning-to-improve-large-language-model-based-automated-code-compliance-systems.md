## 摘要
基于大语言模型（LLM）的建筑规范自动化合规（ACC）方法容易生成错误且产生幻觉的计算机可处理规则。本文提出P4IR框架，该框架采用两阶段方法：首先通过监督微调（SFT）向LLM注入领域知识，随后采用组相对策略优化（GRPO）以高层代码骨架形式提升所生成中间表示的准确性。与SFT基线相比，该框架在树编辑距离和词元级Levenshtein距离上分别实现了高达23.8%和38.6%的缩减。对比分析表明，在零样本设置下，该方法在代码结构和语义上均优于领先的LLM（具体通过少样本提示评估了Claude Opus和Sonnet 4.5、GPT-5.2、Qwen-3-Max以及GLM-4.7）。此外，GRPO阶段产生了虽小但统计上显著的误报率降低。通过将SFT与GRPO相结合以直接优化领域特定目标，该方法为构建更准确可靠的基于LLM的ACC系统提供了路径。

## Abstract
Large language model (LLM)-based approaches for automated code compliance (ACC) of building regulations are prone to generating incorrect and hallucinated computer-processable rules. This paper introduces P4IR, a two-stage framework that uses supervised fine-tuning (SFT) to instill domain knowledge in an LLM, followed by Group Relative Policy Optimization (GRPO) to improve the accuracy of the generated intermediate representations in the form of high-level code skeletons. The framework achieved reductions of up to 23.8% and 38.6% in tree edit distance and token-level Levenshtein distance respectively, relative to the SFT baselines. Comparative analysis demonstrates that this approach in a zero-shot setting outperforms leading LLMs in both code structure and semantics, specifically Claude Opus and Sonnet 4.5, GPT-5.2, Qwen-3-Max, and GLM-4.7, evaluated via few-shot prompting. Additionally, the GRPO stage produced a small yet statistically significant reduction in false positives. By combining SFT with GRPO to optimize directly for domain-specific objectives, this approach offers a path toward more accurate and reliable LLM-based ACC systems.

# 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：基于大语言模型（LLM）的建筑规范自动化合规（ACC）系统在将自然语言规则转换为计算机可处理规则时，容易生成错误和幻觉（hallucination）的输出，例如不存在的类、函数或逻辑。这导致生成的中间表示（IR）不可靠，需要大量人工修正。
- **背景**：建筑规范合规对于建筑安全、成本和工期至关重要（如新加坡2025年建设需求530亿新元）。传统ACC依赖硬编码规则，耗时且缺乏灵活性；LLM虽能自动生成规则，但存在幻觉问题。即使经过监督微调（SFT），模型仍可能生成结构错误或冗余的代码骨架。
- **目标**：提出一种两阶段框架P4IR，先通过SFT注入领域知识，再利用强化学习（GRPO）直接优化代码骨架的结构准确性，减少幻觉，提升IR质量，最终降低人工审核成本。

# 2. 论文提出的方法论

- **核心思想**：将ACC任务分解为两步：① 用SFT使LLM学习从规则文本到代码骨架的映射（注入领域语义）；② 用GRPO进一步优化代码骨架的结构准确性，通过奖励函数惩罚错误结构并鼓励与参考骨架对齐。
- **关键技术细节**：
  - **基座模型**：Mistral 7B Instruct v0.3（开源，生成能力好）。
  - **中间表示（IR）**：代码骨架（code skeleton），即类、函数、参数及嵌套关系的高层定义，忽略低层实现细节（用`pass`代替）。
  - **SFT阶段**：最小化交叉熵损失 \( L_{SFT} = -\mathbb{E}_{(q,y)\sim C} \sum_{t=1}^{|y|} \log \pi_\theta(y_t | q, y_{<t}) \)，训练模型将规则文本 \( q \) 映射到参考代码骨架 \( y \)。
  - **GRPO阶段**：
    - 对每个输入 \( q \)，从旧策略采样 \( G=16 \) 个候选输出 \( \{o_i\} \)。
    - 计算奖励 \( r_i \)（包括准确率奖励、语法惩罚、长度惩罚），并标准化得到优势 \( A_i = \frac{r_i - \text{mean}}{\text{std}} \)。
    - 优化GRPO目标函数（公式3）：包含策略比率裁剪和KL散度约束，避免偏离参考策略。
  - **奖励设计**：
    - **准确率奖励** \( R_{\text{structure}} \)：基于Jaccard相似度，比较生成与参考代码骨架的签名集（类/函数名+层次位置）。
    - **语法惩罚** \( R_{\text{syntax}} \)：若输出不是合法Python代码，奖励-1。
    - **长度惩罚** \( R_{\text{length}} \)：若输出过短且与参考长度偏差超过阈值，奖励-3，防止奖励破解。
- **算法流程**（文字说明）：
  1. 使用规则-代码骨架对数据集对预训练LLM进行SFT，得到初始策略 \( \pi_{\theta_{\text{init}}} \)。
  2. 以 \( \pi_{\theta_{\text{init}}} \) 为参考，对每个规则输入，采样多个候选代码骨架。
  3. 计算每个候选的奖励（准确率+语法+长度），并归一化得到优势。
  4. 使用GRPO更新策略参数，使高优势输出概率增加，同时限制与参考策略的KL散度。
  5. 迭代多步（本文2000步），保存最佳检查点。

# 6. 论文的主要结论与发现

1. **GRPO能进一步改善SFT模型生成的代码骨架准确性**：树编辑距离降低23.8%，词元级Levenshtein距离降低38.6%（最佳SFT epoch 10，GRPO 2000步）。
2. **SFT成熟度决定GRPO效果**：存在最佳窗口（epoch 8~10）：模型具有足够领域知识但未过拟合，保持适度探索能力。欠拟合（epoch 4~6）或过拟合（epoch 12~14）模型受益有限。
3. **GRPO可减少假阳性（幻觉）**：平均假阳性数从21.60降至18.60，统计显著（p<0.001 Wilcoxon, p=0.005 t-test），但效应量小（Cohen’s d=0.127）。
4. **GRPO不损害语义知识**：CodeBERTScore在GRPO过程中保持稳定，表明SFT注入的语义被保留，GRPO仅优化结构。
5. **P4IR零样本超越SOTA少样本模型**：在所有指标上（树编辑距离、Levenshtein、Jaccard、CodeBERTScore）均优于Claude Opus 4.5、Sonnet 4.5、GPT-5.2、Qwen-3-Max、GLM-4.7。例如树编辑距离20.49 vs 最佳基线22.56（GLM-4.7 2-shot）。
6. **SOTA模型在少样本下表现不佳**：增加示例有时反而导致性能下降（如Claude Opus 1-shot 33.18 vs 2-shot 36.47），表明通用模型难以直接应用于专业ACC任务。

# 7. 优点

- **方法创新**：首次将GRPO应用于ACC领域，并设计两阶段框架，明确SFT负责语义、GRPO负责结构，两者互补。
- **奖励设计合理**：结合Jaccard准确率、语法惩罚和长度惩罚，直接针对代码骨架结构优化；惩罚力度与错误严重性匹配。
- **实验设计严谨**：系统探讨SFT成熟度对GRPO的影响，通过logit熵解释机制；使用多种评估指标（结构、语义、距离），并进行统计显著性检验。
- **公平对比**：P4IR零样本 vs SOTA少样本，且SOTA使用RAG增强，更能体现框架优势。
- **可解释性**：通过分析logit熵揭示SFT模型的最佳工作窗口（适度不确定性利于GRPO探索）。
- **隐私保护**：训练后模型可本地部署，无需上传敏感数据到外部API。

# 8. 不足与局限

- **IR形式单一**：仅测试代码骨架，未验证其他中间表示（如LegalRuleML、原子函数、本体），泛化性未知。
- **数据集局限**：仅732个样本，且全部来自新加坡规范，术语和结构可能与其他国家差异大；未测试跨国家泛化能力。
- **缺少与其他RL算法对比**：未与PPO/RLHF等对比，无法确认GRPO是否最优。
- **奖励仅关注结构而非功能正确性**：优化的是代码骨架，而非最终生成规则的可执行正确性；未来可考虑使用BIM沙箱测试结果作为奖励。
- **超参数未调优**：GRPO使用默认参数（如βKL=0.04），可能未针对该任务最优。
- **算力限制**：仅单GPU训练，可能影响可扩展性；未报告SFT训练时长和GRPO训练时长。
- **效应量小**：假阳性减少虽统计显著，但实际改进幅度有限（Cohen's d=0.127）。
- **未测试小样本/少数据场景**：现实ACC中标注数据稀缺，框架对数据规模的依赖未探讨。
