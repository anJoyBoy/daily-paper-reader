## 摘要
大规模语言模型显著推进了Text-to-SQL系统的发展，但将其应用于企业级数据库仍然面临挑战。现实世界的数据库通常包含庞大且异构的模式、不完整的元数据、特定方言的SQL语法以及难以通过单个SQL查询解决的复杂分析问题。为应对这些挑战，我们提出了ProSPy，一个面向企业级Text-to-SQL的分析驱动型SQL-Python智能体框架。ProSPy将推理过程组织为四个阶段：首先通过自动分析提取细粒度数据证据，逐步将大型模式剪枝为任务相关的上下文，通过方言无关的SQL接口获取中间视图，最后使用Python执行灵活的下游分析。该设计结合了SQL在大数据库上的高效性与基于Python的分析灵活性，同时减少了对不可靠元数据的依赖，并提升了跨SQL方言的鲁棒性。在Spider 2.0-Lite和Spider 2.0-Snow上的实验表明，ProSPy在使用开源和专有模型时均持续优于强基线方法，在Claude-4.5-Opus上无需多数投票即可达到60.15%和60.51%的执行准确率。进一步分析显示，ProSPy对SQL方言变化具有鲁棒性，并在模式召回率与精确度之间实现了良好的权衡。

## Abstract
Large language models have substantially advanced Text-to-SQL systems, yet applying them to enterprise-scale databases remains challenging. Real-world databases often contain large and heterogeneous schemas, incomplete metadata, dialect-specific SQL syntax, and complex analytical questions that are difficult to solve with a single SQL query. To address these challenges, we propose ProSPy, a Profiling-driven SQL--Python agentic framework for enterprise-scale Text-to-SQL. ProSPy structures the reasoning process into four stages: it first extracts fine-grained data evidence through automatic profiling, progressively prunes large schemas into task-relevant contexts, fetches intermediate views through a dialect-agnostic SQL interface, and finally performs flexible downstream analysis with Python. This design combines the efficiency of SQL over large databases with the flexibility of Python-based analysis, while reducing reliance on unreliable metadata and improving robustness across SQL dialects. Experiments on Spider 2.0-Lite and Spider 2.0-Snow show that ProSPy consistently outperforms strong baselines with both open-source and proprietary models, achieving execution accuracies of 60.15% and 60.51% with Claude-4.5-Opus, without majority voting. Further analysis shows that ProSPy is robust to SQL dialect variations and achieves a favorable trade-off between schema recall and precision.

## 1. 核心问题与整体含义（研究动机和背景）
企业级Text-to-SQL面临三大核心挑战：  
- **大型异构模式**：真实数据库包含数百张表、不规范的命名、半结构化字段，使模式识别困难。  
- **不完整元数据**：官方提供的元数据常缺失或不可靠，导致模型难以理解字段语义。  
- **复杂分析需求**：许多问题需多步中间计算（如聚合、排名、比率），单条SQL难以表达，且SQL方言差异（Snowflake、BigQuery、SQLite）增加了生成难度。  

现有方法（如ReForce、APEX-SQL）依赖反复LLM调用和数据库探测，延迟高且局限于SQL表达能力。ProSPy旨在通过**SQL高效检索与Python灵活分析**的互补结合，实现企业级端的准确鲁棒推理。

## 2. 方法论
### 核心思想
将企业级数据推理分解为**四个阶段**，利用SQL进行可扩展数据提取，利用Python进行复杂下游计算，并通过**自动Profiling**和**渐进式剪枝**减少对不可靠元数据的依赖，通过**方言无关DSL**屏蔽SQL语法差异。

### 关键技术细节
1. **数据Profiling（A）**  
   - 对每个表执行一系列模板SQL查询，自动识别5类语义列（度量、维度、标识符、时间、其他），收集类型相关统计（分布、摘要、空值比率、样例），并递归解析嵌套类型（如VARIANT）。  
   - 产出结构化JSON描述，可复用（每个数据库仅执行一次，并行处理）。

2. **渐进式模式剪枝（B）**  
   - **两阶段剪枝**：先粗后细。首先将大型模式分批，LLM识别每批中任务相关表并移除无关表；再对保留表的字段进行相同操作。  
   - 目标：构建紧凑、信息丰富的模式上下文，而非单纯追求高召回。

3. **Agentic数据获取（C）**  
   - **迭代计划-执行**：给定剪枝后模式，LLM先计划所需数据，然后逐步生成多个视图定义。  
   - **DSL中间表示**：每个视图由三维度（维度、度量、条件）描述，自然对齐profiling输出。  
   - **方言无关编译**：DSL通过transpiler转换为目标数据库可执行SQL（如Snowflake、BigQuery），避免直接生成方言特定语法。  
   - 支持视图依赖与复用，直到累积足够数据。

4. **Python分析（D）**  
   - 所有物化视图以CSV形式传递给Python沙箱，LLM生成Python代码进行多步计算（如合并、分组、过滤、数学运算），直至得到最终结果。  
   - 单次执行通常即可完成（>80%），最多三次。
