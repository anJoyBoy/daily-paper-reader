## 摘要
随着大语言模型的出现，许多数据库系统引入了语义运算符，支持对非结构化数据（如文本、图像、视频）进行分析查询。语义运算符通常带来高推理成本和高延迟，使得语义（AI）SQL查询难以在大规模数据集上应用。同时，其语义性质导致数据库引擎将其视为黑盒，使得AI SQL查询难以优化。本文介绍了Larch，一个用于优化AI SQL查询中语义过滤器执行的框架。Larch的灵感来源于两个关键观察：i) 语义运算符的高延迟为计算密集型运行时优化技术留下了显著空间；ii) 非结构化数据通常以嵌入形式附带语义信息，允许在AI_FILTER提示和数据值之间进行高效的语义比较。基于这两个关键观察，我们提出了两种Larch变体：Larch-A2C和Larch-Sel。Larch-A2C使用嵌入增强的门控图神经网络对任意语义过滤器表达式树进行编码，并将过滤器评估顺序形式化为马尔可夫决策过程。相比之下，Larch-Sel利用监督学习模型预测过滤器选择性，随后应用动态规划为每个输入行找到接近最优的评估顺序。在多样化的真实世界数据集和全面的合成工作负载上评估，两种Larch变体在令牌使用方面始终优于现有的语义过滤器优化技术。我们的结果表明，Larch在多样化工作负载上具有鲁棒性，与Palimpzest和Quest相比，总令牌成本开销降低了3-19倍。

## Abstract
With the advent of Large Language Models (LLMs), many database systems introduced semantic operators that enabled analytical queries over unstructured data (e.g. text, images, videos). Semantic operators typically incur high inference costs and latencies making semantic (AI) SQL queries challenging to apply on large scale datasets. At the same time, their semantic nature leads database engines to treat them as black boxes, making AISQL queries difficult to optimize. In this paper, we introduce Larch, a framework for optimizing the execution of semantic filters in AI SQL queries. Larch was inspired by two key observations: i) the high latency of semantic operators leaves significant room for computationally-heavy runtime optimization techniques, ii) unstructured data are typically accompanied by semantic information in the form of embeddings allowing for efficient semantic comparisons between AI_FILTER prompts and data values. Based on these two key observations, we present two Larch variants: Larch-A2C and Larch-Sel. Larch-A2C encodes arbitrary semantic filters expression tree using an embedding-augmented Gated Graph Neural Network and formulates the filter evaluation order as a Markov decision process. In contrast, Larch-Sel leverages a supervised learning model to predict filter selectivities, subsequently applying dynamic programming to find a near-optimal evaluation order for each input row. Evaluated across diverse real-world datasets and comprehensive synthetic workloads, both Larch variants always outperform existing semantic filter optimization techniques in terms of token usage. Our results demonstrate that Larch is robust across diverse workloads, reducing total token cost overhead by 3x-19x compared to Palimpzest and Quest.

# 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：随着大语言模型（LLM）在数据库中的广泛应用（如 Snowflake、BigQuery、Microsoft），AI SQL 查询支持对非结构化数据（文本、图像、音频）进行语义分析。然而，语义运算符（如 `AI_FILTER`）执行时依赖 LLM 推理，这类推理成本高昂（占查询总成本的 80%-90%），且延迟长达秒级。当查询包含多个语义谓词时，传统关系优化器无法处理它们的黑盒语义特性，无法提前估计选择性和相关性，导致按书写顺序依次评估所有谓词，浪费大量 LLM 调用。
- **核心挑战**：如何动态确定多个语义谓词的评估顺序，使得启发式短路逻辑（AND 中遇 False 提前结束，OR 中遇 True 提前结束）最有效地减少 LLM 调用次数。关键难点在于谓词的选择性完全依赖于语义内容，无法预计算或通过传统直方图统计获得。
- **整体含义**：Larch 提出利用 LLM 推理的高延迟窗口（纳秒级 → 秒级）来执行在线学习，同时利用预计算的嵌入向量作为低成本的语义摘要，从而实现在执行过程中动态优化过滤顺序，大幅降低 token 开销。

# 2. 论文提出的方法论

### 核心思想
- **关键观察 1**：LLM 推理的高延迟（数百毫秒至秒级）给计算密集型的运行时优化提供了时间窗口，本地模型训练可以完全隐藏在该延迟内。
- **关键观察 2**：非结构化数据通常预计算了嵌入向量（如文档嵌入），其获取成本比 LLM 推理低 100–500 倍。虽然单纯用嵌入相似度预测选择性噪声较大（见图 2），但嵌入可作为高层语义特征输入轻量学习模型。

基于上述观察，Larch 提出两种变体：

### Larch-A2C（端到端强化学习）
- **MDP 建模**：将每行数据的过滤器评估视为一个马尔可夫决策过程。
  - **状态**：使用**门控图神经网络（GGNN）** 编码当前部分评估的表达式树（包含 AND/OR 节点和剩余谓词叶子节点）。每个叶子节点融合文档嵌入和谓词嵌入，内部节点使用可学习的 AND/OR 嵌入。通过 K 轮消息传递（区分 AND 与 OR 边）得到每个节点表示，再取均值得到全局树摘要。
  - **动作**：从剩余叶子谓词中选择一个进行 LLM 评估。
  - **奖励**：每一步奖励为负的 token 成本（归一化到 [-1,0]），累计奖励越高越好。
- **策略与价值网络**：Actor 网络接收叶子节点嵌入和全局树摘要，输出概率分布；Critic 网络预测状态价值。使用 A2C 算法（Advantage Actor-Critic）在线训练，利用 TD(0) 更新，熵衰减从探索转向利用。
- **在线训练**：在每次 LLM 调用等待期间，后台线程使用上一个时间步的转移元组更新模型，完全隐藏训练开销。

### Larch-Sel（分解方法）
- **选择性预测**：使用轻量 MLP（约 144K 参数），输入为文档投影、谓词投影、点积、余弦相似度，输出 Sigmoid 概率。所有谓词共享网络权重，通过二分类交叉熵损失在线训练。
- **动态规划排序**：在**独立性假设**下，给定每行每个谓词的预测选择性 ˆs_i 和 token 成本 c_i，使用动态规划递归求解最优评估子树顺序。状态数为 O(3ⁿ)，n=10 时约 59 万状态，单 CPU 只需 20ms。每行重新调用 DP。
- **优势**：将问题分解为监督学习 + 精确规划，比端到端强化学习样本效率更高。实验证明选择性估计是主要瓶颈，Larch-Sel 直接解决该瓶颈。

# 6. 论文的主要结论与发现

- **Larch-Sel 始终最优**：在所有配置下，Larch-Sel 的 token 开销接近 Optimal 下界（最低 1.7%），比 PZ/Quest 降低 3–19 倍。Larch-A2C 次之但也显著优于基线。
- **选择性估计是瓶颈**：端到端强化学习（Larch-A2C）需要更多数据收敛；分解方法（Larch-Sel）通过隔离选择性预测任务并利用二分类监督信号，样本效率更高。
- **全局选择性局限**：PZ/Quest 依赖单一全局选择性，无法捕捉每行变化；即使 Oracle 版本（使用真实全局选择性）也差于 Larch-Sel，因为全局平均不能代表局部特征。
- **延迟隐藏可行**：模型更新（约 7-10ms）完全隐藏在 LLM 调用（数百毫秒）内，且延迟更新策略对最终性能几乎无影响（变化 <0.6%）。
- **鲁棒性**：在不同选择性、不同叶子数、不同数据规模下，Larch-Sel 均保持近最优性能。

# 7. 优点

- **创新性**：首次将在线学习（强化学习/监督学习）与嵌入特征结合用于语义谓词排序，利用 LLM 高延迟窗口训练模型。
- **高效性**：分解方法（Larch-Sel）样本效率极高，仅需几十到几百行数据即可收敛，在 1K 规模的 GovReport 上也能取得显著提升。
- **实用性强**：不依赖显式采样阶段的额外 LLM 调用，与生产系统中嵌入的预计算趋势兼容；异步流水线设计不增加执行时间。
- **实验严谨**：包含理论下限（Optimal）、Oracle 上限、多种消融和敏感性分析，结果可信。

# 8. 不足与局限

- **假设限制**：Larch-Sel 的 DP 求解基于谓词独立性假设，虽然实验表明在此工作负载下效果很好，但未测试强相关场景下的退化情况。
- **冷启动问题**：初始几行数据缺乏历史观察，模型预测可能不准确。论文提到未来可研究跨查询迁移学习缓解冷启动。
- **嵌入依赖**：假设文档嵌入已预计算；若嵌入缺失或变换（如上游改写操作），需要额外重嵌入成本（虽然便宜，仍增加复杂度）。
- **实验覆盖**：仅测试了单个过滤器节点内的排序，未涉及多过滤器节点之间的全局优化（如多个 WHERE 子句中的不同过滤器节点）。也未测试其他数据类型（如图像、音频）。
- **通用性局限**：查询工作负载来自 ScaleDoc（特定语义谓词池），可能不能完全代表真实生产环境中用户自定义的任意谓词。
